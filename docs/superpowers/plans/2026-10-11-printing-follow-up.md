# План доработок печати после Station 2.3.0

Статус: реализован и проверен; физическая приёмка и deployment остаются отдельным этапом.

[Дизайн и ограничения](../specs/2026-10-11-station-printing-follow-up-design.md).

Работа разбита на четыре самостоятельных плана с RED/PASS проверками и scoped commits. Выполнение — здесь по этапам, без обязательной делегации.

1. [Исторические поля перепечатки](2026-10-11-printing-follow-up-dates.md): сохранять достоверные дату/expiry при принятии, синхронизировать и использовать после закрытия; восстановить старые локальные задания, не пересчитывать неизвестный исторический срок из текущего каталога.
2. [Три макета А4](2026-10-11-printing-follow-up-a4.md): отступ logo/name, крупная ПАЛЕТА справа, линия продукции, footer INN/Маркиро. Обновлённые пресеты создаются как новые шаблоны, назначаются новым сменам; пользовательские и исторические снимки не перезаписываются.
3. [Общая Сохранить](2026-10-11-printing-follow-up-admin.md): единая форма, существующий атомарный PUT, одинаковые selectors категорий каталога, корректное слово палета по всей tenant admin.
4. [Перепечатка палеты](2026-10-11-printing-follow-up-pallet-reprint.md): отдельный режим с подтверждением; SSCC палеты, короб или КМ продукции; только закрытые производственные палеты Station в первом выпуске; immutable source и существующая доставка.

## Порядок и gates

- Этап 1 устраняет причину ошибки. Для уже закрытой смены пользователя отдельно проверить retained local job/context: серверная история содержит hashes, а не полный набор исторических полей. Нет доказанного expiry — точное объяснение и совместимый шаблон, без скрытого восстановления из сегодняшнего shelf life.
- Этапы 2 и 3 независимы и могут идти отдельными PR. Для футера нужна новая версия шаблона и новая смена; ожидание изменения старого снимка будет ошибкой.
- Этап 4 использует правила источников этапа 1; требует additive server/local schema, versioned protocol, offline/recovery и tenant tests. Это самый большой этап, split на source/lookup и confirmation/delivery предусмотрен в его плане.
- После каждого этапа: focused tests, package test/typecheck/lint/build затронутых packages, rebuild зависимостей, `git diff --check`; для cross-package итога `corepack pnpm turbo lint typecheck test build --concurrency=1 --force` с безопасным test env, `corepack pnpm format:check`. Skips DB не считать выполненным e2e.
- Browser: общий Save, preview трёх А4 и два режима перепечатки; affected CI ownership проверить в `tools/ci/affected.mjs` и `.github/workflows/ci.yml`. Production bundle/browser contracts выполнять по затронутым surfaces. Cargo/Windows checks — если изменится native boundary; host checks не заменяют Windows.
- Подготовить scoped push/PR по ранее данному поручению после реализации и проверок. Сопоставить полный three-dot diff с fetched main, сохранить чужую работу.
- После merge отдельно выпускать API/admin и beta Station существующими защищёнными workflows. В этом поручении релиз новых исходников ещё не запускается. Stable 2.3.0 не изменять.

## Физическая приёмка следующей beta

1. Новая смена с production date → закрытие → перепечатка по КМ; поля совпадают. Старое сохранённое задание также проверяется отдельно.
2. Три новых А4: прямоугольный logo, правильная шапка, подчёркивание и footer; каждый SSCC читается сканером.
3. Палета найдена тремя способами; до подтверждения принтер молчит. Отмена, двойной скан, RAW/Windows и offline restart проверяются отдельно.
4. Доказанный отказ до отправки, delivery unknown и смена владельца не приводят к случайному повтору или смене исторического макета.

## Проверка самого плана

План сопоставлен с текущим lookup, local sources, V1 contracts, A4 defaults/rendering, profile form/PUT и print snapshot/delivery. Планирование не включает запуск product tests, DB migrations, browser или физической печати. Все такие gates перечислены для выполнения; PASS не заявлен.

## Результат реализации

Этап реализован в `codex/station-printing-follow-up`. [Проверки и ограничения](2026-10-11-printing-follow-up-verification.md) фиксируют фактические результаты, исправления итогового ревью и требования к следующей beta. Исторические задания не переписываются; production deployment и физическая печать здесь не выполнялись.
