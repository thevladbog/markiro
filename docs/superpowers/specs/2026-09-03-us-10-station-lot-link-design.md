## Problem

The station already closes boxes offline, allocates SSCCs from a pre-mirrored pool, prints a box label, records print verification or skip, and syncs all of it idempotently. Nothing on the station knows about a traceability lot: the shift bundle carries product, template, capacities and production date, but no TLC. A U.S. processor running Scenario A (docs/us/demo-scenario.md §5.2) forms 100 cases of `NRF-260915-APL01` on the line and needs the case-to-lot relationship recorded without a live server, printed in human-readable form on the case label, and replayed exactly once when the device reconnects. This slice adds that link as a thin layer on top of the existing box pipeline and leaves every existing invariant untouched (STN-001). Because the administrative Transformation workflow (US-04) already creates the output lot and the bridge table, the station is an optional accelerator, not a dependency of the critical path.

## Design

### Data model

Server (Postgres, additive, `packages/db/src/schema/traceability.ts`):

- `traceability_station_settings` (owned by US-10): `tenant_id text PK → organization.id`, `lot_mismatch_policy` pgEnum `trace_station_lot_policy` (`block`, `warn`) default `block`, `expired_lot_policy` same enum default `block`, `shipping_case_scan` pgEnum `trace_shipping_case_scan` (`optional`, `required`) default `optional`, `created_at`, `updated_at`. One row per U.S. tenant, created lazily with defaults; absent row means defaults (RU tenants never get one).
- `trace_station_lot_links` (owned by US-10, the server-side journal of station link facts): `id uuid PK` (= device `link_id`, so a replay is a primary-key hit), `tenant_id`, `device_id uuid` (composite FK `(tenant_id, device_id)` → `station_devices`), `shift_id uuid` (composite FK → `shifts`), `box_id uuid NULL` (composite FK `(tenant_id, box_id)` → `boxes (tenant_id, id)`; NULL if and only if `outcome = deferred`, enforced by a CHECK), `device_box_id text`, `terminal_id text NULL`, `sscc char(18) NULL`, `lot_id uuid` (composite FK → `traceability_lots`), `tlc_snapshot text`, `operator_id uuid NULL`, `linked_at timestamptz` (device clock), `received_at timestamptz` (server clock), `verdict` pgEnum `trace_station_link_verdict` (`ok`, `override`), `override_reason text NULL`, `policy_snapshot text` (`block|warn` in force on the device), `payload_digest char(64)` (SHA-256 of the canonical link payload: `shiftId, terminalId, deviceBoxId, sscc, lotId, tlc, linkedAt, verdict, overrideReason, policySnapshot`; the same idiom as `station_shift_close_events.payload_digest`), `outcome` pgEnum `trace_station_link_outcome` (`accepted`, `already_resolved`, `conflict`, `rejected`, `deferred`), `conflict_code text NULL` (`box_linked_to_other_lot`, `link_payload_changed`, `lot_not_found`, `lot_unavailable`, `box_disassembled`, `shift_mismatch`, `box_not_synced`). Unique `(tenant_id, id)`; index `(tenant_id, shift_id, device_box_id)`. `deferred` is the only non-terminal outcome: the row is written with `box_id NULL` and `conflict_code = box_not_synced`, and a later replay of the same `link_id` updates it in place to a terminal outcome (the only UPDATE ever issued on this journal). `accepted`, `already_resolved`, `conflict` and `rejected` are terminal.
- `trace_station_print_log` (owned by US-10, server copy of the device print journal, STN-007): `log_id uuid` (device-generated), `tenant_id`, `device_id uuid` (composite FK → `station_devices`), `shift_id uuid` (composite FK → `shifts`), `device_box_id text`, `box_id uuid NULL` (composite FK → `boxes`, resolved like a link; NULL when the box has not synced yet — log rows are facts and are accepted regardless), `link_id uuid NULL`, `action` pgEnum `trace_station_print_action` (`requested`, `confirmed`, `skipped`, `failed`), `confirmation_method` pgEnum `trace_print_confirmation_method` (`scan_back`, `visual`) NULL, CHECK `(action = 'confirmed') = (confirmation_method IS NOT NULL)`, `error_code text NULL`, `printer_kind text NULL`, `printer_identity text NULL`, `printer_language text NULL`, `template_id uuid NULL`, `template_name text NULL`, `station_version text NULL`, `operator_id uuid NULL`, `at timestamptz` (device clock), `received_at timestamptz` (server clock). Primary key `(tenant_id, device_id, log_id)`, so a resend is a primary-key hit and the insert is `ON CONFLICT DO NOTHING`; index `(tenant_id, shift_id, device_box_id)`. Insert-only; never updated.
- Bridge row: on `accepted`, the service inserts `trace_lot_boxes (tenant_id, lot_id, box_id, linked_at, linked_by)` through the US-04 domain/service function. Facts taken from `2026-09-03-us-04-transformation-design.md`: `trace_lot_boxes` has composite FK `trace_lot_boxes_tenant_box_fk` to `boxes(tenant_id, id)`, an `unlinked_at` column and the partial unique `trace_lot_boxes_active_box_uq (tenant_id, box_id) WHERE unlinked_at IS NULL` (one box belongs to at most one active lot), and the cabinet links boxes through `linkLotBoxesSchema { boxIds[] }`. US-10 inserts through that same service path and does not redesign the bridge (OQ-US10-3).
- Bundle: no table change on the server; `ShiftBundleDto` gains an optional `traceLot` object (see Contracts). Its source is the latest non-void `transformation_events` revision whose nullable `shift_id` (composite FK `transformation_events_tenant_shift_fk`, TRN-001 in the US-04 spec) equals the shift, and that event's single output lot; a transformation with several output lots yields `traceLot: null` until the admin picks one (OQ-US10-1).

Station (SQLite, trailing appends to `STATION_MIGRATIONS`):

- `shift_mirror` gains `trace_lot_id TEXT`, `trace_lot_tlc TEXT`, `trace_lot_product_name TEXT`, `trace_lot_production_date TEXT` (ISO `YYYY-MM-DD`), `trace_lot_status TEXT`, `trace_lot_use_by_date TEXT` (ISO, nullable; from the US-02 operational dates of LOT-011), `trace_lot_policy TEXT` (`block|warn`), `trace_expired_policy TEXT`, `trace_locale TEXT` (`en-US|ru-RU`), `trace_tlc_source_name TEXT`. All nullable; a RU bundle leaves them null and the whole feature stays dormant.
- New table `trace_lot_links`: `link_id TEXT PRIMARY KEY`, `shift_id TEXT NOT NULL`, `box_id TEXT NOT NULL`, `terminal_id TEXT`, `sscc TEXT`, `lot_id TEXT NOT NULL`, `tlc TEXT NOT NULL`, `operator_id TEXT`, `linked_at TEXT NOT NULL`, `verdict TEXT NOT NULL` (`ok|override`), `override_reason TEXT`, `policy_snapshot TEXT NOT NULL`, `state TEXT NOT NULL DEFAULT 'pending'` (`pending|accepted|already_resolved|conflict|rejected`), `conflict_code TEXT`, `acked_at TEXT`, `last_checked_at TEXT`; `UNIQUE (box_id)`. Never purged by shift retention while `state = 'pending'`. A server `deferred` answer leaves the row `pending` and only stamps `last_checked_at` (and `conflict_code = box_not_synced` for diagnostics); every other outcome is terminal and sets `acked_at`.
- New table `trace_print_log`: `log_id TEXT PRIMARY KEY` (device-generated UUID, the replay key), `box_id TEXT NOT NULL`, `shift_id TEXT NOT NULL`, `link_id TEXT`, `action TEXT NOT NULL` (`requested|confirmed|skipped|failed`), `confirmation_method TEXT` (`scan_back|visual`; set if and only if `action = 'confirmed'`), `error_code TEXT`, `printer_kind TEXT` (`serial|tcp|usb`), `printer_identity TEXT` (port/host:port/queue name, never bytes), `printer_language TEXT` (`zpl|tspl`), `template_id TEXT`, `template_name TEXT`, `station_version TEXT`, `operator_id TEXT`, `at TEXT NOT NULL`, `acked_at TEXT`. Pure facts, insert-only, drained with the links (STN-007). `confirmed` is written after scan-back verification (`verifyPrintedLabel`) succeeds (`confirmation_method = scan_back`) or, only for a template without a verifiable barcode, after the operator's manual confirmation on the verification screen (`confirmation_method = visual`; see Station); a plain transport success stays `requested` so the evidence export cannot claim a physical print that was never verified. The method travels unchanged through the request payload, the server journal and the evidence export, so a reader can always tell a scanned-back print from a visually confirmed one (whether `visual` rows count as confirmed prints for STN-007 evidence is OQ-US10-6).

### Domain rules

`packages/domain/src/traceability/station-lot-link.ts` (pure, no I/O):

- `evaluateLotLink({ snapshot, scannedTlc?, today, policy })` → `{ decision: "allow" | "warn" | "block", reasons: ("tlc_mismatch" | "lot_expired" | "lot_not_active" | "no_snapshot")[] }`. `tlc_mismatch` fires only when the operator entered or scanned a TLC that differs from `snapshot.tlc` (the bundle TLC is authoritative; STN-004). `lot_expired` fires when `trace_lot_use_by_date < today` in the tenant timezone. `lot_not_active` fires when `snapshot.status !== "active"` (US-02 statuses `consumed`, `shipped`, `quarantined`, `recalled`, `archived`) and always yields `block`, independent of policy: the server rejects such a link as `lot_unavailable`, so a local override could never succeed and is not offered. Policy `block` → `block`; `warn` → `warn` with mandatory override reason (policies exist only for `tlc_mismatch` and `lot_expired`); `no_snapshot` on a U.S. shift is always `block` (cannot link to nothing); on a RU shift the function is never called.
- `traceLotLabelFields(snapshot, box, locale)` → overlays the five new label fields (below) on the record returned by `boxLabelFields`; dates go through the locale-aware formatter `formatLabelDateForLocale(iso, locale)` (OQ-US10-11; `en-US` → `MM/DD/YYYY`, `ru-RU` → `DD.MM.YYYY`, byte-identical to `formatLabelDate`), quantity is `"<count> <uom>"` with the shift product's case UOM (`ea` default) — no unit conversion (NFR-009).
- `linkReplayOutcome(existing, incoming)` (server, pure): same `link_id` and equal `payload_digest` → `already_resolved` (or the stored terminal outcome when the row is `conflict`/`rejected`, so a replay never flips a verdict); same `link_id` with a different digest → `conflict(link_payload_changed)` and no write — the same rule `station-shift-close.service.ts` applies when a close event's payload digest differs; different `link_id`, same box, same lot → `already_resolved`; same box, different lot → `conflict(box_linked_to_other_lot)`. Cycle-free by construction (a box links to exactly one lot).
- Label field enum extension in `packages/domain/src/labels/model.ts`: `LABEL_FIELDS` gains the five keys `trace.tlc`, `trace.product`, `trace.productionDate`, `trace.quantity`, `trace.source` (STN-005). `Record<LabelField, string>` is a closed record, so widening the enum requires every construction site to define all five keys: `sampleLabelData()` (U.S. sample values used by the editor preview), `boxLabelFields` in `apps/station/src/lib/box-label.ts` (empty string for each, for every box on RU and U.S. shifts alike) and the test fixtures that build the record literally; `traceLotLabelFields` then overlays real values on a U.S. shift with a snapshot. Emitters, `bounds.ts` and the editor look fields up by key and need no change; a RU label therefore renders these as `""` exactly like `km.code` today. The admin editor lists the new fields under a "Traceability (U.S.)" group shown only for U.S. profiles; stock templates are unchanged, and US-10 adds two English stock templates (`Case 4×6 in (203 dpi) — TLC`, `Case 4×6 in (203 dpi) — TLC + SSCC`) seeded only for U.S. profiles (OQ-US10-5). Barcodes remain optional carriers: the TLC-only template has no barcode element (STN-006).

### Contracts and API

`packages/platform-contracts/src/traceability/station.ts` (Zod, `.strict()` like the rest of the package):

- `stationTraceLotSnapshotSchema`: `{ lotId, tlc, productName, productionDate (ISO date), status, useByDate (nullable), tlcSourceName, policy: { lotMismatch: "block"|"warn", expiredLot: "block"|"warn" }, locale: "en-US"|"ru-RU" }`. Added to `ShiftBundleDto` and `ShiftReferenceBundleDto` as `traceLot: … | null` (null for RU tenants and for U.S. shifts without an output lot). Bundle OpenAPI schema and `shifts-openapi.test.ts` updated; `shifts-bundle.e2e.test.ts` gains a U.S.-profile case and an unchanged-RU case.
- `POST /station/trace-lot-links` (new, `TenantGuard + StationOnlyGuard + SubscriptionAccessGuard + TraceabilityProfileGuard` with `RequireTraceabilityProfile("US_FSMA204_PROCESSOR", "US_GENERIC_LOT_TRACEABILITY")` from the US-00 spec; the controller is registered in `apps/api/test/authorization-metadata.test.ts`, listed in `docs/device-key-surface.md` "Reachable by a device key" and in the CORS station allow-list tested by `cors-station-surface.test.ts`): body `{ links: [{ linkId, shiftId, terminalId, deviceBoxId, sscc, lotId, tlc, operatorId, linkedAt, verdict, overrideReason, policySnapshot }], printLog: [{ logId, deviceBoxId, shiftId, linkId, action, confirmationMethod, errorCode, printer: { kind, identity, language }, template: { id, name }, stationVersion, operatorId, at }] }`, max 100 links and 500 log rows per call. Response `{ results: [{ linkId, outcome: "accepted" | "already_resolved" | "conflict" | "rejected" | "deferred", conflictCode?, boxId? }], printLog: [{ logId, outcome: "accepted" | "duplicate" }] }`. Every `linkId` and every `logId` in the request gets exactly one result; links are idempotent by the `link_id` PK plus `payload_digest`, print-log rows by the `(tenant_id, device_id, log_id)` PK (`ON CONFLICT DO NOTHING` → `duplicate`). `deferred` is the only retryable outcome; the device keeps such rows pending and resends them on the next drain.
- Server resolution order per link: shift belongs to tenant and is a U.S.-profile shift, else `rejected(shift_mismatch)`; box resolved by `(tenant_id, shift_id, terminal_id, device_box_id)`; if absent → `deferred(box_not_synced)`: the journal row is inserted with `box_id NULL` and the device keeps the row pending (the station only sends links whose `boxes_mirror.acked_at` is set, so this is a defensive branch); on the next replay of the same `link_id` the deferred row is resolved in place; box `disassembled_at` set → `conflict(box_disassembled)`; lot resolved tenant-scoped (cross-tenant id → `rejected(lot_not_found)`, never 404 leaking existence); lot status other than `active` → `rejected(lot_unavailable)` (the same rule `evaluateLotLink` applies locally as `lot_not_active`); then `linkReplayOutcome`.
- `GET/PUT /traceability/station-settings` (cabinet, `RequirePermissions` with the U.S. `traceability.settings.manage` capability from US-00): `{ lotMismatchPolicy, expiredLotPolicy, shippingCaseScan }`. Denied for RU profiles with the standard profile-gating error from US-00.
- Audit events (`tenant_audit_events`, exact fields asserted in tests): `traceability.station_settings.updated` (actor = cabinet user, target_type `traceability_station_settings`, target_id tenant, before/after full row, outcome `ok`); `traceability.lot_box.linked` (actor_user_id null, `after = { deviceId, operatorId, linkId, boxId, lotId, tlc, verdict, overrideReason, policySnapshot }`, target_type `trace_lot_box`, target_id box id, outcome `success` — the value US-00 uses); `traceability.lot_box.link_conflict` (outcome `conflict`, `after.conflictCode`); `traceability.lot_box.link_override` is emitted in addition to `linked` whenever `verdict = override` so an audited override is a distinct row (STN-004). The station device identity is carried in `after.deviceId` because `actor_user_id` is a user FK (OQ-US10-7).
- `POST /station/scans` is not modified. Batch id, box payload and exception payload stay byte-identical; `station-scans.e2e.test.ts` is the regression proof (STN-001).

### Station

- Shift entry (`App.tsx` → `mirrorShiftBundle`): `upsertBundle` writes the `trace_*` columns from `bundle.traceLot` (null-safe; a pre-upgrade server omits the field and the columns stay null). `refreshShiftBundleForRecovery` refreshes them too (reference bundle), so a lot created in the admin after the shift opened reaches the device on the next recovery/refresh without a live dependency at scan time (STN-002).
- WorkScreen header (aggregation mode, U.S. shift only): a "Traceability lot" card with TLC, product description, production date (locale display) and lot status; when the snapshot is null the card shows `No output lot assigned — cases will be linked in the cabinet` and box closing continues unchanged (the link is optional, the box pipeline is not).
- Link moment: inside `closeCurrentBox` success path (`close-box.ts` → `WorkScreen`), after the box row is closed and before the print attempt, a single `INSERT INTO trace_lot_links` is issued when a snapshot exists and `evaluateLotLink` returns `allow`. `warn` opens a full-screen confirmation with the reason list and a required reason field (64 px targets, keyboard reachable; copy in `en.json` and `ru.json`); confirming inserts the row with `verdict = override`; cancelling leaves the box closed and unlinked and shows a persistent "Not linked" chip until the operator links it from the box list or the cabinet does. `block` shows the same screen without a confirm action (STN-004). The insert is one statement; if it fails the box is still closed and printed, and the chip tells the operator to retry (`Link to lot` action on the closed-box row), because losing a link is recoverable in the cabinet whereas blocking a closed box is not.
- Print log: `trace_print_log` rows (each with a fresh `log_id` UUID) are written at `attemptClosedBoxPrint` (`requested` with printer identity from `HardwareConfig`/`PrintTarget`, template id/name from the mirrored `boxLabelTemplate`, `getVersion()` for the station version), on `failed(code)`, on `markPrintSkipped` (`skipped`) and on verification success (`confirmed` with `confirmation_method = scan_back`, or `visual` from the no-barcode confirmation below). Log writes are best-effort inserts after the existing state transitions; they never gate the recovery screen (STN-007).
- Sync: a new drain phase in `createSyncEngine`, run after the scan batch is acknowledged, posts pending `trace_lot_links` whose box has `acked_at IS NOT NULL` plus unacked `trace_print_log` rows to `/station/trace-lot-links`, then applies results per row: links get `state`, `conflict_code`, `acked_at` (a `deferred` result only stamps `last_checked_at` and leaves `state = pending`); log rows get `acked_at` for both `accepted` and `duplicate`. Rejected/conflict rows are terminal, counted into a new `SyncState.lotLinkConflicts`, and shown in `ConflictList` under a "Lot links" heading. The phase respects `pause()/resume()`, credential sealing and backoff exactly like `drainShiftCloseRows`; it is skipped entirely when no U.S. rows exist, so RU devices execute no new network calls (STN-001, STN-003).
- Locale contract (STN-009). Two representations exist and one mapping joins them: the server/bundle side uses BCP-47 tags (`traceLot.locale`, `shift_mirror.trace_locale`: `en-US | ru-RU`), the station UI side uses `SupportedLanguage` from `i18n/index.ts` (`ru | en`, stored in `StationConfig.locale?`). Mapping: tag → language by prefix (`ru*` → `ru`, anything else → `en`, the rule `stationDisplayLocale` already applies in reverse); language → tag is `ru` → `ru-RU`, `en` → `en-US`. Formatting: screen dates keep `formatShiftPlannedDate`/`formatCivilDate` fed with the tag; label dates use the single new `formatLabelDateForLocale(iso, tag)` (OQ-US10-11); no other formatter is introduced. Source of truth: `StationConfig.locale` when set (editable in `WorkstationSetup`); otherwise the bundle's `traceLot.locale` mapped to a language and written to `StationConfig.locale` on first U.S. shift entry; when `traceLot` is null and no config value exists the device stays `ru` (today's hard-coded behavior), so RU devices are unchanged. `i18n/index.ts` reads `StationConfig.locale` at boot; whether a `WorkstationSetup` change applies immediately or on the next start is OQ-US10-8. Storage stays ISO (`YYYY-MM-DD`, UTC instants) — only rendering changes. Quantities on screen and labels print `<n> ea` / `<n> cases` with no conversion.
- Barcodes (STN-006): the U.S. stock template without a barcode prints and verifies (scan-back verification is skipped when the template has no barcode element; a new `templateHasVerifiableBarcode(spec)` helper decides, and the verification screen says `This template has no barcode — confirm the printed text` with a manual confirm that logs `confirmed` with `confirmation_method = "visual"`). Documentation states carriers are optional.
- STN-010 (P2): receiving and shipping station modes are not built. An ADR note (`docs/superpowers/specs/2026-09-03-us-10-station-lot-link-design.md` §Out of scope plus a row in docs/us/limitations.md "Deferred after the MVP release") records the trigger: a design partner needs offline receiving/shipping capture.

### End-to-end sequence (reference)

```text
admin (US-04)   finalize Transformation -> output lot NRF-260915-APL01 (status active)
station         enter shift -> GET /shifts/:id/bundle -> traceLot snapshot mirrored
station         scan 24 cups -> capacity -> closeCurrentBox -> SSCC assigned, box closed
station         evaluateLotLink(snapshot, today, policy) -> allow | warn(reason) | block
station         INSERT trace_lot_links (link_id, box_id, lot_id, tlc, verdict, policy)
station         print label (trace.tlc, trace.product, trace.productionDate, trace.quantity)
station         trace_print_log: requested -> confirmed | skipped | failed(code)
sync            POST /station/scans (unchanged) -> boxes acked
sync            POST /station/trace-lot-links (links with acked boxes + print log)
api             resolve box, lot -> accepted | already_resolved | conflict | rejected | deferred
api             trace_lot_boxes row (US-04) + tenant_audit_events rows
admin           lot card "Station links" panel; conflicts visible, never dropped
```

Restart at any point replays from durable rows: `trace_lot_links.state = pending` and
`trace_print_log.acked_at IS NULL` are the only cursors, and both are keyed by device-
generated ids, so a resend after a crash between server commit and device ack lands on
the server primary key and answers `already_resolved` for links and `duplicate` for print-log rows (STN-001, STN-003).

### Profile gating and RU_CHZ safety

- RU tenants: `traceLot` is null in every bundle; SQLite columns stay null; `evaluateLotLink` is never invoked; the sync phase finds zero rows and makes no request; `LABEL_FIELDS` additions render empty and appear in no RU stock template; admin settings page and label-field group are hidden by the US-00 gating helper; `/station/trace-lot-links` returns `rejected(shift_mismatch)` for a RU shift and writes no audit row. Required proof: the full `apps/station` suite, `station-scans.e2e.test.ts`, `shifts-bundle.e2e.test.ts` RU cases and `sqlite-schema.test.ts` must run unchanged and stay green on the implementing PR; a new test must assert a RU bundle serialization is deep-equal to the pre-slice fixture except for the added `traceLot: null` key (OQ-US10-2).
- U.S. tenants: `US_GENERIC_LOT_TRACEABILITY` gets the same station behavior but its label templates and screens carry no FTR wording (the card title is `Lot`, not `Traceability lot`), consistent with docs/us/demo-scenario.md §4.

## Out of scope

- Station receiving and shipping modes, offline KDE capture, offline trace queries (STN-010, P2; reopened only by a design-partner trigger).
- Any change to `/station/scans`, SSCC allocation, print recovery categories, roster sync or credential recovery.
- Item-level serialization or making a barcode a legal requirement on any label (docs/us/limitations.md).
- Automatic lot expiry inference; the use-by date is whatever US-02 stores.
- Pallet (SSCC extension digit) links; US-04's bridge is box-level.
