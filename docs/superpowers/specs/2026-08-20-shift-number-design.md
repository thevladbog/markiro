# Человекочитаемый номер смены (`AUG26-003`)

**Дата:** 2026-08-20
**Статус:** утверждено

## Задача

У смен нет человекочитаемого номера — они идентифицируются UUID, в UI показывается дата + продукт, на станции в статус-баре может всплыть сырой UUID. Вводим номер формата `<3 буквы месяца EN, заглавные><2 цифры года>-<порядковый номер в месяце, паддинг до 3 цифр>`, например `AUG26-003`. Для смен, созданных на станции («Новая смена»), к номеру добавляется суффикс `/S`: `AUG26-003/S`. Номер отображается в админке и на станции; список смен в админку отдаётся с сортировкой по реальной дате.

## Утверждённые правила

1. **Месяц/год** берутся из `plannedDate` на момент создания; если `plannedDate` не задана (возможно только из админки) — из текущей даты создания. Станция при «Новой смене» сама шлёт `plannedDate` = текущая локальная дата, так что для неё правило «текущий месяц» выполняется автоматически.
2. **Суффикс `/S`** — только у смен с `createdFrom = "station"`. Фиксируется при создании навсегда.
3. **Номер неизменяем.** Перенос `plannedDate` на другой месяц через админку номер не меняет.
4. **Порядковый номер** — сквозной в рамках `(tenant, месяц)` для всех смен независимо от источника; паддинг до 3 цифр (`001`), при seq ≥ 1000 — просто больше цифр без обрезки.
5. **Сортировка `GET /shifts`**: `coalesce(planned_date, created_at::date) DESC, created_at DESC` (новые сверху).
6. **Бэкфилл**: существующие смены получают номера миграцией по тем же правилам; поля NOT NULL.
7. **Этикетки**: поле `shift.no` на коробочных этикетках перестаёт быть пустым — печатается номер смены.

## Решение

### 1. Данные (Postgres, `packages/db`)

- Новая таблица `shift_number_counters`: `tenant_id uuid`, `month_key text`, `last_seq integer NOT NULL`; PK `(tenant_id, month_key)`. Выдача номера — атомарный `INSERT ... ON CONFLICT (tenant_id, month_key) DO UPDATE SET last_seq = last_seq + 1 RETURNING last_seq` в той же транзакции, что и вставка смены. Без гонок и ретраев, номера без дырок.
- В `shifts` две NOT NULL колонки: `number_month_key text` (например `AUG26`) и `number_seq integer`; уникальный индекс `(tenant_id, number_month_key, number_seq)` как страховка инварианта.
- Миграция-бэкфилл в том же файле: `month_key` из `planned_date` (NULL → из `created_at`), `seq` — по порядку `created_at` внутри `(tenant, month_key)` (row_number), счётчики инициализируются максимумами по каждой группе. После заполнения колонки объявляются NOT NULL.

### 2. Домен (`packages/domain`)

- `shiftMonthKey(isoDate: string): string` → `AUG26` (вход — календарная дата `YYYY-MM-DD`, без таймзонной магии; названия месяцев — фиксированная EN-таблица, не `toLocaleString`).
- `formatShiftNumber(input: { monthKey: string; seq: number; createdFrom: "admin" | "station" }): string` → `AUG26-003` / `AUG26-003/S`.
- Экспорт через индекс пакета; используется API (DTO), бэкфилл валидируется e2e, станция и админка получают уже готовую строку.

### 3. API (`apps/api/src/modules/shifts`)

- `createShift`: `monthKey` = `shiftMonthKey(plannedDate ?? текущая дата)`; инкремент счётчика и insert смены — одна транзакция.
- DTO смены (список, деталь, shift-bundle для станции) получает поле `number: string` — собирается `formatShiftNumber` из `number_month_key`, `number_seq`, `created_from`.
- Сортировка списка — правило 5 выше (вместо текущего `ORDER BY created_at ASC`).
- `updateShift` номерные поля не трогает.

### 4. Админка (`apps/admin`)

- Таблица смен: новая первая колонка «Номер» (`pages.shifts.table.number`, ru: «Номер», en: "Number").
- Заголовок панели редактирования и подписи в диалогах (закрытие/удаление): номер вместо `productName ?? id` — `«AUG26-003 · Продукт»`.
- Клиентский DTO (`pages/shifts/api.ts`) расширяется полем `number`.

### 5. Станция (`apps/station`)

- SQLite-зеркало `shift_mirror`: колонка `number text` (+ `ALTER TABLE` в `migrations.ts`), заполняется из API при синке.
- `ShiftSelection` / `ShiftCard`: номер отображается на карточке рядом с продуктом.
- `StatusBar` (`App.tsx`): `shiftLabel` = `«AUG26-003/S · Продукт»`; UUID больше не показывается.
- `box-label.ts`: `"shift.no"` = номер смены (вместо `""`).

### 6. Тесты

- Домен: `shiftMonthKey` (границы месяцев/года), `formatShiftNumber` (паддинг, `/S`, seq ≥ 1000).
- API e2e (`shifts.e2e.test.ts`): последовательные номера в одном месяце; отдельные последовательности по месяцам и тенантам; `/S` для станционного создания; номер не меняется при правке `plannedDate`; сортировка списка; смена без `plannedDate` получает номер текущего месяца.
- Миграция: бэкфилл присваивает корректные номера существующим строкам (тест на схему/миграцию в `packages/db/test`).
- Админка (`shifts.test.tsx`): колонка «Номер» в таблице.
- Станция: карточка выбора смены и статус-бар показывают номер; `close-box.test.ts` — ожидание `shift.no` = номер смены.

## Вне скоупа

- Показ номера в выгрузках смен и именах файлов экспорта.
- Ввод/редактирование номера вручную.
- Значение `kiosk` в `shift_origin` (киоск смены не создаёт).
