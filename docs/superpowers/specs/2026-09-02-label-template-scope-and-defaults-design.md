# Область применения, включение и дефолты по категориям для шаблонов этикеток — Design Spec

**Date:** 2026-09-02

**Status:** Implemented (branch claude/label-template-scope-and-defaults)

**Scope:** Две связанные возможности для библиотеки шаблонов этикеток коробки:
(1) шаблон применим либо ко всем категориям товаров (товарным группам ЧЗ), либо
только к перечисленным; (2) админ включает и выключает шаблоны, и это прорастает во
все точки выбора шаблона в админке и на станции. Как следствие появляется дефолтный
шаблон на категорию в дополнение к общему дефолту организации.

**Related:**

- `docs/superpowers/specs/2026-08-14-default-box-label-template-design.md` — общий дефолт
  организации и снапшот шаблона на смену.
- `docs/superpowers/specs/2026-08-20-station-box-template-selection-design.md` — шаг выбора
  шаблона в `NewShift` на станции.
- `docs/superpowers/specs/2026-08-28-product-archived-flag-design.md` — идиома «скрыть, но
  не удалять» и deny-by-default фильтр листинга.
- `docs/superpowers/specs/2026-08-29-chz-product-groups-design.md` — справочник товарных
  групп ЧЗ и `products.chz_product_group_code`.

## Задача

Библиотека шаблонов уже большая: 20 стоковых на тенанта плюс свои. Все они попадают в
каждый селект без разбора. Два следствия:

- Шаблон, рассчитанный на одну категорию, предлагается для любой. Пример: строка ЕГАИС
  имеет смысл только для ТГ 15 «Пиво», на остальных категориях она печатается пустой.
- Тенанту нужна малая часть библиотеки, но выключить лишнее некуда, и оператор на
  станции листает страницы карточек.

## Ключевые факты кодовой базы

- `label_templates` (`packages/db/src/schema/labels.ts`): колонки `id`, `tenant_id`,
  `name`, `spec`, `created_at`, `updated_at`. Ни статуса, ни области. Стоковые шаблоны
  идентифицируются именем (`packages/domain/src/labels/defaults.ts`), их спеки
  закреплены дрейф-тестом.
- Категории: глобальная таблица `chz_product_groups` (56 кодов), у товара
  `products.chz_product_group_code`. Активный товар всегда имеет код: readiness считает
  карточку без кода незаполненной, а смена и инвентаризация принимают только активный
  товар. Значит в момент выбора шаблона категория известна всегда.
- Смена и инвентаризация привязаны к одному товару (`shifts.product_id`,
  `inventories.product_id`). На станции товар сканируется до шага выбора шаблона.
- Точки выбора шаблона: общий дефолт в `OrgProfilePage`, форма смены `ShiftForm`,
  `InventoryParametersForm` (режим `repack`), шаг шаблона в `NewShift` на станции.
  Станция инвентаризации не создаёт.
- Листинги `GET /label-templates` и `GET /shifts/box-label-templates` не принимают
  параметров. Разрешение дефолта при создании смены:
  `data.boxLabelTemplateId ?? org_profiles.default_box_label_template_id`
  (`ShiftsService.createShift`). Инвентаризация дефолт на сервере не разрешает: админка
  предзаполняет форму из `GET /shifts/planning-config`.
- Правило «ЕГАИС только для ТГ 15» есть на сервере как два литерала
  `product.chzProductGroupCode === 15` в `readiness.service.ts`.
- Спек выбранного шаблона снапшотится на смену и уезжает на станцию только через бандл
  смены и SQLite-зеркало. Станция видит только сводки шаблонов.

## Принятые решения

1. **Общий дефолт организации выбирается только из шаблонов с областью «все
   категории».** Тогда он гарантированно подходит любой смене.
2. **Дефолт на категорию.** Для каждой ТГ, у которой есть хотя бы один неархивный товар
   в каталоге, админ может назначить свой дефолт из пригодных шаблонов. Цепочка
   разрешения: дефолт категории товара → общий дефолт → пусто.
3. **Дефолт всегда пригоден.** Выключить шаблон или сузить его область так, что он
   перестаёт подходить общему дефолту или дефолту категории, нельзя: сервер отвечает 409 с
   подсказкой, куда сходить. Назначить выключенный или неподходящий шаблон дефолтом тоже
   нельзя.
4. **Стоковая библиотека приходит без изменений поведения:** все 20 шаблонов с областью
   «все категории» и включённые, у существующих и у новых тенантов. Админ сам сужает
   область и выключает лишнее.
5. **Редактор даёт мягкую подсказку по ЕГАИС**, не блокируя сохранение.

## Модель данных

Миграция `0111_label_template_scope_and_defaults.sql`.

```sql
ALTER TABLE label_templates
  ADD COLUMN enabled boolean NOT NULL DEFAULT true,
  ADD COLUMN chz_product_group_codes integer[] NULL,
  ADD CONSTRAINT label_templates_product_group_codes_nonempty
    CHECK (chz_product_group_codes IS NULL OR cardinality(chz_product_group_codes) > 0);

CREATE TABLE org_box_label_template_defaults (
  tenant_id text NOT NULL REFERENCES organization(id),
  chz_product_group_code integer NOT NULL REFERENCES chz_product_groups(code),
  template_id uuid NOT NULL,
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, chz_product_group_code),
  CONSTRAINT org_box_label_template_defaults_template_tenant_fk
    FOREIGN KEY (tenant_id, template_id) REFERENCES label_templates(tenant_id, id)
);
```

- `chz_product_group_codes IS NULL` означает «все категории». Непустой массив означает
  «только эти ТГ». Пустой массив запрещён и CHECK-констрейнтом, и zod-схемой.
- Коды массива не защищены FK. API проверяет их по `chz_product_groups` при записи;
  справочник статичный и маленький, нормализация в join-таблицу не окупается
  (рассмотрена и отклонена). Хранить область и флаг внутри `spec` тоже отклонено: `spec`
  это доменная модель печати, она снапшотится в бандл и в SQLite станции.
- Имя `org_box_label_template_defaults_template_tenant_fk` добавляется в
  `LABEL_TEMPLATE_REFERENCE_CONSTRAINTS` сервиса шаблонов, чтобы удаление шаблона с
  дефолтом категории отвечало 409, как и сейчас для общего дефолта.
- Существующие строки получают `enabled = true`, `chz_product_group_codes = NULL`. Данные
  спеков не трогаются, дрейф-тест стоковых шаблонов остаётся зелёным. Провижининг новых
  тенантов (`tenant-provisioning.service.ts`) не меняется: колонки заполняются
  дефолтами.
- Общий дефолт остаётся в `org_profiles.default_box_label_template_id`.
- SQLite-зеркало станции не меняется.

## Домен (`packages/domain`)

Новый модуль `src/labels/eligibility.ts`, чистые функции с юнит-тестами:

```ts
export const EGAIS_PRODUCT_GROUP_CODE = 15;
export function isEgaisApplicable(chzProductGroupCode: number | null): boolean;

export interface BoxLabelTemplateEligibility {
  enabled: boolean;
  chzProductGroupCodes: number[] | null;
}
export function isBoxLabelTemplateEligible(
  template: BoxLabelTemplateEligibility,
  chzProductGroupCode: number,
): boolean; // enabled && (codes === null || codes.includes(code))

export type BoxLabelTemplateDefaultSource = "category" | "organization";
export function resolveBoxLabelTemplateDefault(input: {
  categoryDefaultId: string | null;
  organizationDefaultId: string | null;
}): { templateId: string | null; source: BoxLabelTemplateDefaultSource | null };

export function labelTemplateUsesField(spec: LabelTemplateSpec, field: LabelField): boolean;
```

`readiness.service.ts` переходит на `isEgaisApplicable` вместо двух литералов `15`.
Поведение readiness не меняется.

## API

### Шаблоны (`/label-templates`, кабинет)

- `LabelTemplateSummaryDto` и `LabelTemplateDto` получают `enabled: boolean` и
  `chzProductGroupCodes: number[] | null`.
- `GET /label-templates?enabled=true|false|all`, по умолчанию `true` (deny-by-default,
  как `archived` у товаров). Библиотека запрашивает `all`, все селекты используют
  умолчание. Фильтра по категории у этого эндпоинта нет: сводка несёт область, и админка
  фильтрует на клиенте без повторного запроса при смене товара.
- `POST` и `PATCH` принимают `enabled?: boolean` и `chzProductGroupCodes?: number[] | null`.
  Валидация: массив непустой, без дублей, каждый код есть в `chz_product_groups`, иначе 400.
- Инвариант «дефолт всегда пригоден» на PATCH. Перед записью сервис собирает, где шаблон
  стоит дефолтом: общий дефолт профиля и строки `org_box_label_template_defaults`. Если
  после изменения шаблон перестаёт подходить хотя бы одному месту (выключен, либо для
  общего дефолта область стала не `null`, либо для дефолта категории код выпал из
  области), ответ 409 со списком мест, которым изменение мешает:

  ```json
  {
    "code": "LABEL_TEMPLATE_IS_DEFAULT",
    "message": "Label template is used as a default",
    "organizationDefault": true,
    "categoryDefaults": [15, 22]
  }
  ```

  Проверка и запись выполняются в одной транзакции.

### Профиль организации (`PUT /org/profile`)

- DTO получает `categoryBoxLabelTemplateDefaults: Array<{ chzProductGroupCode: number;
templateId: string }>` и `productGroupsInUse: number[]` (различные коды неархивных
  товаров тенанта с непустым кодом, отсортированы по коду).
- PUT принимает `categoryBoxLabelTemplateDefaults` целиком как замену списка: строки,
  которых нет в новом списке, удаляются. Дубли кодов в списке отвечают 400.
- Валидация дефолтов при PUT: `defaultBoxLabelTemplateId` должен указывать на
  включённый шаблон с областью `null`; каждый `templateId` дефолта категории должен быть
  включён и покрывать свой код. Нарушение отвечает 400 с кодом
  `BOX_LABEL_TEMPLATE_NOT_ELIGIBLE` и полем-нарушителем. Код категории проверяется по
  справочнику. Категорию без товаров в каталоге назначать можно: `productGroupsInUse`
  только подсказка для UI.
- Изменение списка дефолтов категорий пишет событие `tenantAuditEvents` с action
  `tenant.box_label_template_defaults.updated` и полями `before`/`after` (списки
  до и после), по образцу события `tenant.pickup_policy.updated` в том же сервисе.

### Смены (`/shifts`)

- `GET /shifts/planning-config?productId=` возвращает
  `{ defaultBoxLabelTemplateId, defaultSource: "category" | "organization" | null }`. С
  `productId` дефолт разрешается по цепочке для категории товара. Без `productId` ответ
  как раньше плюс `defaultSource: "organization" | null`. Товар чужого тенанта или
  неизвестный отвечает 404.
- `GET /shifts/box-label-templates?productId=`: с `productId` в `items` попадают только
  пригодные шаблоны (включён и область покрывает код товара), `defaultBoxLabelTemplateId`
  и `defaultSource` разрешены по цепочке, дефолт по-прежнему первым в списке. Без
  `productId` список содержит все включённые шаблоны и общий дефолт. Так станции старых
  версий продолжают работать.
- `createShift`: если `boxLabelTemplateId` не передан, сервер разрешает дефолт по цепочке
  для товара смены. Если передан, шаблон должен существовать у тенанта (иначе 400
  «Unknown box label template», как и раньше через FK) и быть пригодным для товара,
  иначе 422 с кодом `BOX_LABEL_TEMPLATE_NOT_ELIGIBLE`. Правило «сбор без шаблона
  невозможен» не меняется.
- `updateShift`: проверка пригодности только когда `boxLabelTemplateId` передан и
  отличается от текущего. Смена с выключенным или непригодным шаблоном остаётся
  редактируемой, если шаблон не трогают.

### Инвентаризации (`/inventories`)

- `create` и `update`: та же проверка пригодности явного `boxLabelTemplateId` к товару
  инвентаризации, 422 с кодом `INVENTORY_BOX_LABEL_TEMPLATE_NOT_ELIGIBLE` (модуль
  использует префикс `INVENTORY_`). На `update` проверка только при смене шаблона.
  Разрешение дефолта на сервере не добавляется:
  инвентаризацию создаёт только админка, а она предзаполняет форму через
  `planning-config?productId=`.

### OpenAPI

Новые параметры, поля и коды ошибок описываются в схемах, гейт покрытия должен пройти.

## Админка

### Библиотека `/labels`

- Чипы фильтра «Все / Включённые / Выключенные», по умолчанию «Все». Страница
  запрашивает `enabled=all` и фильтрует на клиенте.
- Карточка: к бейджам размера и DPI добавляются «Выключен» (нейтральный тон) и область.
  Область «все» читается как «Все категории», одна или две ТГ показываются именами,
  три и больше как «N категорий» с полным списком в `title`.
- Быстрое действие «Выключить / Включить» на карточке для `OPERATIONS_WRITE`, PATCH
  `{ enabled }`. Ответ 409 показывается тостом: «Шаблон стоит дефолтом организации» и/или
  «дефолтом категорий: Пиво, Вода», со ссылкой на настройки.

### Редактор `/labels/:id`

- В форме настроек рядом с именем появляются чекбокс «Включён» и блок «Область
  применения»: радио «Все категории / Только выбранные». Во втором режиме список
  чекбоксов по ТГ из `GET /chz-product-groups` с полем поиска по имени. Переключение на
  «Все категории» очищает выбор. Сохранение общим PATCH вместе с `name` и `spec`;
  область и флаг хранятся в состоянии формы рядом с именем, а не в состоянии спека.
- Подсказка ЕГАИС: если `labelTemplateUsesField(spec, "product.egais")` и область не
  `null` и не содержит `EGAIS_PRODUCT_GROUP_CODE`, под блоком области показывается
  `Alert tone="warning"`: «Поле ЕГАИС заполняется только для товаров категории «Пиво».
  На выбранных категориях оно будет пустым». Сохранение не блокируется.
- Ответ 409 при сохранении показывается как ошибка формы с тем же текстом, что и в
  библиотеке.

### Настройки организации

- Селект общего дефолта содержит только включённые шаблоны с областью «все». Stale-пункт
  для сохранённого, но недоступного значения остаётся.
- Новая секция «Шаблоны коробки по категориям» под общим дефолтом. Строки: объединение
  `productGroupsInUse` и кодов с уже заданным дефолтом, отсортированы по имени ТГ.
  Столбцы: категория, селект с первым пунктом «Как у организации» и пригодными для этой
  категории шаблонами (включён, область `null` или содержит код). Если у сохранённого
  дефолта шаблон стал непригоден, показывается stale-пункт. Пустая секция при отсутствии
  товаров с кодом: подсказка «Назначьте товарам категории в каталоге».
- Сохраняется общей кнопкой профиля: PUT отправляет `categoryBoxLabelTemplateDefaults`
  только с непустыми строками.

### Форма смены

- Список шаблонов фильтруется на клиенте функцией `isBoxLabelTemplateEligible` по коду
  выбранного товара. Пока товар не выбран, список пуст, а пункт «По умолчанию» подписан
  «выберите товар».
- Пункт «По умолчанию» подписывается по `planning-config?productId=`: «по умолчанию для
  категории «Пиво»: <имя>», «по умолчанию организации: <имя>» или «дефолт не настроен».
  Если товар из старой смены отсутствует в списке товаров, категория неизвестна и
  форма показывает весь список включённых шаблонов, а не пустой. Сабмит с пунктом «По
  умолчанию» дожидается ответа `planning-config`, а не отвечает ошибкой.
- Смена товара сбрасывает выбор на «По умолчанию», если текущий шаблон стал непригоден.
- В режиме редактирования сохранённый непригодный шаблон остаётся задизейбленным
  stale-пунктом, как сейчас «шаблон недоступен».

### Параметры инвентаризации

- Тот же клиентский фильтр по товару в режиме `repack`. Предзаполнение из
  `planning-config?productId=` после выбора товара; смена товара пересчитывает
  предзаполнение, если пользователь не выбирал шаблон вручную.

## Станция

- `NewShift.openTemplateStep` передаёт `productId` в `/shifts/box-label-templates`. Сетка
  карточек показывает только пригодные шаблоны, предвыбор берётся из
  `defaultBoxLabelTemplateId`. Пустой список показывает существующее состояние
  `shifts.templatesEmpty`; создать сборочную смену без шаблона по-прежнему нельзя.
- Бандл смены, SQLite-зеркало, печать и поток инвентаризации на станции не меняются.

## Что не меняется

- Спек шаблона и его валидация. Уже созданные смены и инвентаризации с выключенным или
  непригодным шаблоном продолжают печатать по снапшоту.
- Стоковая библиотека, миграции стоковых спеков и дрейф-тест.
- Станции старых версий: без `productId` получают включённые шаблоны и общий дефолт.
- `products.default_label_template_id` остаётся неиспользуемым.

## Тестирование

- Домен: `isBoxLabelTemplateEligible`, `resolveBoxLabelTemplateDefault`,
  `labelTemplateUsesField`, `isEgaisApplicable`.
- API, шаблоны: фильтр `enabled` и его умолчание, 400 на пустой массив, дубли и
  неизвестный код, 409 на выключение и сужение области шаблона-дефолта (общего и
  категории), 409 на удаление шаблона с дефолтом категории, успешный PATCH шаблона без
  дефолтов.
- API, профиль: общий дефолт принимает только область `null`, 400 на выключенный или
  непригодный шаблон в дефолте категории, замена списка удаляет отсутствующие строки,
  `productGroupsInUse` не содержит коды только архивных товаров.
- API, смены: разрешение дефолта категория → организация → пусто, 422 на непригодный
  явный шаблон при создании, PATCH с тем же шаблоном проходит, PATCH на другой
  непригодный отвечает 422, `box-label-templates?productId=` фильтрует и возвращает
  `defaultSource`, без `productId` возвращает только включённые.
- API, инвентаризации: 422 на непригодный явный шаблон.
- Readiness: ЕГАИС применим только для кода 15 через константу.
- Админка: фильтр библиотеки, тост 409 на карточке, подсказка ЕГАИС в редакторе,
  таблица дефолтов категорий и её сохранение, сброс выбора в форме смены при смене
  товара, предзаполнение инвентаризации.
- Станция: `NewShift` передаёт `productId` и предвыбирает разрешённый дефолт.
- OpenAPI: гейт покрытия зелёный.

## Вне объёма
