# US-04 — server case/SSCC bridge

**Status:** Approved by the owner for implementation planning on 2026-09-26. This approval does not claim that the bridge, routes, seed or UI exist, and does not authorize a commit, push, PR or release.

**Scope:** The next US-04 increment after [Transformation revisions and current/pinned genealogy](2026-09-26-us-04-revisions-genealogy-design.md). The [current US-04 design](2026-09-26-us-04-transformation-current-design.md), [MVP contract](../../us/mvp-contract.md) and MUS-CR-001 decision govern where older drafts differ. This increment implements LOT-010/TRN-010 server-side case linkage. Transformation HTTP and the unified Events UI are the next separate increment; the reproducible 100-case seed belongs to US-11. No Station, physical closure, scan ingestion, printing or release is included.

## Intent and accepted choices

The U.S. office workflow must connect an output lot to tenant-owned boxes identified by valid SSCCs without making case records a prerequisite for finalizing a Transformation CTE. `100 case` in the immutable event snapshot is a quantity; `100 linked cases` is a separately queried operational count. Neither implies the other. The P0 demo will explicitly mark its synthetic boxes, but manual P0 linking also accepts any eligible existing box in the same U.S. tenant. The U.S. instance never mounts a RU boxes or Station router to obtain that data.

An eligible box has a valid, non-null SSCC and no `disassembled_at`. The bridge does not infer physical closure from `closed_at`, print fields or a synthetic marker. This intentionally supersedes the historical draft's closed-shift/closed-box prerequisite: synthetic records must not claim a physical closure that did not happen. A box can have only one active lot link. An output lot needs a corroborated current finalized Transformation origin for a _new_ link. If that Transformation is later voided, existing active links and their history remain visible with an explicit current-origin gap; new links are blocked, while an authorized unlink with reason remains possible. Amendment keeps the output lot ID and its case links.

## Storage boundary

Add a migration with three US-owned relations, using the next free migration number at implementation:

1. `trace_lot_boxes` is an append-preserving link history. Each row has a UUID, tenant, box, output lot, frozen bare 18-digit `sscc_at_link`, link source (`manual` or `demo_seed`), authenticated actor or explicit seed actor, link timestamp, and nullable one-time unlink actor/time/reason. Composite tenant FKs reference `boxes(tenant_id,id)` and `traceability_lots(tenant_id,id)`. A partial unique index on `(tenant_id,box_id)` where `unlinked_at IS NULL` enforces one active lot per box; a tenant/lot active index supports counts and pagination. Link identity, lot, box, SSCC and original actor/time are immutable. An unlink may set its three fields once, never clear or rewrite them. No service hard-deletes history.
2. `traceability_synthetic_case_origins` holds the explicit trusted seed marker keyed by `(tenant_id,box_id)` with a tenant-composite box FK, seed identity/version and creation time. Only the controlled US-11 seed/test-fixture path writes it; there is no public create-synthetic-case route. Absence means “existing box record,” not “physically verified.” This marker survives unlink/relink and is separate from _how a particular link was made_.
3. `trace_lot_box_operations` stores tenant, command, operation key, canonical input digest, target and immutable result receipt. Its uniqueness makes retries deterministic. A reused key with a different canonical target/SSCC set/reason conflicts. The command rechecks current authorization before returning a stored receipt.

The bridge does not add `lot_id` or synthetic flags to shared `boxes`, modify `box_items`, copy scan contents or extend Station SQLite. A box's current SSCC must agree with `sscc_at_link` for an active row; drift is surfaced as unavailable/inconsistent rather than silently reassigning a historical SSCC. The supporting `shifts` rows required by the existing box FK are created only by a controlled synthetic fixture/seed, hidden from the US office workflow and not presented as actual production. No trigger claims scan, closure or print verification.

## Commands and reads

Expose only US-allowlisted, session-protected routes and an internal store; do not register RU box controllers. Validate strict shared contracts at the boundary, then reload tenant membership/capability in the service. `traceability.read` permits list and lookup; `traceability.transformation.write` permits link and unlink. QA inherits that capability; auditor is read-only. Origin/Host checks, privacy and no-store headers follow existing US HTTP middleware. Cross-tenant and foreign identifiers reveal no target details.

- `GET /traceability/lots/:lotId/cases`: bounded active case count and paginated active/history rows, frozen SSCC, link provenance, synthetic/existing-record marker, actors/times, and the lot's current-origin state. The count is of active bridge rows only, never a CTE quantity or regulatory KDE.
- `GET /traceability/cases/lookup?sscc=...`: exact tenant-scoped lookup, returning the case and its active linked lot or an explicit unlinked state. Accept shared-domain SSCC forms (bare, `00` and `(00)`/supported scanner wrapper), normalize to bare 18 digits and verify the check digit. Return current-origin gap when applicable. An unknown or foreign case is not found; this is not the later US-06 broad Search feature.
- `POST /traceability/lots/:lotId/cases`: bounded atomic manual link of 1–100 distinct normalized SSCCs with an operation key. Require a current finalized Transformation output origin, eligible same-tenant boxes and no active link to another lot. An already active link to the same lot is reported unchanged, not inserted again. Any invalid/conflicting member rejects the entire batch; there is no partial success or inferred box creation. The response distinguishes newly linked and unchanged IDs/counts. The caller cannot choose `link_source=demo_seed` or synthetic provenance.
- `POST /traceability/lots/:lotId/cases/:linkId/unlink`: a single active link ID, required reason and operation key. Compare the exact active link, not just the SSCC, so a stale request cannot unlink a later relink. It remains available when the lot has lost its current origin. A successful unlink retains the historical row and records the actor, reason and time. An exact replay returns the saved receipt; a stale/new intent conflicts without changing a later link.

All writes use one transaction for membership check, operation-key arbitration, target/box validation, link mutation, receipt and exact `tenant_audit_events` row. Acquire the affected lot lock before sorted box locks and coordinate with the existing per-lot dependency version used by Transformation finalize/void; retry serialization conflicts through the established bounded transaction pattern. The active unique index remains the last line of defense against concurrent links. Audit assertions cover exact tenant, actor, action, target, outcome, request ID and relevant before/after box/lot/link/source/reason metadata. Seed actions use an explicit seed identity in metadata, never a spoofed cabinet user.

## Failure and lifecycle behavior

Malformed SSCC, duplicate entries, oversized batch and invalid reason are precise input errors. Missing/foreign lot or box is not found without cross-tenant disclosure. A box already linked elsewhere, stale link, changed operation-key payload, retired box or missing current output origin is a 409 with a stable code and no partial writes. Infrastructure failure is not a successful incomplete result. A voided origin does not detach cases, resurrect a current event or make lookup claim complete provenance. Link/unlink never changes the event's frozen snapshot, event quantity, lot identity, lot status, quarantine/recall holds or genealogy edges.

The existing bridge is operational, not an FDA KDE or a readiness shortcut. A zero-link finalized Transformation is valid. The separate demo acceptance asserts 100-case event quantity and 100 active synthetic links independently. Case history remains available after amendment, void and unlink; a later relink is a new row.

## Delivery and verification

Implement in separately reviewable steps: strict contracts and migration/schema tests; internal link/unlink/lookup service with focused failing tests; US HTTP registration and access/error contract tests; then CI/isolation ownership. The controlled US-11 seed may be built later against this contract. The subsequent UI specification will reconcile the `.pen` Cases frames and EN/ES design briefs through Pencil MCP, use a unified Events list for Receiving and Transformation, preserve the current Receiving editor, and show Cases on output lots and finalized Transformation detail. Shipping remains absent until US-05; no disabled placeholder.

Required tests include fresh/upgrade migration, tenant-composite FK and active uniqueness, 100 eligible synthetic fixtures without physical-closure assertions, existing-box linking, malformed/check-digit SSCC, disassembled rejection, same-lot no-op, cross-lot and cross-tenant denial, batch atomicity, concurrent link/link and link/unlink, operation replay/conflict, exact audit, amendment stability, void origin gap/new-link refusal/unlink allowance, and immutable CTE snapshot bytes. Run affected domain/contracts/DB/API package gates, focused US PostgreSQL integration, isolation checker and `git diff --check`; report database skips, RU regression coverage and external/browser/hardware gates separately. Neither synthetic rows nor automated checks prove a physical line, a deployed US data plane or regulatory acceptance.

## Open boundaries

No live synthetic-case creation API, automatic association at finalization or case closure, shift selection, Station sync, label printing, GTIN/KM dependency, Shipping case selection, broad Search, export/package logic, production rollout, provider choice, or release action belongs to this increment. The case bridge is designed so the later US-06 Search and US-11 seed can consume its exact read contract without rewriting link history.
