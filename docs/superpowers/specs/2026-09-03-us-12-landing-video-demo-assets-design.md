## Problem

The landing (`apps/landing`, Astro 7, RU root + `/en/` mirror) positions Markiro exclusively as a beer and low-alcohol marking system for Chestny ZNAK; `grep FDA` over the landing, admin and README returns nothing. The MVP needs a public English page that describes the U.S. traceability demonstrator in the cautious wording of docs/us/limitations.md, a 5–8 minute narrated video, and a repeatable demo kit for discovery calls, specialist review and optional structured product feedback. None of these assets exist, there is no place in the repository for a video (no LFS, no CDN), and no test prevents a prohibited claim from reaching the public site.

## Design

### Data model

Not touched. No database change; the demo-request `sourcePath` enum is a code constant, not a column.

### Domain rules

- `packages/domain/src/traceability/claims.ts` (US-00 spec, `2026-09-03-us-00-regulatory-profile-design.md`) exports `PROHIBITED_CLAIM_PATTERNS` (English and Russian regexes for the right column of docs/us/limitations.md) and `findProhibitedClaims(text): string[]`. US-12 consumes it from the landing tests and the demo-content linter so there is exactly one list (field-registry principle applied to wording), and proposes one addition to that list: `/compliance[- ]ready/i`, rejected everywhere on public surfaces until the EVD-009 memo exists (OQ-US12-7).
- `usTraceabilityCopy` (`apps/landing/src/content/us-traceability.ts`): a typed, frozen EN object (`hero`, `whatItDoes`, `threeCtes`, `lotLevel`, `demoNumbers`, `limitations`, `cta`) whose `limitations` block is the "No certification statement" paragraph of docs/us/limitations.md verbatim, duplicated in `us-traceability.ts` (no docs→landing build dependency) with a drift test that compares it byte-for-byte to the markdown so the page and the document cannot diverge (OQ-US12-4, recommended, pending confirmation).

### Contracts and API

- `apps/api/src/modules/demo-requests/demo-request-routes.ts`: `DEMO_SOURCE_PATHS` gains `/en/us-food-traceability/` (and the RU alternate if OQ-US12-1 chooses one). `market: "ru" | "us"` is derived server-side from the validated `sourcePath` (`/en/us-food-traceability/` and its RU alternate → `us`, every other allow-listed path → `ru`) by a pure `marketForSourcePath()` next to `DEMO_SOURCE_PATHS`; the request body carries no `market` field, so a U.S. submission can never be filed as `ru` by omission and a client cannot send an inconsistent pair. The derived value is threaded to the lead e-mail subject so U.S. leads are distinguishable (`LANDING_DEMO_RECIPIENT` unchanged). Contract test in `apps/api/test/demo-requests*.test.ts` updated; no other API change.
- Consent: the form on the U.S. page keeps the existing consent gate but references the EN consent artifact `MKR-PD-02` (en) already published under `/en/personal-data-consent/`; whether a Russian-law consent is appropriate for U.S. leads is OQ-US12-5. Safe default until OQ-US12-5 is resolved: U.S. form submissions stay disabled — the U.S. page pair is built with submissions off regardless of `PUBLIC_DEMO_SUBMISSION_ENABLED` (OQ-US12-3 decides the mechanism) and shows the contact e-mail instead of the POST form.

### Landing page

- Route `/en/us-food-traceability/` (EN, `locale: "en"`), alternate RU page `/proslezhivaemost-pishchevoi-produktsii-ssha/` (short RU summary with the same limitations block, needed for the reciprocity test and hreflang; OQ-US12-1). Both added to `SEO_PAGES`, so sitemap, llms.txt, breadcrumbs and JSON-LD come for free; `og-us-food-traceability.jpg` added to `public/`; `reviewedAt` set to the tag date.
- Sections (in order): hero `Markiro U.S. Traceability — a traceability readiness demonstrator for small and mid-sized food processors` with lead `Designed to support applicable FSMA 204 recordkeeping requirements: lot-level Receiving, Transformation and Shipping records, a versioned Traceability Plan and an FDA-aligned electronic sortable spreadsheet.`; `01 / Three critical tracking events` (Receiving, Transformation, Shipping, each with its KDE groups from docs/us/data-dictionary.md §7); `02 / Lot-level, not item-level` (`Lot-level workflow with optional case scanning`; SSCC/GS1-128/QR are optional carriers); `03 / 24-hour readiness` (trace request, `due_at`, validation, package contents); `04 / Built on a working platform` (the existing offline station, tenancy, audit, label engine; link to `/en/offline-production/`); `05 / What the demo shows` (Scenario A numbers from docs/us/demo-scenario.md §5.5 and a still frame from the video); `06 / Limitations and non-goals` (the verbatim statement plus the bullet list of excluded CTEs, exemptions engine, EPCIS and direct FDA submission — EVD-007); `07 / Talk to us` (existing `DemoSection` with `market: "us"`, EN phone placeholder `+1 202 555 0114`, note `Synthetic demo only; no customer data is shown`).
- Wording in every section comes only from the "Allowed" column; the page never uses `compliant`, `certified`, `approved`, `guarantee`, `required by FDA`. `EPCIS-ready architecture (future)` is the only EPCIS mention.
- Video embed: a static poster image with a link to the hosted MP4 (see below); no third-party iframe, so `landing_csp` in `deploy/production/Caddyfile` is unchanged. If the file is hosted on `releases.markiro.app`, only `media-src`/`connect-src` for that origin is added (OQ-US12-2).
- Navigation: EN header gets a `U.S. traceability` link; RU header unchanged. Footer link lists updated symmetrically (`rendered-page.test.ts` counts footer links; the RU count stays at 6 + 3 unless the RU alternate is linked).
- Accessibility and SEO: same components and tokens; Lighthouse gate stays ≥ existing thresholds (`scripts/lighthouse-landing.mjs`); page passes `auditBuiltSite`.

### Content review test for prohibited wording

- `src/lib/audit.ts` gains finding code `PROHIBITED_CLAIM` (`{ code, path, excerpt }`) computed over `document.body.textContent`, `meta[name=description]`, `og:*` and JSON-LD strings of every built HTML file using `findProhibitedClaims`; `test/site-audit.test.ts` therefore fails on any prohibited phrase anywhere on the site, RU pages included. The matrix rows in docs/us/limitations.md are not built into the site, so no allow-list is needed for the landing.
- `test/rendered-page.test.ts` additions for the U.S. page: zero Cyrillic on the EN route (existing pattern), presence of the exact limitations paragraph, `expect(findProhibitedClaims(renderedText)).toEqual([])` on both the EN route and the RU alternate (the shared EN+RU `PROHIBITED_CLAIM_PATTERNS`, not a hand-written English-only FDA regex), demo form `data-market="us"` and `sourcePath` value in the allow-list, poster link points to a URL whose SHA-256 is listed in `docs/us/evidence/register.json`.
- `tools/production-browser/tests/landing-seo.spec.ts`: hreflang pair and canonical for the two new routes; JSON-LD `SoftwareApplication.description` free of prohibited phrases.
- The same `findProhibitedClaims` runs in `us-demo scan` (US-11) over `docs/us/demo-assets/**`, the video script and transcript.
- Text embedded in raster assets is outside the automated audit: the OG image, the video poster, screenshot frames used on the page and the video overlays/captions are checked by a manual review step recorded in the register (`evidenceType: screenshot`, `verifiedBy`, `verifiedAt`) before the tag; automated OCR is out of scope for this slice.

### Demo video production plan (EVD-004, C-016)

- Script: `docs/us/demo-assets/video-script.md`, nine scenes mapped 1:1 to docs/us/demo-scenario.md §5.4 with target durations (intro and baseline 0:40; classification 0:35; receiving 0:50; transformation 1:00; shipping 0:40; backward/forward trace 0:50; trace request and validation 0:50; package generation 0:50; limitations 0:35; total 6:50 ± 1:00). Each scene lists the route, the on-screen fixture ids (`OSS-260914-A1`, `NRF-260915-APL01`, `REQ-2026-APPLE-001`) and the narration text; narration lines are linted with `findProhibitedClaims`.
- Narration rules: English; say `designed to support applicable FSMA 204 recordkeeping requirements` and `FDA-aligned electronic sortable spreadsheet`; never `compliant`, `certified`, `approved`, `guarantees`; state in scene 1 that all parties, lots and documents are synthetic and in scene 9 that there is no direct FDA submission, no certification and EPCIS is deferred; do not mention pricing, customers, or Russian regulators; show the evidence ribbon (build, seed version, baseline) in every frame.
- Recording setup: seeded tenant `us-demo-apple` from `pnpm us-demo:seed` at the tagged commit, admin opened with `?evidence=1`, fresh browser profile, 1920×1080, OS locale `en-US`, timezone `America/Los_Angeles`, system date within the demo week or the ribbon date visibly noted; screen capture 30 fps, H.264 MP4 plus a `.vtt` caption file generated from the script; no cursor highlighting plugins; no background music (avoids licensing questions).
- Storage and hash: the MP4 is not committed (no LFS; a 6–7 minute 1080p file is 150–400 MB). Canonical copy in the sealed package `evidence/US-<date>-demo-01/video/demo-us-traceability-v0.1.0.mp4` with SHA-256 in `SHA256SUMS`; public copy uploaded to object storage under `https://releases.markiro.app/us/demo-us-traceability-v0.1.0.mp4` (immutable key, same SHA-256, `Content-Type: video/mp4`) using the `tools/station-release/object-storage.mjs` upload/verify helpers; the register entry `CL-xxx` cites both the package path and the public URL with the hash. Optional unlisted YouTube copy only as a convenience link in demo follow-up e-mail, never embedded (OQ-US12-2).

### Demo asset package (C-021, C-022, EVD-009, EVD-010)

Tracked, public, template-only, no recipient data — `docs/us/demo-assets/`:

- `one-pager.md`: problem (24-hour records, lot-level KDEs, small processors), what Markiro U.S. Traceability does (three CTEs, TLC/source, plan, request, XLSX), what it is not (limitations block verbatim), demo numbers, link to the page and video, contact `hello@v-b.tech` (existing operator address); rendered to PDF with the `@react-pdf/renderer` script from US-11 (`tools/us-demo/render-doc.mjs`) on the EN letterhead layout of `MKR-BRD-01`; PDF hash recorded in the register.
- `deck-outline.md`: 10 slides — context and rule timeline (from docs/us/regulatory-basis.md, dated), target users, the three-CTE flow (docs/us/diagrams/demo_chain.png), data model (architecture_scope.png), demo walkthrough stills, evidence ladder (evidence_ladder.png), platform foundation (RU product facts from README), limitations, roadmap (P1/P2 from docs/us/implementation-plan.md), next steps. Slides are produced outside the repo from this outline; the outline is the tracked source.
- `discovery-call-guide.md`: 30-minute agenda, 12 open questions (current lot records, how a request would be answered today, who assigns TLCs, what documents exist, case scanning practice, ERP/EDI), what to demo live vs. video, follow-up template, note-taking template that records only business facts and explicit permission to be quoted.
- `feedback-guide.md` (EVD-010): a neutral question set recording what the participant reviewed, which workflow or artifact was useful, where it differs from current practice, and any concerns or missing steps. It does not solicit purchase commitments, commercial promises, endorsements, compliance claims or confidential company data. Names and organizations are recorded only with explicit consent; otherwise the register uses a neutral participant id and hash. A `feedback-follow-up-email.md` template accompanies it.
- `specialist-review-request.md` (EVD-009): memo template addressed to a U.S. food-safety or traceability specialist — purpose (scope and terminology review of a demonstrator, explicitly not a legal opinion or certification), materials provided (`docs/us/regulatory-basis.md`, `data-dictionary.md`, `limitations.md`, the video, a read-only seeded tenant), questions (are the CTE/KDE mappings and TLC/source terminology consistent with FDA-03/FDA-09; is the limitations statement adequate; is any wording an overclaim), requested output (dated written feedback or a signed memo of 1–2 pages, permission to cite), disclosure of any compensation, timeline, and the standing rule that `compliance-ready` may be used only after this review (docs/us/regulatory-basis.md step 5).
- `README.md` in that directory: index, how each asset maps to C-021/C-022 and to register entries, and the rule that feedback records, memos and call notes never enter git.

Private, sealed — `evidence/US-<date>-demo-01/external/`: feedback records (`EXT-FEEDBACK-01.json` or `.pdf`), review memo (`EXT-REV-01.pdf`) and consented call notes, hashed and listed in `SHA256SUMS`; the register cites them by id and hash only. The verification report's External section lists what was obtained and marks the rest `not performed` (EVD-008).
