# Признак «Не использовать» (архив) у карточки товара

Дата: 2026-08-28. Статус: принято, реализуется в этой ветке.

## Задача

В админке тенанта нужно уметь помечать карточку товара как «Не использовать»
(«Неактивна») вместо удаления: товар может фигурировать в исторических заказах,
сменах и отчётах. Помеченный товар нельзя выбрать ни на киоске, ни в других
местах выбора товара — **кроме инвентаризации**, где выбор остаётся возможным
(инвентаризация остатков снятого с производства товара — целевой сценарий).

## Ключевые факты кодовой базы

- `products.status` (`draft`/`active`) — серверно-вычисляемый признак полноты
  карточки (`ProductsService.computeStatus`), пересчитывается при каждом
  create/update. Третьим значением enum флаг быть не может — его сотрёт
  ближайший PATCH.
- В репозитории уже есть идиома «скрыть, но не удалять»: булева колонка
  `pickup_order_reasons.archived` и статус киоска `archived`.
- `GET /products` — единственный листинг каталога; его используют каталог,
  форма смены, форма инвентаризации, поиск по кодам, очередь кандидатов 1С,
  секция товаров киоска и станция (резолв GTIN при создании смены).

## Решение

### Модель данных

`products.archived boolean NOT NULL DEFAULT false` — отдельная колонка,
ортогональная вычисляемому `status`. Новая drizzle-миграция (0085).

### API

- `ProductDto.archived: boolean`; `create/updateProductSchema` принимают
  `archived: z.boolean().optional()` (PATCH — переключение, повторная
  активация разрешена).
- `GET /products` получает параметр `archived: "true" | "false" | "all"`
  (default `"false"`). Deny-by-default: без параметра архивные скрыты, и любая
  будущая точка выбора безопасна автоматически. `"all"` — явный opt-in для
  каталога, формы инвентаризации, поиска по кодам, формы смены и очереди
  кандидатов; `"true"` — фильтр «Не используется» на странице каталога.
  Фильтры `status=draft|active` продолжают работать и подчиняются тому же
  правилу `archived`.

### Серверные запреты (defense in depth)

1. `ShiftsService.createShift` — 422 для архивного товара (по аналогии с
   гейтом черновика).
2. `KiosksService.setProducts` — 400 при попытке назначить киоску архивный
   товар.
3. Kiosk bootstrap (`PickupOrdersService.bootstrap`) и `kioskAllowlist` —
   `archived = false` в join: уже назначенный товар исчезает с киоска после
   ближайшей синхронизации, его коды перестают приниматься в заказы.
4. Пул подсказок кандидатов 1С (`IntegrationsService`) — архивные товары не
   предлагаются к связыванию.
5. Инвентаризация — **без изменений**: `resolveParameters`/lifecycle требуют
   только `status === "active"` (полноту карточки) и принимают архивный товар.
6. Обмен CommerceML — без изменений: импорт цен продолжает обновлять
   `unit_price` уже связанных архивных товаров (историчность данных).

### Админка

- Каталог: чип «Не используется» (neutral) в колонке статуса; фильтр статусов
  получает четвёртый пункт «Не используется»; «Все статусы» показывают и
  архивные (`archived=all`).
- Карточка товара (режим редактирования): чекбокс «Не использовать» с
  пояснением; сохраняется обычным PATCH.
- Форма смены: `archived=all` + архивные опции задизейблены с подсказкой (как
  черновики); при редактировании смены название архивного товара продолжает
  отображаться.
- Форма инвентаризации: `archived=all`, архивные остаются выбираемыми, в
  описании опции — пометка «не используется».
- Поиск по кодам: `archived=all` (отчётность по историческим данным).
- Очередь кандидатов 1С: `archived=all` для резолва имён, но в модалке
  связывания архивные товары исключены из списка выбора.
- Секция товаров киоска и дашборд — без изменений (серверный default уже
  скрывает архивные).

### Киоск и станция

Без изменений кода: киоск получает отфильтрованный bootstrap; станция резолвит
GTIN через `GET /products?search=…` с серверным default `archived=false`, а
`POST /shifts` отбивает архивный товар 422.

## Отклонённые альтернативы

- Третье значение enum `product_status` — конфликтует с вычисляемым статусом.
- `archived_at timestamptz` — момент архивации нигде не показывается; булево
  поле проще и совпадает с идиомой `pickup_order_reasons.archived`.
- Мягкое удаление (`deleted_at`) — требование явно про обратимый признак, а не
  про удаление.

## Тесты

- API e2e: products (PATCH/фильтры листинга), shifts (422), kiosks (400 на
  назначение), kiosk bootstrap (исключение из payload), inventories (создание
  инвентаризации по архивному товару успешно).
- packages/db: тест схемы/миграции по существующему образцу.
- Admin: каталог (чекбокс, чип, фильтр), формы смены/инвентаризации.
