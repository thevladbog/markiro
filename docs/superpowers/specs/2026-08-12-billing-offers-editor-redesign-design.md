# Редизайн создания счетов и коммерческих предложений

## Контекст

Текущие формы в SaaS-admin создают документ из одной условной строки. Оператор вводит tenant ID и сумму, не видит каталог, не может добавить несколько позиций, посчитать НДС или проверить итог до сохранения. В нескольких разделах сохраняются нативные `<select>`, а стили формы заданы локально через `style`.

Backend уже поддерживает до 100 строк в счёте и коммерческом предложении, опубликованные версии каталога, индивидуальную цену, НДС и правила применения тарифа или дополнения. Редизайн должен раскрыть этот контракт без изменения финансовой модели.

## Цели

- Создавать счёт или коммерческое предложение из одной или нескольких строк.
- Добавлять опубликованные тарифы, дополнения и услуги через поиск.
- Выбирать тенанта по имени или slug, не копировать технический ID вручную.
- До сохранения показывать сумму без НДС, НДС и итог.
- Явно задавать применение тарифа и дополнения после оплаты.
- Использовать общий редактор для счетов и предложений.
- Убрать нативные селекты из SaaS-admin и сохранить доступность с клавиатуры.

## Не входит в объём

- Редактирование уже выставленного счёта или опубликованного предложения.
- Новая бухгалтерская модель, валюты кроме RUB или изменение расчёта НДС на backend.
- ЭДО, отправка документа контрагенту и кабинет контрагента.
- Перетаскивание строк мышью. Позиция определяется порядком добавления; при необходимости используются кнопки вверх/вниз.

## Информационная архитектура

Список и создание разделяются:

- `/billing` — реестр счетов и операции с выбранным счётом;
- `/billing/new` — полноэкранный редактор нового счёта;
- `/offers` — реестр коммерческих предложений;
- `/offers/new` — полноэкранный редактор нового предложения.

Из карточки тенанта доступны действия «Создать счёт» и «Создать предложение». Они открывают редактор с заранее выбранным tenant ID. Из коммерческого предложения действие «Создать счёт» открывает редактор счёта с копией всех строк. В рамках этого редизайна новая скрытая связь между документами в базе не добавляется.

## Общий редактор документа

Редактор состоит из трёх визуальных зон.

### Шапка документа

- Заголовок и понятная ссылка назад к реестру.
- Поисковый combobox тенанта: название, slug и текущий статус подписки.
- Для предложения — срок действия.
- Для счёта — срок оплаты.
- Режим применения после оплаты: вручную или автоматически.

### Таблица позиций

Каждая строка содержит:

- порядковый номер;
- тип и название позиции;
- зафиксированную версию каталога;
- количество;
- единицу измерения;
- цену за единицу;
- ставку НДС и отметку «включён в цену»;
- правило применения для тарифа и дополнения;
- сумму строки;
- действия перемещения и удаления.

Добавление выполняется через searchable combobox по опубликованным версиям каталога. Поиск работает по русскому и английскому названию, коду, типу и версии. Результат группируется по тарифам, дополнениям и услугам. После выбора строка получает цену, единицу и НДС из версии каталога; цену можно изменить как согласованную цену документа.

Одна версия каталога может быть добавлена повторно только осознанно: повторный выбор увеличивает количество существующей строки, а отдельная строка создаётся через явное действие «Добавить отдельной строкой».

### Сводка и сохранение

Липкая правая панель показывает:

- количество строк;
- сумму без НДС;
- НДС;
- итог в RUB;
- режим применения;
- ошибки, блокирующие сохранение;
- основное действие «Создать черновик».

Итоги на клиенте служат предварительным расчётом. После создания интерфейс использует суммы, возвращённые backend, как авторитетные.

## Коммерческое предложение и счёт

Оба документа используют один `DocumentComposer` и одну модель строки. Различия задаются конфигурацией:

| Возможность | Счёт | Коммерческое предложение |
| --- | --- | --- |
| Срок | срок оплаты | срок действия |
| Создание | draft | draft |
| Следующее действие | выставить | опубликовать |
| Применение после оплаты | manual / automatic | сохраняется в строках |
| Создать счёт из источника | — | доступно для опубликованного предложения |

Коммерческое предложение создаётся из тех же опубликованных позиций каталога, а не из захардкоженной услуги.

## Компоненты выбора

Нативные `<select>` в SaaS-admin заменяются компонентами `@markiro/ui` на Radix:

- короткие списки — `Select` без `native`;
- длинные списки тенантов и каталога — новый `Combobox` с поиском, keyboard navigation, empty/loading/error states и portal внутри overlay-контейнера;
- множественный выбор не нужен: строки добавляются по одной;
- все trigger-элементы имеют минимум 44 px, видимый focus ring и корректные label/description.

Замена охватывает billing, offers, team, catalog, tenant filters и subscription assignment. Исключение допускается только для системного select внутри офлайн/аппаратного интерфейса, которого в SaaS-admin нет.

## Визуальное направление

Сохраняется индустриальный стиль Markiro: IBM Plex Sans/Mono, жёсткая сетка, тёплый светлый фон, один зелёный акцент и табличные цифры. Формы больше не выглядят как набор равнозначных карточек:

- редактор занимает основную ширину страницы;
- таблица строк является главным рабочим объектом;
- сводка визуально отделена вертикальной направляющей и остаётся видимой при прокрутке;
- технические идентификаторы показываются вторичным моноширинным текстом;
- hover, active и focus состояния единообразны;
- inline-стили переносятся в `global.css` с именованными классами.

## Валидация и ошибки

Сохранение блокируется, если:

- не выбран тенант;
- нет ни одной строки;
- количество меньше 1 или не целое;
- цена не соответствует денежному формату;
- для тарифа или дополнения не задано допустимое правило применения;
- версия каталога больше не опубликована.

Ошибки отображаются возле поля и в сводке. Ошибка одной строки не очищает остальные строки. Конфликт публикации или версии предлагает обновить каталог и повторить проверку.

При переходе со страницы с изменениями показывается существующий navigation blocker. Успешное создание ведёт на реестр и выделяет новый документ; введённые данные не теряются при серверной ошибке.

## Доступность и адаптивность

- Один `h1`, логичная иерархия `h2` для секций.
- Таблица имеет доступное имя и клавиатурную прокрутку.
- Combobox поддерживает ввод, стрелки, Enter, Escape и возврат фокуса.
- Кнопки удаления имеют имя с названием позиции.
- Итоги обновляются через ненавязчивый `aria-live`.
- На ширине до 900 px сводка переходит под строки, таблица прокручивается внутри своего контейнера, страница не получает горизонтальный overflow.

## Данные и API

Frontend продолжает использовать существующие endpoints:

- `GET /platform/tenants`;
- `GET /platform/catalog/items`;
- `POST /platform/invoices`;
- `POST /platform/offers`;
- `GET /platform/offers/:id` для создания счёта из предложения.

Payload содержит массив `lines` до 100 элементов. Для каталоговой строки передаются `kind`, `catalogVersionId`, `quantity`, `agreedUnitPrice`, `vatRateBps`, `vatIncluded` и допустимая `activationPolicy`. Название и единица берутся из опубликованной версии на backend. Пользовательские строки не добавляются в этом редизайне: услуги создаются через каталог.

## Тестирование

Компонентные тесты должны доказать:

- поиск и выбор тенанта без ввода ID;
- поиск позиции по имени, коду и версии;
- добавление минимум трёх строк разных типов;
- увеличение количества при повторном выборе;
- удаление и изменение количества/цены;
- независимый расчёт суммы, НДС и итога;
- отдельные правила применения тарифа и дополнения;
- точный payload для счёта и предложения;
- создание счёта из всех строк коммерческого предложения;
- отсутствие нативных select в SaaS-admin формах;
- сохранение введённых данных после ошибки;
- блокировку ухода с несохранёнными изменениями.

Финальные проверки: package tests, typecheck, lint, build, format/diff, затем браузер на desktop и 390 px с keyboard-проходом combobox и проверкой overflow.
