Both accept only trusted dataset context and a strict unit selector, not transaction, proof, receipt, skip flag, callback or previously observed result. Both independently establish actual target/original owner/profile before interpreting the selector. `verify` never installs prerequisites or repairs progress. The returned bounded deeply frozen result contains the current Trace result and exact native assembly entry for that same unit; it is output, never authority accepted by another entry.

Each public unit invocation independently authorizes the actual target/owner/profile, strictly parses its selector, then calls `UsDatasetReferenceSeedStore[mode]` before any selected-unit business work, loading the current header afterward. Initialize owns installation of missing shared references; verify never does. Do not replace these errors with Trace-target or Shipping errors. The repeated Reference proof is an explicit residual cost, not grounds for a `referencesVerified` flag.

For regular units, preserve the existing four-header completion discriminator: all Receiving/Transformation/Cases/Shipping rows must be revision2 with receipts. If any is incomplete, call Receiving[mode], Transformation[mode], Cases[mode], then Shipping[mode] in that order, proving completed ancestors as well as creating missing work in initialize. Verify uses only verifier methods and preserves the local first error/annotations/cause, including earlier ancestor drift before later missing stages. If all four are complete, use one fresh terminal Shipping projection. A projection-producing initializer uses the existing private Shipping execute's actual final checked projection, releasing it only after its atomic transaction commits. That same unit invocation immediately derives the native summary and Trace expectation from the checked projection and executes the existing real Trace/readiness/history reads for every expected lot, all exact comparators, date window, history limit and semantic digest rules. No second terminal proof is run solely to reconstruct the same expectation.

Existing standalone native/range, Trace proof and Trace stage APIs stay independently guarded with their current prerequisite-only behavior; calling existing stage initialize must not suddenly create missing business records. For correction and orphan, dispatch by selected kind and preserve existing native services and their fresh/replay checks, even where small duplicated special proof remains.
