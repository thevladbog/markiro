# MKR-INS-03 «Станция сканирования: исключения и восстановление» — дизайн

Дата: 2026-08-22
Статус: утверждён (brainstorming)
Предшественники: MKR-INS-01 (PR #220), MKR-INS-02 (PR #230, merge `1ad3ba11e`) —
конвейер категории `instruction` полностью в main.

## Цель

Третья печатная инструкция оператора: нештатные ситуации на станции
сканирования — экран «Исключения» (перепечатка этикетки, расформирование
короба), сбой печати при закрытии короба, коды, занятые другим терминалом,
и краткий раздел про отказ оборудования. Контентная итерация по накатанному
конвейеру.

## Решения (принятые в brainstorming)

- Расформирование короба описывается как штатный инструмент ОПЕРАТОРА
  (без правила «только по указанию мастера») — решение владельца; при этом
  необратимость подчёркивается честно, теми же словами, что и UI
  («Действие необратимо», «Номер короба будет аннулирован навсегда»,
  «Расформировать безвозвратно»).
- Отказ оборудования посреди смены — КРАТКО: что видит оператор в строке
  состояния и кого звать; переподключение/настройка — скоуп MKR-INS-04.
- Конфликтные коды («Коды, занятые другим терминалом») — в этом документе:
  это не тревога, рабочее правило — «Не сканируйте повторно. Продолжайте
  работу — расхождение проверит менеджер».

## 1. Документ

- Код `MKR-INS-03`, kind `instruction`, ревизия `2026.08/01`, effectiveDate
  `2026-08-22`, статус `active`, RU-only, маршрут
  `/instruktsii/isklyucheniya-i-vosstanovlenie/`.
- Контент — `packages/legal-documents/src/documents/station-exceptions.ts`.
  Цитаты интерфейса — строго из `apps/station/src/i18n/ru.json`
  (секции `box`, `conflicts`, `work`). Структура секций:
  1. Назначение: когда открывать «Исключения»; вход и штатный цикл — см.
     MKR-INS-01/MKR-INS-02.
  2. Экран «Исключения»: кнопка на рабочем экране, выбор действия
     («Перепечатать этикетку» / «Расформировать короб»), возврат кнопкой
     «Вернуться к работе».
  3. Перепечатка этикетки: выбор закрытого короба (сканом этикетки или из
     списка — «Отсканируйте этикетку короба или выберите его из списка»),
     причина из справочника (Этикетка повреждена / Этикетка не читается /
     Замятие принтера / Запрос контроля качества / Другая причина),
     подтверждение, результат; старую этикетку уничтожить — на коробе
     должна остаться одна.
  4. Расформирование короба: причины (Неверный товар / Неверное количество /
     Упаковка повреждена / Отклонено контролем качества / Другая причина),
     двойное подтверждение необратимости; после расформирования единицы
     остаются принятыми и могут укладываться в новый короб; SSCC
     аннулируется навсегда.
  5. Сбой печати при закрытии короба: экран «Этикетка короба не напечатана»
     (варианты причин: принтер/замятие, нет шаблона, не удалось подготовить
     этикетку), действия «Печатать заново» / «Продолжить без этикетки»
     (короб уже закрыт, промаркировать позже); негативные исходы сверки:
     «Это другая этикетка», «Это не групповой код».
  6. Коды, занятые другим терминалом: что это; счётчик «Дубли» в строке
     состояния; список с «Закреплён за … в …»; правило «Не сканируйте
     повторно. Продолжайте работу — расхождение проверит менеджер».
  7. Оборудование посреди смены (кратко): сканер «Нет связи» / принтер не
     печатает — что видно в строке состояния, работу остановить, позвать
     наладчика; настройка — в отдельной инструкции.
  8. Частые вопросы (definition-list) + контакты.

## 2. Скриншоты

- Каталог `packages/legal-documents/assets/instructions/mkr-ins-03/`,
  ориентировочный набор (id файла ← состояние галереи):
  - `exception-action` ← `exception-action` (выбор действия)
  - `exception-target` ← `exception-target` (выбор закрытого короба)
  - `exception-reason` ← `exception-reason` (справочник причин)
  - `exception-confirm` ← `exception-confirm` (подтверждение необратимого
    расформирования)
  - `exception-result` ← `exception-result` (результат действия)
  - `box-print-failed` ← `box-print-transport-failed` (этикетка не напечатана)
  - `print-mismatch` ← `print-mismatch` (сверка: другая этикетка)
  - `conflicts` ← `conflicts-page-1` (список занятых кодов)
- Обязательный предварительный шаг: сверка фикстур `exception-*`,
  `box-print-*`, `print-mismatch`, `conflicts-*` с реальными компонентами
  (`ExceptionFlow.tsx`, `BoxPrintRecovery.tsx`, `PrintVerification.tsx`,
  `ConflictList.tsx`) — при расхождении сначала чинится фикстура
  (прецеденты: MKR-INS-01 логин, MKR-INS-02 work-ok/box-full/offline).
  Итоговый состав может уточниться по фактическому виду фикстур; правило
  «каждый step-image ссылается на существующий файл» держит тест
  синхронизации ассетов.
