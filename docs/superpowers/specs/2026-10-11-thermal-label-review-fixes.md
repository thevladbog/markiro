# Совместимость и офлайн-печать стандартных термоэтикеток

По ревью PR #703 API должен выпускаться до клиентов. Возможность
`thermal-label-branding-v1` согласуется через существующий `x-station-capabilities`.
Без точного токена API выдаёт прежние стандартные макеты либо проекцию V1 без
нового kind, новых форматов и новых параметров типографики. Это касается бандлов
смен, манифестов инвентаризаций, каталога складской перепечатки и bootstrap палет ТСД.
Проекция не меняет хранимые шаблоны, снимки и digest фактов инвентаризации.
Подписанный task scope описывает ту же клиентскую проекцию макета, что и бандл.
Пользователь явно разрешил согласование scope и бандла; владельцы, permissions
и количественные лимиты не меняются.

Миграция 185 не меняет шаблоны, на которые ссылаются planned/active смены
той же организации. Проверка и изменения выполняются одним атомарным DO-блоком с SHARE-блокировкой
shifts. `lock_timeout = 2s` ограничивает ожидание блокировки; при занятости
миграция отказывает, изменения этого блока откатываются. Выпуск нужно повторить
после освобождения таблицы, не обходя защиту. Единый блок также работает после
исторической миграции 158 с собственным COMMIT. Эти шаблоны остаются прежними до явного редактирования
пользователем; автоматического последующего обновления нет. Закрытые смены
по-прежнему могут регенерировать коробочные этикетки из текущего макета.

Логотип декоративный: рендер не делает сетевых запросов. Нет полного валидного
кэша текущего владельца — печатается этикетка с пустой зарезервированной шапкой.
Подтверждённое отсутствие логотипа на сервере по-прежнему означает Маркиро;
ошибка загрузки установленного логотипа не означает замену на Маркиро.
Запечатанные credentials не дают доступ к старому логотипу. A4 сохраняет свой
контракт обязательного полного снимка. Windows delivery_unknown повторяет байты.

ТСД проверяет ревизию и все метаданные изображения перед повторной загрузкой;
неизменённый логотип не скачивается, не декодируется и не записывается повторно.
Название «Палета» и печатный «ПАЛЕТА» согласованы пользователем; 58×40 исключён.

План: сначала регрессионные тесты; затем общая доменная проекция и API-потребители;
защита миграции; пустая шапка в RAW/Windows/Android; кэш ТСД; единое написание;
целевые тесты с БД, браузерная регрессия A4, Android и стандартные статические gates.
