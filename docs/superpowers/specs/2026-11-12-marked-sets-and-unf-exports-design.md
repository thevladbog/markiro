# Сборка маркированных наборов и выгрузки для 1С:УНФ

Черновик от 12 ноября 2026 года.

## Задача

На производстве собирают розничные наборы из маркированной косметики. Нужно
сохранить фактический состав каждого экземпляра и передать его в офис для
подачи в Честный знак или загрузки в 1С:УНФ. Для обычной смены с агрегацией
офису нужен такой же файловый обмен с 1С по коробам и палетам.
Первая версия охватывает офис, станцию и ТСД Markiro Автоном.

## Сборка набора

1. В каталоге создают карточку набора с названием, собственным GTIN из
   Национального каталога, перечнем маркированных товаров и количеством
   каждого GTIN. В первую версию входят маркированные позиции одной
   товарной группы «Косметика, бытовая химия и товары личной гигиены».
2. На станции оператор открывает «Новая смена» и сканирует Data Matrix
   или EAN. По GTIN станция находит карточку в каталоге. Карточка набора
   открывает настройку «Сборка наборов», карточка единицы продукции
   открывает обычную настройку смены. Этот скан выбирает карточку.
   Для ТСД макет показывает настройку после выбора набора.
3. Для текущего экземпляра используется зафиксированный состав карточки.
   Оператор сканирует Data Matrix вложений в любом порядке и видит для
   каждой позиции число принятых единиц и требуемое количество.
4. Станция отклоняет чужой GTIN, превышение количества и повтор марки в
   текущей сборке. Единицу можно взять из ранее выпущенной продукции, если
   её код свободен для сборки. Предлагается принимать и маркированную
   продукцию поставщиков по тем же локальным проверкам. Статус кода в
   ГИС МТ проверяется при подготовке и подаче сведений. Одна марка может
   числиться только в одном действующем наборе. Предлагается разрешить
   убрать ошибочно принятое вложение до закрытия.
5. Последним оператор сканирует Data Matrix на самом наборе. Ранний скан
   показывает недостающие позиции. Полный набор закрывается после проверки
   GTIN и уникальности кода упаковки. Код набора и список кодов вложений
   сохраняются вместе. Затем станция готова собирать следующий экземпляр
   по той же карточке.

Сборка использует заранее полученные этикетки. Предлагается сохранять
незавершённый набор при перезапуске станции и использовать штатную
офлайн-очередь. Если две станции приняли одну марку без связи, итоговую
принадлежность определяет общий реестр. Офис видит конфликт, а спорная
сборка ждёт разрешения перед выгрузкой.

## Выгрузки наборов

Предлагается выгружать закрытые наборы по смене сборки.

- **Реестр для Честного знака.** Предлагаемый формат XLSX для сверки и
  ручного заполнения мастера в ЛК. Для каждого закрытого набора указываются
  его код идентификации и коды идентификации вложений. Отчёт о нанесении
  подаётся отдельно в СУЗ. В этой версии подача в Честный знак остаётся
  действием офиса. Подписанный JSON через True API относится к отдельной
  интеграции. [Инструкция для косметики](https://markirovka.ru/knowledge/tovarnye-gruppy/kosmetika-bytovaya-himiya/formirovanie-naborov-kosmetika-bytovaya-khimiya-i-tovary-lichnoy-gigieny),
  [True API](https://docs.crpt.ru/gismt/True_API/#_формирование_набора).
- **Выгрузка для 1С:УНФ.** Одна строка на вложение. В первой колонке код
  товара, во второй код самого набора. Окончательное представление
  значения в каждой колонке определяет проверка в УНФ.

## CSV для обычной смены

Предлагаем один файл на закрытую смену для каждого выбранного формата.
Выгрузка использует актуальный состав закрытых коробов и палет. Короб без
палеты даёт строки со своими товарами. Расформированные связи не включаются.

| Формат                               | Строки                                        | Штрихкод или код маркировки | Код упаковки                               |
| ------------------------------------ | --------------------------------------------- | --------------------------- | ------------------------------------------ |
| `[1C][csv] Общая выгрузка`           | Товары в коробах и короба на палетах          | КМ товара или SSCC короба   | SSCC короба или SSCC палеты соответственно |
| `[1C][csv] Выгрузка Короба - Коды`   | Одна строка на товар во всех закрытых коробах | КМ товара                   | SSCC короба                                |
| `[1C][csv] Выгрузка Палеты - Короба` | Одна строка на короб в составе палеты         | SSCC короба                 | SSCC палеты                                |

В общей выгрузке короб под палетой и товары внутри этого короба
представлены отдельными строками. Пример со схематическими значениями:

```csv
Штрихкод или код маркировки;Код упаковки
КМ товара 1;SSCC короба А
КМ товара 2;SSCC короба А
SSCC короба А;SSCC палеты Б
КМ товара 3;SSCC отдельного короба В
```

Короб, входящий в палету, представлен одной связью с палетой независимо
от числа товаров. В смене без палет общая выгрузка содержит связи
«товар → короб». Поуровневые форматы предназначены для последовательной
загрузки: сначала содержимое коробов, затем размещение коробов на палетах.

## Контракт загрузки УНФ

Цель проверки — актуальная типовая 1С:УНФ 3.0. На дату проектирования
последний найденный официальный релиз — 3.0.14.187.
[Релиз 1С](https://v8.1c.ru/news/vyshla-novaya-versiya-3-0-14-187-tipovoy-konfiguratsii-upravlenie-nashey-firmoy-redaktsiya-3-0.htm).

На скриншотах заказчика форма «Загрузка кодов маркировки» предлагает
скопировать данные из внешнего файла через буфер обмена. Для загрузки
состава используется форма с колонками «Штрихкод или код маркировки» и
«Код упаковки». Заголовки копируются в спецификацию дословно. Колонки
«Код маркировки» и «Количество» предназначены для указанного в подсказке
сценария ЕГАИС. Во второй форме на скриншоте отсутствует колонка для
родительской упаковки.

Рекомендуемый тестовый путь в УНФ — открыть связанный с «Производством»
документ «Нанесение и ввод в оборот» либо маркировочный документ с операцией
агрегации, перейти в подбор и проверку и вставить таблицу в форму загрузки.
Скриншот подтверждает заголовки и возможность указать непосредственного
родителя. Пригодность каждого режима документа, порядок строк, представление
SSCC и действие флажка «Формат base64» на обе колонки проверяются в целевом
релизе. Текстовые значения должны сохранять ведущие нули и, если выбранная
операция требует полного КМ, разделители GS и криптохвост.
[Методическая поддержка 1С:УНФ](https://its.1c.ru/db/content/metod81/src/appsolutionselffinanced/small%20business/gism/i8108009.htm).

## Приёмка

- Два набора одного GTIN с разными кодами вложений. После вставки у
  каждого набора в «Структуре упаковок» видны именно его марки.
- Палета с двумя коробами и третий короб вне палеты. После вставки
  общего CSV в УНФ видны оба уровня, а третий короб остаётся отдельным.
  Для проверки формирования новых связей берутся упаковки, состав
  которых ещё не зарегистрирован.
- Поуровневые CSV дают те же связи после последовательной загрузки.
  Отдельно проверяется смена только с коробами.
- В УНФ после вставки проверяются точные значения SSCC и марок.
  Повторное скачивание сохранённой выгрузки возвращает тот же файл.

## Открытые решения

- Как офис исправляет уже закрытый набор до передачи состава. В этот
  момент нужно определить, при каких условиях освобождаются марки вложений
  и что происходит с наклеенным кодом набора.
- Если актуальная УНФ принимает только один уровень за раз, выбор между
  двумя штатными загрузками и отдельной обработкой для общего файла
  зависит от результатов прогона и требований пилота.
