## Problem

Slices US-00..US-09 produce a working U.S. workflow, but nothing in the repository can recreate the Scenario A dataset from docs/us/demo-scenario.md on demand, prove which build a screenshot came from, or bundle the generated XLSX, plan PDF, request report, screenshots and test results into a tamper-evident package that an independent reviewer can verify with one command. Today there is no seed script at all, the admin exposes no version, the evidence tooling is locked to the Russian inventory protocol, and there is no backup/restore procedure to drill. US-11 closes those gaps without touching the RU product.

## Key facts of the codebase

- No seed or reset command exists in any `package.json`; "seed" in `apps/api/src` refers only to SSCC counter seeding (`apps/api/src/modules/sscc/sscc.service.ts`) and in `tools/station-release` to release-baseline seeding. The only tenant bootstrap is `TenantProvisioningService.provision()` (`apps/api/src/modules/platform-tenants/tenant-provisioning.service.ts`): one transaction creating `organization`, `pickup_tenant_policies`, stock label templates (`buildDefaultLabelTemplates()`), `org_profiles`, owner `user` + `member`, `tenant_audit_events` (`tenant.owner.provisioned`), activation token and a `tenant_subscriptions` row with `source: "demo"` (a billing concept, not a demo dataset). It is idempotent on slug and creates no products, lines or shifts. CLI wrappers: `apps/api/scripts/provision-tenant-owner.mjs` (argv allow-list, rejects `--password`) → `dist/cli/provision-tenant-owner.js`.
- API test fixtures (`apps/api/test/support/auth.ts`) create tenants through real Better Auth routes with `t-<uuid>@example.com` and a random password; `createTestStationDevice` mints a station api-key; all helpers throw unless `NODE_ENV === "test"`.
- `tools/evidence-package/`: `init.mjs`, `seal.mjs`, `verify.mjs`, `station-date.mjs`, `cli.mjs`, `evidence-package.mjs`, `secure-filesystem.mjs`, tests under `test/`. Root scripts `evidence:init <root> <operation-id>`, `evidence:seal <root>`, `evidence:verify <root>`, `evidence:station-date <db> <shift-id> <out>` (positional only, exact arity). Operation id is locked to `/^INV-\d{8}-[a-z0-9-]{2,40}-\d{2}$/` in both `init.mjs` and `evidence-package.mjs` (lines 165, 187), `protocolVersion` is `inventory-recovery-v1`, scaffold is `baseline/ amendments/ photos/ exports/ metrics/ attestation/`, manifest `device: { id, stationVersion, apiVersion }` and `timezone: "Europe/Moscow"`. Sealing writes `SHA256SUMS` (coreutils format, includes `manifest.json`), sorts artifacts by code point, aborts if files change mid-seal; `verify` re-hashes everything and rejects `*.tmp`. Packages live under gitignored `/evidence/`. Exports: `sealEvidencePackage(root)`, `verifyEvidencePackage(root)`.
- Release tooling: `tools/station-release` (`version.mjs` tags `station-vX.Y.Z[-beta.N]`, `artifacts.mjs` asset names + `SHA256SUMS` + `release-evidence.json` with `baseSha`/`releaseSha` validated by `/^[0-9a-f]{40}$/`, `SECRET_TEXT` scrub regex, dual origin GitHub/Yandex), `tools/signer-release` (`signer-vX.Y.Z`, `SIGNER_CHANNEL_BASE_URL`). No workflow runs `evidence:*`.

## Design

### Data model

- `traceability_demo_seeds` (owned by US-11, `packages/db/src/schema/traceability.ts`): `tenant_id text PK → organization.id`, `seed_version text` (`us-demo-2026.09/01`), `dataset_sha256 char(64)` (hash of the canonical fixture JSON), `scenario text` (`A` | `B`), `seeded_at timestamptz`, `reset_count integer default 0`, `last_reset_at timestamptz NULL`, `seeded_by text` (`cli` | `ci`). Presence of this row is what turns on evidence mode for a tenant and what authorizes `reset`; production tenants never get one. Additive migration; RU schema untouched.
- No other tables. Everything else is fixtures on disk and rows created through the US-01..US-09 services.

### Domain rules

`packages/domain/src/traceability/demo-fixture.ts` (pure):

- `parseDemoFixture(json)` validates `tools/us-demo/fixtures/scenario-a.json` against a Zod schema mirroring docs/us/demo-scenario.md §5.1–5.3: three parties/locations (Orchard Slice Supply LLC, North River Fresh Foods LLC, Harbor Market Distribution Center; `555` phones; `example.com` emails), products (inbound slices 10 lb bag; output snack cups 6 oz × 24/case), lots `OSS-260914-A1`, `OSS-260914-A2`, `NRF-260915-APL01`, quantities (2 × 50 bags = 1,000 lb in; 100 cases = 900 lb out; 100 lb operational loss flagged `demoContextOnly: true` and never mapped to a KDE), reference documents (`ASN-2026-0914-001`, `BOL-0914-A`, `WO-2026-0915-APPLECUP`, `BATCH-2026-0915-01`, `BOL-0916-H`, `INV-2026-0916-047`, `REQ-2026-APPLE-001`), event dates 09/14–09/17/2026, tenant timezone `America/Los_Angeles`.
- `demoFixtureDigest(fixture)` → canonical JSON (sorted keys) SHA-256; `expectedDemoNumbers` returns the §5.5 table so `verify` can compare (2 input lots, 1 output lot, 1/1/1 events, 100 cases, 2 lots / 1 source backward, 1 recipient forward, 0 missing KDEs).
- `scanFixtureForSensitiveData(text)` → findings for: phone numbers whose exchange is not `555`, e-mail domains other than `example.com`/`example.org`, U.S. SSN/EIN shapes, GLN/FFRN-looking 13/11-digit numbers not on an allow-list, private keys/tokens (`SECRET_TEXT` from `tools/station-release/artifacts.mjs` reused verbatim), Cyrillic in an English fixture, and the prohibited wording matrix via `findProhibitedClaims` from `packages/domain/src/traceability/claims.ts` (US-00). Exact, deterministic, no network.

### Contracts and API

- Seed and reset run inside the API process, not as raw SQL, so every event passes the same validators, snapshots and audit as a human user (data-dictionary §4). New CLI `apps/api/src/cli/us-demo.ts` with wrapper `apps/api/scripts/us-demo.mjs` (same argv allow-list style as `provision-tenant-owner.mjs`), exposed as root scripts `us-demo:seed`, `us-demo:reset`, `us-demo:verify`, `us-demo:scan`, `us-demo:evidence`. Fixtures, scanner rules, manifest schemas and package scaffolding live in `tools/us-demo/` (`fixtures/scenario-a.json`, `fixtures/scenario-b.json`, `fixtures/documents/*.pdf` generated by a small `@react-pdf/renderer` script committed with its source, `screenshots.plan.json`, `evidence.mjs`, `scan.mjs`, `test/`).
- `us-demo seed --scenario A [--slug us-demo-apple] [--reset]`: provisions the tenant via `TenantProvisioningService.provision()` (owner `owner@example.com`, slug allow-listed `^us-demo-[a-z0-9-]+$`), sets the regulatory profile to `US_FSMA204_PROCESSOR` with baseline `US-REG-2026-09-03` (US-00 service), then calls US-01..US-09 services in order: parties/locations → product traceability profiles (FTL `Fruits (fresh-cut)`, coverage `covered`, reviewed rationale) → lots → receiving (finalized) → transformation (finalized, genealogy) (100-case quantity plus 100 synthetic server-side boxes/SSCC links; no Station operation) → shipping (finalized) → plan version approved → trace request `REQ-2026-APPLE-001` with `due_at = received_at + 24 elapsed hours` and one export run. The export run is asynchronous (US-09: `queued → processing → ready` through the pg-boss worker), so the CLI application context imports `JobsModule` (the worker runs in-process, no separate worker in CI) and `seed` waits until the run reaches `ready`, polling its status every 500 ms with a bounded timeout (`--export-timeout`, default 90 s); on timeout or `failed` the seed exits 4 and prints the run id. `us-demo verify` therefore assumes a `ready` run and never polls, which keeps `pnpm us-demo:seed && pnpm us-demo:verify` a plain sequence. Create an explicit in-progress seed marker at provisioning and mark it complete only after the export is ready. Retry resumes the same fixture IDs and cannot duplicate a partially completed chain. Second run with the same `seed_version` and `dataset_sha256`: no-op with exit 0 and `already seeded`; with `--reset`: controlled reset first. Different `seed_version` without `--reset`: exit 2 with instructions. Target under 2 minutes (acceptance §1).
- `us-demo reset --slug us-demo-apple`: refuses unless `traceability_demo_seeds` exists for that tenant and `US_DEMO_RESET_ALLOWED=1`; deletes tenant-scoped rows in reverse dependency order through a single service (`DemoTenantResetService`) that enumerates the tenant tables from the schema registry used by `packages/db/test/tenant-isolation.test.ts`, keeps `organization`, owner `user`/`member` and `traceability_demo_seeds` (increments `reset_count`), and writes `tenant_audit_events` `traceability.demo.reset` (outcome `success`). Never callable for a tenant without the seed row (RU tenants are structurally excluded).
- `us-demo verify`: reads the tenant through the public API services and asserts the §5.5 numbers, `regulatory baseline` presence, zero missing KDEs, package generation under 60 s (timed run recorded for C-014/NFR-013), prohibited wording absent from every U.S. string; prints a JSON report used as `tests/us-demo-verify.json` in the package.
- `us-demo scan [paths...]`: runs `scanFixtureForSensitiveData` over `tools/us-demo/fixtures/**`, `docs/us/**`, the seeded tenant's string columns (dump via services) and `docs/us/evidence/**`; non-zero exit on any finding (NFR-006, DOC-005, C-019).
- Build identity (evidence mode): `GET /health/build` (new route, unauthenticated like `/health`, own OpenAPI schema so the frozen `health.openapi.ts` objects stay unchanged) → `{ app: "markiro-api", version, commit, builtAt, regulatoryBaseline }` from env `MARKIRO_BUILD_VERSION`, `MARKIRO_BUILD_COMMIT`, `MARKIRO_BUILD_AT` injected as build args in `deploy/production/api.Dockerfile`; dev returns `commit: "uncommitted"`. The controller is added to `apps/api/test/authorization-metadata.test.ts` with the same exemption as `health.controller.ts` (a controller without a policy is otherwise denied). Admin gets `define: { __MARKIRO_BUILD__ }` in `apps/admin/vite.config.ts` from the same env at build time (edge.Dockerfile build args). Both values are compared by the screenshot suite and written to the manifest.
- Evidence mode in the admin: when the active tenant has a `traceability_demo_seeds` row (exposed as `demoSeed: { seedVersion } | null` on the existing tenant profile read from US-00), a persistent top ribbon reads `Synthetic demo · <seedVersion> · build <commit7> · baseline US-REG-2026-09-03 · <date in tenant tz>` and every page footer shows the route path. Additional provenance is toggled by `?evidence=1`; the synthetic label is always present (preference persisted in `localStorage["markiro.evidenceMode"]`); never rendered for tenants without the seed row. i18n keys `evidence.ribbon.*` en/es.
- Audit: `traceability.demo.seeded` and `traceability.demo.reset` in `tenant_audit_events` with `actor_user_id` = owner, `after = { seedVersion, datasetSha256, scenario, counts }`, outcome `success` (the value the US-00 spec uses), `target_type = "tenant"`.

### Admin UI

- Ribbon and footer route label as above; `Settings → Regulatory profile` shows the seed version and a `Synthetic data` badge. No other UI. Accessibility: ribbon is `role="status"`, text-only, high contrast, not colour-coded (NFR-012).

### Station

- Not touched by code. If US-10 ships, its gallery states are captured by the existing station gallery suite in `en` locale and included in the screenshot set; otherwise the station rows of the report are recorded as not performed.

The screenshot suite runs manually before the tag (needs the compose stack), not on every PR.

Restore drill (NFR-007): restore a captured synthetic backup into a separate disposable database and object prefix after verifying target identity. Never reset or restore over the running instance. Compare pinned request artifacts and document recovery steps and results. Station SQLite is P1 and not part of this P0 drill.

### Profile gating and RU_CHZ safety

- Every command refuses tenants whose regulatory profile is `RU_CHZ` or whose slug is outside `^us-demo-`; `reset` additionally requires the seed row. No RU table, migration, template or string changes. `/health/build` is additive and unauthenticated exactly like `/health`; the ribbon component mounts only when `demoSeed` is non-null. RU regression proof: full repository gates unchanged plus a test that provisioning a RU tenant leaves `traceability_demo_seeds` empty and `us-demo reset` exits 3 for it.

## Testing

- Unit: fixture schema, digest determinism, expected numbers, sensitive-data scanner (positive and negative corpora incl. a real-looking `+1 503-555-0120` accepted and `+1 503-201-0120` rejected), register linter, report linter, version tag parser, manifest builder (exact key sets like `release-manifest.mjs`).
- DB/API: fresh + upgrade migration for `traceability_demo_seeds`; `us-demo.e2e.test.ts` (seed twice and retry after interrupted seeding → identical `dataset_sha256` and row counts, `--reset` → same counts and incremented `reset_count`, RU tenant refused, cross-tenant slug refused, audit rows exact, wall-clock under 120 s asserted with a generous CI margin, package generation under 60 s recorded), `/health/build` openapi coverage.
- Browser: `us-demo.visual.spec.ts` produces 12–18 frames from a clean seed; assertions on ribbon commit, zero console errors, `sensitiveLeaks` empty, prohibited wording absent.
- Evidence tooling: `tools/evidence-package/test` extended for the `US-` operation id; `tools/us-demo/test/evidence.test.mjs` init → seal → verify round trip on a temp package.
- Negative cases from docs/us/acceptance.md §2.4: duplicate import retry (seed twice), cross-tenant id (reset with another tenant's slug), prohibited phrase in a fixture (scanner fails), EPCIS absent (verify passes without any EPCIS artifact).

## Out of scope

- Real customer data, production hosting, U.S. billing; any automated FDA submission.
- Changing the inventory evidence protocol beyond widening the operation-id regex.
- Video recording itself, demo assets and feedback records (US-12).
- Making the screenshot suite a PR gate (manual pre-tag run only).

Verify 100 distinct active links and SSCC lookup. These rows are synthetic, not proof of physical production; do not fabricate scan/print confirmation. Public screenshots and synthetic artifacts use the U.S. deployment/storage inventory.
