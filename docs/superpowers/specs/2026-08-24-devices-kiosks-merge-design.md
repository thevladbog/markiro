# Объединение разделов «Устройства» и «Киоски» — дизайн-спека

> Дата: 2026-08-24. Продолжение переименования «Для себя» → «Выбытие»
> (`2026-08-24-vybytie-rename-design.md`). Ветка `claude/kiosk-naming-892cd0`.

## Проблема

Киоск живёт в двух разделах сайдбара: «Устройства» (`/devices`) — общий реестр
станций и киосков со спариванием, отзывом и создание обоих типов через дровер —
и «Киоски» (`/kiosks`) — киоск-специфичные настройки (профиль, продукция,
лимиты, показ цен), архивация, вкладка «Причины» и вторая панель спаривания.
Дублируются список киосков и спаривание; «Причины выбытия» — настройка модуля
«Выбытие», а не железа.

## Решение (вариант A)

Один реестр железа — «Устройства»; процессные вещи — в «Выбытии». Пункт
«Киоски» из сайдбара удаляется.

### 1. Панели киоска переезжают под `/devices`

- Роуты `kiosks/new`, `kiosks/:kioskId/edit`, `kiosks/:kioskId/pair` становятся
  дочерними роутами `devices`: `/devices/kiosks/new`,
  `/devices/kiosks/:kioskId/edit`, `/devices/kiosks/:kioskId/pair`.
- Хостом панелей (Outlet + panel-контекст, ныне в `KiosksPage`) становится
  `DevicesPage`. Компоненты панелей (`KioskPanelRoute`, `KioskPairingPanelRoute`,
  `KioskProductsSection`, `KioskProfileForm`) переиспользуются как есть, меняются
  только целевые пути навигации.
- Ссылка «Настройки киоска» в `DeviceActions` ведёт на
  `/devices/kiosks/:id/edit` (панель открывается на месте).
- Кнопка «Добавить киоск» не нужна: дровер устройств уже создаёт киоски.
  `KioskCreatePanelRoute` остаётся достижимым по `/devices/kiosks/new` для
  сценария «создать с полными настройками» — на него ведёт ссылка из дровера
  устройств при выборе типа «Киоск» (если такой ссылки нет — добавить хинт).
- Архивация киоска переезжает из списка киосков в действия панели
  редактирования киоска.
- Отдельный список `/kiosks` (KiosksPage-таблица с операционными фильтрами)
  удаляется. Фильтрация по киоскам — существующий фильтр «Тип: Киоск» в таблице
  устройств.

### 2. «Причины» переезжают в «Выбытие»

- `/kiosks/reasons` → `/pickup/reasons` (ReasonsPage переносится в
  `pages/pickup/`).
- Раздел «Выбытие» получает вкладочную навигацию (новый `PickupLayout` по
  образцу `KiosksLayout`): **Заявки | Отклонённые сканы | Причины**
  (`/pickup`, `/pickup/rejections`, `/pickup/reasons`). Существующий баннер
  отклонённых сканов сохраняется.
- Роут заявки `/pickup/:id` регистрируется до `/pickup/reasons`-конфликтов не
  имеет (статические сегменты `rejections`/`reasons` объявляются раньше
  динамического `:id`).

### 3. Редиректы со старых адресов

- `/kiosks` → `/devices?type=kiosk`
- `/kiosks/reasons` → `/pickup/reasons`
- `/kiosks/new` → `/devices/kiosks/new`
- `/kiosks/:kioskId/edit` → `/devices/kiosks/:kioskId/edit`
- `/kiosks/:kioskId/pair` → `/devices/kiosks/:kioskId/pair`

### 4. Capability-гейты (без изменений семантики)

- Просмотр устройств: `OPERATIONS_READ`.
- Настройки/создание/архив киоска: `OPERATIONS_WRITE`.
- Спаривание: `CREDENTIALS_MANAGE`.
- Причины: как сейчас у ReasonsPage (`OPERATIONS_READ` на чтение).

### 5. i18n

- Удаляется `nav.kiosks`; блок `pages.kiosks.*` сохраняется для панелей,
  строки чисто спискового UI (`emptyTitle`/`emptyHint` списка киосков,
  фильтры состояния) удаляются вместе со списком.
- Вкладки «Выбытия» получают ключи (`pages.pickup.tabs.*`); заголовок вкладки
  «Причины» переиспользует существующие строки ReasonsPage.

### Не меняем

Админ-API `/kiosks/*` и серверные модули, БД, kiosk-приложение, спаривание,
`pickup`-ключи роутов. Изменение чисто фронтовое (apps/admin) + i18n + тесты.
