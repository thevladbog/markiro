## Что подтверждено кодом

`WarehouseLookupService` возвращает сохранённую дату смены, но всегда ставит `expiry` в `unavailableFields`. `renderWarehouseLabel` правильно блокирует шаблон, использующий недоступное поле: так возникает показанная ошибка. У принятого локального задания дубликата есть сохранённые `fields`; серверная история дубликатов содержит события и дайджесты, а не эти поля. Поэтому исправление не сводится к удалению проверки или вычислению срока из сегодняшнего каталога.

Новые стандартные А4 уже содержат подчёркивание и футер. Старые шаблоны из миграции `0183_chunky_valkyrie.sql` их не содержат; изменение builder не обновляет сохранённые шаблоны. Смена также фиксирует собственный снимок шаблона. Для новых листов нужен выбор новой версии макета, а для исторического повторения сохраняется исходный снимок.

`OrgProfilePage` и `PalletSheetDefaultsForm` сохраняются отдельно. При этом существующий PUT профиля уже поддерживает обе группы настроек и выполняет запись транзакционно. Новый endpoint для общей кнопки не нужен.

Текущая перепечатка V1 поддерживает единицы и короба и явно отклоняет палету. А4 уже имеет журнал доставки, снимок фактов/макета/брендинга и правила восстановления. Их нужно использовать повторно.

## Общие правила

- Node 24+, Corepack и объявленная репозиторием версия pnpm; без новых зависимостей по умолчанию.
- Существующие задания, снимки, события и байты не переписывать.
- Исторические даты брать из достоверного сохранённого источника; текущий `shelfLifeDays` не является историческим источником.
- Гражданские даты хранить как `YYYY-MM-DD`; срок годности считать через `shelfLifeExpiryDate`, включая производственный день.
- RAW ZPL/TSPL и драйвер Windows сохраняются. А4 печатается через драйвер Windows; термоэтикетки используют существующую маршрутизацию.
- Отправке предшествует долговечная запись. Неизвестная доставка не повторяется автоматически; смена оператора/владельца не даёт отправить подготовленное задание.
- Все новые запросы и записи ограничены tenant/device/operator. Не помещать сырой КМ, токены или байты изображения в аудит.
- Безопасная совместимость: существующие строгие V1-контракты не расширять неподдерживаемыми вариантами без согласования версии. Новые операции Station включать по явной capability.
- Станция работает без сети с сохранёнными источниками и локальными ресурсами. Отсутствие источника не маскировать под успешную перепечатку.

## 1. Исторические поля продукции

Ввести версионированный снимок фактов этикетки единицы, связанный с tenant, сменой, принятым кодом и его occurrence/временем принятия. Он хранит печатное имя, GTIN, ЕГАИС, эффективную дату производства, срок годности и происхождение дат. Сырой КМ остаётся в существующем защищённом источнике; ключом поиска служит его hash. Повторное принятие одного кода в другой смене не должно подменять старый источник.

Для новых принятий сохранить факты локально до публикации принятия, в той же атомарной операции, затем отправить через retry-safe outbox в отдельный версионированный канал. Это работает и в агрегации без исходного задания печати. Если событие приходит раньше серверного scan, сервер не создаёт фиктивную связь: запись остаётся ожидающей/повторяемой до валидации фактического принятия.

Для старых кодов сначала искать сохранённые локальные поля принятого задания. Их можно дозагрузить по новому каналу после проверки связи с принятием и provenance. Другие сохранённые контексты допустимы только при доказанной связи с конкретным принятием и неизменности. Если такого доказательства нет, оставить неизвестное поле неизвестным. Сообщение должно назвать отсутствующее поле и дать выбрать совместимый шаблон; не обещать восстановление всех старых сроков.

Lookup возвращает `expiry` доступным только после получения достоверных фактов. Локальная и серверная перепечатка используют одинаковые поля. Ранее подготовленная перепечатка продолжает использовать свой снимок и байты.

## 2. Три листа А4

Шапка: слева логотип и организация с отдельным отступом, справа крупная «ПАЛЕТА». Начальные значения для визуальной проверки: отступ 5 мм, заголовок 18 pt для полного А4; для каждой А5 — 3 мм и 12 pt. При длинном названии переносится название, а заголовок остаётся в правой области. Прямоугольный логотип сохраняет пропорции и ограничение по высоте; широкие варианты проверяются существующим механизмом компоновки.

Под названием продукции — существующая линия. Внизу — «ИНН …» слева, «Сформировано в Маркиро» справа; отсутствующий ИНН скрывается, платформа остаётся. У двух А5 свой футер у каждой копии. Геометрию GS1, quiet zones, штрихкоды и безопасные поля принтера не менять ради шапки.

Для действующей организации добавить явное создание актуальных стандартных макетов из библиотеки: новые записи с новыми ID, без перезаписи пользовательских и старых стандартных записей. Пользователь видит новый макет и назначает его в общих настройках. Новые смены получают новый снимок. Уже открытая смена и историческая перепечатка сохраняют прежний макет; это объяснить в интерфейсе. Существующие действия создания пресетов переиспользовать, без дополнительного batch endpoint.

Редактирование и JSON import/export сохраняются; отступы, заголовок и футер доступны через существующие узлы модели. Смена логотипа или ИНН не меняет сохранённый брендинг задания.

## 3. Общие настройки админки

В существующей форме профиля объединить настройки продукции, коробов и палет. В «Шаблоны палеты» показать термоэтикетку и лист А4 для организации и тех же категорий каталога. Использовать существующие Select и таблицу категорий; не добавлять отдельный навигационный раздел.

Выборы управляются общей формой. Одна «Сохранить» отправляет один PUT со всеми изменёнными настройками. `undefined` сохраняет серверное значение, `null` очищает организационный default, пустой массив очищает category overrides. Ошибка сохраняет весь черновик, успех обновляет форму из ответа. Фоновый refetch не затирает несохранённые изменения. Недоступный ранее выбранный шаблон показывается явно и не очищается молча.

Основные строки категорий — категории каталога. Если сохранённое назначение ссылается на исчезнувшую категорию, показать его как требующее исправления и разрешить явное удаление; не превращать полный справочник категорий в сотни пустых строк.

Переименовать пользовательские строки админки и печатных заголовков во всех падежах. API, enum, маршруты, JSON keys и имена SQL остаются совместимыми. Библиотека шаблонов и её редактор остаются едиными.

## 4. Перепечатка производственной палеты

По умолчанию остаётся режим кодов/коробов. В режиме «Палета» скан только ищет источник. SSCC ищет палету напрямую либо её короб; КМ ищет фактическое принятое вхождение → активный короб → активную производственную палету. Открытые, пустые и разобранные палеты не печатаются. Неоднозначность требует явного выбора/уточнения, а не произвольной первой строки. Код, уже перепакованный в другую палету, ведёт к текущему активному составу с видимым SSCC.

На подтверждении показать SSCC, продукцию, даты, количество коробов/единиц, выбранный макет и принтер. Отмена не создаёт печатную попытку. Скан палеты в обычном режиме не отправляет А4.

Сохранить долговечный источник палетной этикетки при закрытии: факты, версии макета и renderer, замороженный брендинг с проверяемыми ресурсами, digest. Клиент формирует изображение, API хранит/проверяет метаданные и ресурсы, не рендерит. Серверное хранение позволяет повторить на другой станции после синхронизации. Источник и membership синхронизируются идемпотентно, несовпадающий повтор не перезаписывает принятый снимок. Изображение, очищенное после печати, восстанавливается по снимку с проверкой digest, а не по текущему каталогу.

Для старых палет использовать достоверные сохранённые снимки. При их отсутствии показать точную причину недоступности; не выдавать новый текущий макет за исторический. Новый тираж с другим макетом — отдельная будущая операция и не входит в этот этап.

Добавить отдельные capability-gated операции lookup/source-sync/events для Station, сохранив V1 кодов/коробов и поведение ТСД. Не расширять строгую V1 union палетным видом. А4 использует существующий `printer_deliveries` и Windows delivery flow; RAW — существующий журнал и маршрутизацию. Перепечатка создаёт самостоятельную попытку с ссылкой на источник; она не разрешает задним числом неопределённую исходную производственную попытку. Для неизвестной доставки применяются существующие ограничения точного повтора; новая геометрия допустима только после доказанного отказа до отправки соответствующей попытки.

Offline разрешает работу по локально сохранённому закрытому источнику и известному составу в рамках текущих grant/ownership правил. Нет источника — требуется сеть. Отрицательный серверный ответ о разборке не обходится старым cache. Без сети удалённые изменения состава нельзя гарантированно обнаружить; интерфейс обозначает локальный источник, аудит сохраняет его revision.

Каждый этап — самостоятельный PR и проверки. Сначала исправление исторических полей, затем А4, общая форма и палетная перепечатка. Этапы 2 и 3 можно проверять независимо; этап 4 использует правила источников этапа 1.

Автоматические проверки отдельно от браузера, Windows и физической печати. Физическая приёмка: закрытая смена с датой → скан продукции; три А4 с прямоугольным логотипом и футером; сохранение всех defaults одной кнопкой; три способа поиска палеты, подтверждение, отказ драйвера, перезапуск и работа без сети. Сканер проверяет GS1 SSCC на каждом физическом листе.
