# SSCC коробов в 20-знаковом формате с «00»

**Дата:** 2026-08-19
**Статус:** утверждено
**База для работы:** ветвиться от `origin/main` (модуль выгрузок смен `apps/api/src/modules/shift-exports` и `packages/domain/src/shift-exports.ts` существуют только там).

## Задача

По требованиям Честного знака коды коробов (SSCC) должны выгружаться и предъявляться в 20-знаковом формате с идентификатором применения GS1 `00` впереди. Сейчас во всех точках вывода (выгрузки смен, API `/boxes`, админка, текст на этикетке) код уходит голыми 18 цифрами. Сканирование 20-знакового варианта уже поддержано.

## Инвариант хранения (не меняется)

В БД (`boxes.sscc char(18)`, `boxes_mirror.sscc`), в обмене станция↔сервер (`station-scans` DTO `.length(18)`), в счётчиках и пулах SSCC хранятся **голые 18 цифр** — канонический SSCC. Префикс `00` — это представление, добавляемое только на точках вывода. Штрихкод на этикетке уже содержит FNC1 + `00` (эмиттеры ZPL/TSPL) — не трогаем.

## Решение

### 1. Доменные форматтеры — единственный источник правила

В `packages/domain/src/gs1/sscc.ts` (экспорт через индекс пакета):

- `formatSsccWithAi(sscc: string): string` → `"00" + sscc` — 20 цифр подряд, машинный формат (выгрузки, API). Вход — строго голые 18 цифр.
- `formatSsccHri(value: string): string` → `"(00)" + 18 цифр` — человекочитаемый GS1 HRI (этикетка, админка). Принимает и голые 18 цифр, и 20-значный машинный формат с `00` (то, что теперь отдаёт API `/boxes`), — display-коду не нужно знать, что у него в руках.

Обе валидируют **форму** (`/^\d{18}$/` после нормализации) и бросают `DomainError("SSCC_FORMAT")` на невалидном значении — чтобы `00` нельзя было навесить дважды или на мусор. Контрольная цифра сознательно НЕ проверяется: ингест со станции гарантирует только длину 18 (`z.string().length(18)`), и одна строка с битой контрольной цифрой не должна ронять целую выгрузку смены или страницу коробов. В рендере текста этикеток используется толерантная обёртка `labelFieldDisplayValue(field, data)` — не-SSCC значение (пустое, произвольный литерал) рендерится как есть, генерация этикетки не падает.

### 2. Выгрузки смен — версия 2 для форматов «с коробами»

- `shift_txt_boxes` и `shift_csv_boxes` получают `version: 2`: SSCC пишется через `formatSsccWithAi` (20 цифр) — в строке-заголовке блока короба в TXT и в колонке `box_sscc` в CSV.
- Форматы `shift_txt_flat` / `shift_csv_flat` остаются v1 без изменений.
- Список форматов для UI (`formats()` / `SHIFT_EXPORT_FORMATS` наружу) отдаёт только актуальные версии — v1 «с коробами» больше не предлагается для создания.
- `getShiftExportFormat` продолжает резолвить v1 «с коробами» с замороженным поведением (18 цифр): ретраи старых заданий и повторные скачивания существующих артефактов не ломаются.
- Идемпотентность создания привязана к `formatId + formatVersion`, поэтому для смен со старыми v1-выгрузками можно создать новую v2-выгрузку без конфликта.
- DTO/OpenAPI: `formatVersion` перестаёт быть литералом `1`; валидация версии делегируется `getShiftExportFormat` (создавать можно только версии из актуального списка).

### 3. API `/boxes` и админка

- `BoxDto.sscc` отдаёт 20 знаков (`formatSsccWithAi`); `null` остаётся `null`.
- Таблица коробов в админке показывает HRI-вид `(00)3460…` (форматирование на клиенте из полученного значения).

### 4. Этикетка — человекочитаемый текст (HRI)

- В эмиттерах ZPL/TSPL текстовые элементы с полем `sscc` рендерятся через `formatSsccHri` → `(00)…`. Штрихкод-элементы уже корректны.
- Превью в редакторе этикеток (sample-значение в `labels/model.ts`) показывает тот же HRI-вид.

### 5. Сканирование — без изменений поведения

`parseScannedSscc` / `classifyScan` уже принимают 20 знаков с `00` (и `]C1`) и «раздевают» до 18. Закрепляем тестами, включая сверку напечатанной этикетки (`PrintVerification`) — сканер вернёт `00…`, сверка идёт по каноническим 18.

## Тесты

- Юниты `formatSsccWithAi` / `formatSsccHri`: валидный вход, отказ на 17/19/20-значном входе, отказ на битой контрольной цифре.
- Рендер выгрузок v2 (TXT и CSV): 20-значный SSCC в заголовке/колонке; v1 продолжает рендерить 18 (заморожено).
- e2e `/boxes`: `sscc` в ответе — 20 знаков с `00`.
- Эмиттеры этикеток: текстовый элемент `sscc` → `(00)…`; штрихкод не изменился (существующие фикстуры).
- Админка: колонка SSCC в таблице коробов показывает `(00)…`.
- Сканирование: 20-значный скан классифицируется как SSCC и совпадает с коробом (существующие + при необходимости новые кейсы).

## Вне скоупа

- Миграция хранения на 20 знаков — отклонена.
- Экспорт агрегации в ГИС МТ (план 07) — не существует; при реализации обязан использовать `formatSsccWithAi`.
- Паллеты (06d, extension digit 1) — форматтеры к ним применимы без изменений.
