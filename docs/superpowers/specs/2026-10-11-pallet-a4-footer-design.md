# Единый стиль палетных листов А4

Статус: дизайн согласован пользователем 2026-10-11; реализация не начата.

## Требование

Обновить только три макета А4: вертикальный, горизонтальный и две одинаковые А5
на листе А4. Под названием продукции — тонкая линия. Под SSCC — разделитель
и футер: слева ИНН организации, справа «Сформировано в Маркиро».
При отсутствии ИНН левую подпись скрывать. Термоэтикетки не менять.
На ручном ярлыке админки исправить «ПАЛЛЕТА» на «ПАЛЕТА».

## Модель и отображение

- Добавить необязательное подчёркивание в модель поля продукции и необязательный
  блок подписи в существующий SSCC footer. Отсутствие этих настроек сохраняет
  прежний макет. Линия проходит под фактически отрисованным названием; запас
  строк для длинных названий сохраняется.
- ИНН брать из `org_profiles.inn`, а не из продукции, контрагента или SSCC.
  Передавать его в приватных данных branding только для поддерживающего клиента.
  Старый ответ `/station/branding` сохраняется без дополнительных ключей.
- Использовать общий domain renderer для предпросмотра, тестовой и рабочей печати.
  Футер редактируется в админке и сохраняется в JSON при импорте и экспорте.
- В варианте двух А5 обе копии получают одинаковый футер. Подписи не пересекают
  линию разреза, SSCC и тихие зоны. Требования GS1 к штрихкоду сохраняются.

## Совместимость и сохранённые данные

- Отдельная capability обозначает поддержку нового footer. Старые Station
  продолжают работать со старыми макетами; новый неподдерживаемый макет нельзя
  начать печатать до обновления Station. Отказ должен быть понятным до отправки.
- Встроенные пресеты обновляются. Сохранённые пользовательские шаблоны и уже
  выбранные шаблоны не переписываются автоматически: футер включается через
  редактор с сохранением новой ревизии либо выбором обновлённого пресета.
- ИНН фиксируется вместе с branding в новом задании. Старые branding snapshots
  без ИНН продолжают читаться без изменения digest. Неизвестные и подготовленные
  попытки повторяют исходные байты, даже после изменения профиля организации.
- Для старых данных нельзя добавлять футер при восстановлении незавершённой
  попытки. Новая отрисовка после доказанного отказа или закрытой попытки проходит
  существующие правила явного повтора и сохраняет историю.

## Проверки и выпуск

Проверить schema/JSON round-trip, legacy snapshots, отсутствие/наличие ИНН,
межтенантное отрицание, старую и новую capability, все три макета, длинные
названия и реальные поля драйвера. Проверить digest и точные байты при повторе.

Провести browser проверки общей отрисовки и production CSP, затем gates
затронутых пакетов. Физическая проверка: А4, две разрезанные А5 и сканирование
SSCC. Выпуск: совместимый API/админка, затем новый beta Station; защищённые
окружения и точный SHA сохраняются.
