# Печатная ведомость отбора: постраничный A4-документ

## Цель

Заменить текущую длинную HTML-страницу ведомости отбора на детерминированный
печатный A4-документ. Каждая страница должна иметь собственную шапку и подвал,
корректную нумерацию `стр. N из M` и не должна разрывать строку товара,
DataMatrix или блок подписей.

## Выбранный подход

API продолжает возвращать статический HTML, который можно открыть и напечатать
из браузера. До рендера шаблон разбивает позиции на страницы. Каждая страница —
отдельная секция фиксированного размера A4 с фиксированной высотой строки товара.
Это позволяет вычислить общее число страниц на сервере и напечатать настоящую
нумерацию без зависимости от неподдерживаемых Chromium счётчиков `@page`.

Переиспользовать JavaScript-компонент `doc-page` из дизайн-хэнд-оффа не нужно:
это прототипный вспомогательный компонент, а ведомость формируется API и должна
оставаться статичной, работать без клиентского JavaScript и внешних ресурсов.
Используется тот же принцип явной пагинации: одна секция соответствует одному
листу и владеет своей шапкой, содержимым и подвалом.

## Разбиение на страницы

- Строка товара имеет ограниченную высоту и вмещает до двух строк названия.
- На промежуточных страницах размещается фиксированное число товарных строк.
- На последней странице резервируется место для итога, способа вывода из
  оборота, информационного примечания о цене и подписей.
- Если остаток позиций вместе с завершающими блоками не помещается, позиции
  заканчиваются на предыдущей странице, а завершающие блоки переходят на новую.
- Пустая или отменённая заявка всё равно создаёт одну страницу с пустой таблицей
  и нулевым итогом.
- Номер каждой страницы и общее число страниц вычисляются из сформированного
  массива страниц и выводятся как `стр. N из M`.

## Содержимое страницы

На каждой странице повторяются:

- логотип организации, если `organization.logo` заполнен, иначе встроенный
  логотип Маркиро;
- заголовок `Ведомость отбора по заявке`, номер заявки отдельной второй строкой;
- компактные реквизиты заявки;
- заголовок таблицы;
- подвал со штрихкодом заявки без текстовой подписи под штрихкодом;
- служебная строка и корректная нумерация страницы.

На первой странице выводятся полные блоки организации, сотрудника и заявки. На
последней странице после таблицы выводятся итог, способ вывода из оборота,
примечание `Цена является информационной. Окончательная цена будет указана в
чеке.` и подписи. ФИО получателя располагается под линией подписи.

Значения цены печатаются без символа рубля; валюта указывается только в заголовке
`Цена, ₽`. Надпись `Платформа маркировки «Честный ЗНАК» · markiro.ru` под
логотипом удаляется.

## QR-блок сотрудника

В настройки каждого киоска добавляется флаг `printEmployeeQrOnSlip` с начальным
значением `false`. Он редактируется в существующей форме киоска в админке.
Ведомость читает значение с того киоска, на котором создана заявка, и печатает
QR-блок сотрудника только при включённом флаге и наличии активного бейджа.

Изменение требует новой Postgres-миграции, обновления схемы киоска, API DTO,
админского API-клиента и формы. Поле также возвращается в bootstrap-конфигурации
киоска для согласованности полного контракта настроек, хотя локальной логике
киоска для печати оно не требуется.

## Логотип

`slipData` получает `organization.logo` вместе с названием организации. Значение
экранируется перед использованием в `img src`. Если логотип не задан или пуст,
шаблон использует встроенный SVG Маркиро, поэтому печать не зависит от CDN или
доступности фронтенд-сборки.

Удалённый URL логотипа может быть недоступен в момент печати. В этом случае
браузер показывает пустое место, а альтернативный текст сохраняет название
организации. Загрузка и хранение логотипов не входят в эту задачу: используется
уже существующее поле Better Auth `organization.logo`.

## Проверка

- Unit-тесты шаблона: одна страница, несколько страниц, корректные `N из M`,
  повторяющиеся шапки/подвалы, отсутствие разрываемых служебных блоков, логотип
  организации и fallback, цены без `₽`, новое примечание и условный QR-блок.
- API/e2e: флаг киоска попадает в данные ведомости и bootstrap; межтенантный
  доступ к ведомости остаётся запрещён.
- DB: schema- и migration-тесты для нового поля с default `false`.
- Admin: форма показывает, отправляет и сохраняет настройку.
- Финальные package gates для затронутых `db`, `api` и `admin`.
- Отдельно остаётся ручная проверка печати/PDF в Chromium на A4: автоматические
  HTML-тесты не подтверждают работу диалога печати и физического принтера.
