# MKR-INS-10 «Кабинет: каталог продукции и карточка товара» — дизайн

**Дата:** 2026-09-10
**Статус:** утверждён (владелец: «ok»)
**Контекст:** серия печатных инструкций расширяется десятым документом.
Владелец решил разделить тему каталога на два документа: MKR-INS-10 —
ручное ведение карточки товара (этот спек), MKR-INS-11 — загрузка из
Национального каталога и связь с Честным Знаком (следующий цикл).

## Объём

Документ для менеджера кабинета с правом «операции: запись». Сквозной
сценарий — жизненный цикл карточки товара: завести товар, довести его
до статуса «Активен», добавить фотографию и значения по умолчанию,
вывести из оборота. Экраны: список `/catalog` и боковые панели
`/catalog/new`, `/catalog/:productId/edit`.

**Вне объёма** (ссылки вперёд): загрузка из Национального каталога
(`/catalog/import`) и панель связи с ЧЗ (`/catalog/:productId/chz`) —
это MKR-INS-11; очередь несопоставленных товаров 1С — раздел
«Интеграции», в документе упоминается одним абзацем как точка перехода;
шаблоны этикеток (раздел `/labels`) — упоминаются только как потребитель
группы продукции.

## Решение

### 1. Структура документа

Девять разделов, по образцу кабинетных MKR-INS-06…09.

1. **Назначение.** Что такое каталог продукции и почему карточка —
   основа работы: смена не запускается по неполной карточке,
   инвентаризация не принимает неактивный товар, группа продукции
   определяет подбор шаблона этикетки, «Наименование для печати»
   попадает на этикетку. Плашка о демонстрационных данных.
2. **Список товаров.** Где находится раздел, поиск по названию и ГТИН,
   фильтры «Статус» / «Статус ЧЗ» / «На странице», колонки таблицы,
   три статуса Markiro: «Черновик», «Активен», «Не используется».
   Кадры: `catalog-list`, `catalog-filters`.
3. **Создание товара: основное.** Кнопка «Добавить продукт», секция
   «Основное»: ГТИН (проверка контрольной цифры на месте — ошибка
   «Неверный ГТИН (проверьте контрольную цифру)»), подсказка владельца
   ГТИН и кнопка «Подставить контрагента», «Название»,
   «Наименование для печати» с подсказкой «Короткое имя для станции и
   этикетки. Пусто — используется полное наименование».
   Кадры: `product-new`, `product-gtin-owner`.
4. **Доведение до статуса «Активен».** Секция «Агрегация и цена»:
   «Группа продукции» (справочник ЧЗ), «Вместимость короба, шт»,
   «Вместимость поддона, шт» — три поля, без которых карточка остаётся
   черновиком; баннер «Черновик — заполните группу и вместимости, чтобы
   запускать смены». Дополнительные поля: цена за штуку, код ЕГАИС,
   срок годности. Кадры: `product-draft-banner`, `product-active`.
5. **Фотография.** Секция «Фотография»: перетаскивание или выбор файла,
   JPEG/PNG/WebP до 5 МБ, где фото видно (список каталога, киоск),
   удаление. Кадр: `product-image`.
6. **Значения по умолчанию.** «Контрагент по умолчанию» — что он даёт
   дальше по процессу. Кадр: `product-defaults`.
7. **Вывод из оборота.** Галочка «Не использовать» и её подсказка
   («Товар нельзя будет выбрать на киоске, в сменах и интеграциях. Он
   останется доступен для инвентаризации и в истории, а его GTIN можно
   будет использовать в новой карточке») против удаления товара с
   подтверждением. Правило выбора: «Не использовать» — штатный способ
   для товара с историей, удаление — только для ошибочно заведённой
   карточки. Кадры: `product-archived`, `catalog-delete`.
8. **Товары из внешних источников.** Плашка несопоставленных товаров
   1С со ссылкой в «Интеграции»; на карточке связанного товара —
   строка «Связано с 1С» и «Разорвать связь». Загрузка из
   Национального каталога — ссылка на MKR-INS-11. Кадр:
   `candidates-plaque`.
9. **Частые проблемы.** definition-list: неверный ГТИН; товар не
   выбирается при планировании смены (черновик или «Не использовать» —
   перекрёстная ссылка на MKR-INS-08); владелец ГТИН не определён; фото
   не сохранилось; нужно повторно завести товар с тем же ГТИН.

Линза «текст ↔ кадры ↔ i18n»: каждая «кавычка»-цитата берётся дословно
из `apps/admin/src/i18n/ru.json` (группа `pages.catalog.*`) и должна
быть видна на кадре своего шага.

### 2. Кадры и съёмка

Одиннадцать кадров в `packages/legal-documents/assets/instructions/mkr-ins-10/ru/`:

| id                     | Экран                                                       |
| ---------------------- | ----------------------------------------------------------- |
| `catalog-list`         | список: активный, черновик и архивный товары, фото у одного |
| `catalog-filters`      | фильтры с применённым «Статус»                              |
| `product-new`          | пустая карточка создания, секция «Основное»                 |
| `product-gtin-owner`   | подсказка владельца ГТИН + «Подставить контрагента»         |
| `product-draft-banner` | карточка-черновик с баннером                                |
| `product-active`       | заполненная «Агрегация и цена», статус «Активен»            |
| `product-image`        | секция «Фотография» с загруженным фото                      |
| `product-defaults`     | «Значения по умолчанию» с контрагентом                      |
| `product-archived`     | галочка «Не использовать» с подсказкой                      |
| `catalog-delete`       | диалог подтверждения удаления                               |
| `candidates-plaque`    | плашка несопоставленных товаров 1С                          |

**Инструмент.** Новый `tools/production-browser/tests/catalog.visual.spec.ts`
поверх существующего энтрипоинта `apps/admin/test/browser/production.html`:
кабинетный харнес монтирует `appRoutes` целиком, поэтому маршруты
каталога уже доступны и новый харнес не нужен. Конфиг —
`catalog.playwright.config.ts` по образцу `production.playwright.config.ts`
(свободный порт 61_595, `testMatch` на новый файл), скрипт
`test:catalog` в `tools/production-browser/package.json`.

Из `production.visual.spec.ts` переиспользуются `settle()`,
`screenshotFullMain()` и `json()`: панели каталога — `SidePanel` с
анимацией входа, без стабилизации кадр поймает полуоткрытую панель.
Перехват `/api/` — строгий: неизвестный путь попадает в `unexpected[]`
и тест падает. Минимальный набор моков: `access/me` (права
`operations.read`, `operations.write`, `integrations.read`), `profile`,
`products` (списочные и одиночные сценарии), `chz-product-groups`,
`counterparties`, `integration-candidates`, `products/:id/image/:checksum`
(бинарный WebP), `products/gtin-check`. Точный список закрепляется в
плане по факту первого прогона — `unexpected[]` покажет недостающее.

**CI.** Спек в CI не добавляется — по образцу `test:production`
(кадры MKR-INS-08/09), который тоже гоняется только локально: кадры
коммитятся в репозиторий, а прогон занимает минуты. При необходимости
регрессионного контроля добавляется отдельно.

**Попутный фикс.** `inventory.visual.spec.ts` и
`production.visual.spec.ts` до сих пор пишут кадры в плоский
`assets/instructions/mkr-ins-0X/`, хотя после переезда на локальные
подпапки (`4ef6b43d3`) файлы живут в `…/ru/`, и лендинг импортирует
именно оттуда. Четыре константы каталогов правятся на `…/ru/` — иначе
следующая переверификация 06–09 положит кадры мимо. Кадры при этом не
перегенерируются, RU-набор не трогается.

### 3. Регистрация документа

- `packages/legal-documents/src/types.ts` — union `LegalDocumentCode`
  расширяется значением `"MKR-INS-10"`.
- `packages/legal-documents/src/registry.ts` — вид документа
  `instruction`, релиз: ревизия `2026.09/01`, дата вступления
  `2026-09-10`, статус `active`, профиль оператора
  `operator-2026-08-15`, маршрут `/instruktsii/katalog-kartochka-tovara/`;
  строка в `LEGAL_DOCUMENTS` с ключом `MKR-INS-10/2026.09/01`.
- Контент: `packages/legal-documents/src/documents/cabinet-catalog-product.ts`,
  только `ru` (см. ниже про локали).
- Лендинг: `apps/landing/src/pages/instruktsii/katalog-kartochka-tovara/index.astro`
  с импорт-картой одиннадцати PNG; EN-страница не создаётся.
- Описание для реестра и SEO: `DESCRIPTION_BY_CODE` в
  `apps/landing/src/content/legal-pages.ts` требует **обе** локали
  (тип `Record<LegalDocumentCode, Record<LegalLocale, string>>`), поэтому
  для MKR-INS-10 пишутся и русское, и английское описание — английское
  используется реестром `/en/legal/` только когда документ получит
  английскую версию, но тип обязывает его задать.

**Что регистрируется само.** Main получил SEO-апдейт с хабами и
зеркалами, поэтому две вещи ручных правок не требуют:

- Хаб `/instruktsii/` (`components/HubPage.astro`) перебирает
  `ACTIVE_LEGAL_RELEASES`, отбирает инструкции по локали и группирует их
  по префиксу заголовка до двоеточия. Поэтому заголовок обязан начинаться
  с «Кабинет: » — тогда документ встаёт в существующую группу кабинетных
  инструкций, а не создаёт новую.
- Markdown-зеркала (`lib/markdown-mirror.ts`,
  `generateMarkdownMirrors(root)`) строятся обходом собранного сайта, то
  есть подхватывают новую страницу автоматически.

### 4. Локали

Документ выходит **только на русском**: код не добавляется в
`INSTRUCTION_EN_PUBLISHED`. Английская версия появится вместе с
кабинетным EN-траншем (спек
`docs/superpowers/specs/2026-09-02-instructions-en-cabinet-design.md`,
ветка `claude/instructions-en-cabinet`).

Полезный побочный эффект: в реестре снова есть инструкция без
английской версии, поэтому негативные тесты «rejects a Russian-only …»
в `registry.test.ts` и «rejects an English artifact for a Russian-only
instruction» в `legal-artifacts.test.ts` сохраняют предмет — их
перепрофилирование, запланированное в EN-кабинетном спеке, отменяется.
Это будет отражено при обновлении того спека.

## Критерии приёмки

1. Одиннадцать кадров сняты в `mkr-ins-10/ru/`, каждая цитата документа
   подтверждена в `ru.json` и видна на кадре своего шага (отчёт линзы
   в PR).
2. Тесты пакета, лендинга и deploy зелёные; `pnpm format:check` и линт
   чистые.
3. `artifacts:generate` публикует 27 файлов, 26 старых байт-в-байт;
   `artifacts:verify` и повторный прогон с `--check` зелёные.
4. Страница `/instruktsii/katalog-kartochka-tovara/` собирается и
   отображается в RU-реестре; EN-реестр без изменений.
5. Прогон `inventory`/`production` visual-спек после фикса путей
   складывает кадры в `…/ru/` и не меняет ни одного RU-кадра.
