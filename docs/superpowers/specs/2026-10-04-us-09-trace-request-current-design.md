**Status:** Owner-approved written design, 2026-10-04. US-09 implementation is In progress; accepted internal checkpoints are recorded in the [implementation roadmap](../../us/implementation-plan.md). This design is not evidence of complete package publication or cabinet integration.

**Scope:** RQ-001–007 (P0), with RQ-008 QA sign-off deferred to P1.

## Purpose and boundaries

An authorized U.S. processor user records a trace request and its deadline, checks the requested records, and prepares a reproducible response package. The package identifies its exact request revision, sources, findings, effective Plan if present, artifact hashes and operator. A later correction produces a new run revision; it never rewrites an earlier response. The P0 workflow prepares files in the separate U.S. instance. It does not transmit them to FDA or assert legal compliance.

The default due time is exactly 24 elapsed hours after receipt; an agreed alternative is recorded with a reason. This is a product drill and recordkeeping workflow, not a claim that every request has this deadline or that the application has measured active human work. The [FDA rule page](https://www.fda.gov/food/food-safety-modernization-act-fsma/fsma-final-rule-requirements-additional-traceability-records-certain-foods), checked 2026-10-04, describes the 24-hour-or-agreed-time provision and its then-current enforcement timing. Review regulatory wording again before any release; neither a local test nor this spec is legal acceptance.

US-only API, database and private artifact storage are required. Persistent production data and infrastructure must be outside the Russian Federation. The current US runtime remains release-disabled. EN/ES cabinet copy and English-only versioned workbook/PDF artifacts follow US-07/08. Station, scanning, printing, email delivery, direct FDA submission and non-processor profiles are outside this P0 slice. All demo records and packages retain server-derived synthetic provenance.

## Implementation baseline at original design approval

The baseline below predates the subsequent foundation increments. For current implementation status, read the accepted checkpoints linked from the roadmap; the [owner-approved package-core supplement](2026-10-04-us-09-package-core-design.md) has a separate implementation-plan review gate.

- `renderUsExportCore(input: ExportInputV1)` in `apps/api/src/modules/traceability/export/adapter.ts` returns optional XLSX bytes/hash, registry version/hash, canonical input digest, row counts, findings and a typed artifact failure. It does **not** persist runs or return an artifact array, manifest or ZIP. The old draft's `TraceExportAdapterService.render` and `buildTraceExportManifest` are not implemented contracts.
- `readUsExportSources` accepts up to 500 explicit pins, authorizes the processor profile and export capability, and opens its own repeatable-read transaction. US-09 needs an internal transaction-aware selection/reader seam so the request, complete source content, findings, Plan identity and version stamps are captured under one consistent view. Preserve the public reader's authorization and tenant checks; do not replace it with the bounded US-06 graph presentation result.
- US-06 search, trace and readiness exist, but their UI projections and page limits are not a complete export scope. A capped traversal cannot silently become a complete response. Selecting records from search must resolve every applicable page/dependency under an explicit server bound; exceeding that bound is a visible non-ready condition, never a truncated success.
- US-08 has versioned published Plan rows, checked PDF hash and a private **local synthetic** artifact store. Its current adapter is Plan-specific, not a US-09 package store or production residency proof. A request package uses the exact effective Plan version and verified existing PDF bytes; it does not render the Plan again or call its user-facing download route as an internal shortcut.
- The strict US-07 input schema contains immutable build identity but the production build-identity provider is not yet implemented. US-09 must not substitute mutable Git/package reads or omit the stamp. This prerequisite blocks package publication until it exists.
- The US cabinet is `apps/admin/src/us/`, with in-cabinet navigation; the HTTP allowlist is `apps/api/src/deployment/us-development.module.ts`. The old draft's RU `pages/traceability` structure, guards, shared pg-boss queue and RU object-storage URLs are not US implementation targets.

## Request and validation

Request receipt and due instants must be exactly representable in milliseconds. Domain parsing and strict create/update contracts reject any nonzero fractional digit beyond the third; trailing-zero forms such as `.123000Z` remain accepted. Contracts preserve accepted text, while the deadline rule returns canonical UTC milliseconds. True microsecond support requires a separate design; the foundation must never silently truncate precision or mistake a changed sub-millisecond deadline for the default.

Persist a tenant-scoped `trace_requests` record with a server ID, tenant-unique requester reference, requester/contact text, `received_at`, `due_at`, optional alternative-deadline reason, nullable draft scope, creator, revision and open/closed lifecycle. Step 1 may save the request shell; validation/preparation require a fully validated scope with at least one selector. A request starts as an editable open record. Concurrent updates use the expected revision; changes to scope/requester/deadline invalidate the last validation. Closing stops new runs but retains old runs and authorized downloads. Display statuses such as Validated, Package ready and Export-ready are derived from the last matching validation/latest run, not competing mutable request statuses.

P0 scope supports the approved product description/ID, TLC list or range, date range, location and source reference selectors, plus a server-resolved selection from US-06 search. Validate all identifiers and ranges, require at least one selector, and record the resolved scope in the snapshot. The server proves that the traversal is complete for its supported bound. If a valid scope matches no records, validation records that exact result. It is not an infrastructure failure and it is not export-ready. The US-07 workbook core requires at least one event, so an empty response never fabricates one.

`Validate` performs a fresh, authorized, consistent read. It stores source-linked findings, a canonical **scoped-content digest** and validation time. That digest includes requester/times/scope, selected values and lifecycle, genealogy, findings, Plan identity/hash and registry/baseline/build stamps, but excludes run-only ID, actor, mode, idempotency key and generated-at instant. `Prepare` reads the scope again within its freeze transaction and compares the same scoped-content digest. A changed request, event lifecycle/content, genealogy, lot/source/product/coverage value, Plan, registry/baseline/build stamp or finding makes validation stale; the user must revalidate. The persisted full `ExportInputV1` separately receives its frozen generation instant and has its own US-07 canonical `inputDigest`; the two digests have different names and cannot be compared as if identical. Warnings stay visible and can be acknowledged with a reason and exact scoped-content digest. Acknowledgement never waives an error. Technical read/timeout/corrupt-revision failures are not findings that can be converted to a successful incomplete run.

## Immutable run and source freeze

An authorized preparation command takes a mode (`export_ready` or `available_records_incomplete`) and an idempotency key. Under a tenant/request lock it allocates the next positive run revision and atomically stores the request metadata, selected record identities and **content**, lifecycle state, genealogy, lot/source/product/coverage facts, validation findings, exact US-07 `ExportInputV1` when at least one event exists, effective Plan ID/hash when present, regulatory baseline, registry version/hash, timezone, build identity, frozen instant, scoped-content digest and full-input digest where applicable. An empty matched scope freezes an explicit empty-selection snapshot and bypasses only the one-event-minimum US-07 workbook adapter; it never fabricates `ExportInputV1`. No client-supplied tenant/actor/provenance or arbitrary event pins become authority. The transaction-aware source reader must share the freeze transaction; a second independent snapshot is not sufficient. Keep bounded input and artifact sizes explicit and test the supported maximum. Crossing a bound fails visibly, without claiming a complete package.

`trace_export_runs` stores tenant/request composite identity, revision, mode, frozen snapshot and named digests, validation summary, status (`queued`, `processing`, `ready`, `failed`), operator, timing, retry state and outcome. `trace_export_artifacts` stores tenant/run composite identity, kind, name, bytes, SHA-256, private key and publication time. Additive migrations enforce tenant composite FKs, uniqueness of `(tenant, request, revision)` and `(tenant, actor, idempotency key)`, constrained digests/statuses and no mutable overwrite path. A retry resumes the **same** frozen run, not a fresh scope; a new response uses a new revision. Identical command-key retry returns the original run. Reuse with a different command payload conflicts; current source drift alone does not redefine the already-accepted command.

For an `export_ready` run, every included source is current/finalized, the scope and dependencies are complete, no blocking finding exists, an effective Plan is pinned, and the workbook is safely representable. Otherwise the command is rejected with precise findings, without creating an export-ready run. `available_records_incomplete` is an explicit separate authorized outcome: it preserves available current and historical/draft/void records with lifecycle labels, source-linked errors, absent Plan/artifact entries and a clear **Incomplete** mark. It may have zero matched records and no workbook, but must say so. Missing/corrupt pinned data, failed storage, wrong tenant, permission denial or unsupported profile fail the operation; they are not successful incompleteness. Neither result auto-closes or fulfils the request.

Do not rebuild old runs from live request fields, current event rows, mutable catalog or current Plan. Store enough frozen bytes/content and version identity to retry or verify an earlier run after source edits. Later amendment/void/Plan supersession changes only future revisions. Existing approved Plan objects remain retained by US-08. No P0 purge or generic deletion of request runs/artifacts.

## Package and publication

The US-only worker claims queued/expired runs with a lease and attempt fence, survives restart through durable queued-run reconciliation, and renders solely from the persisted frozen input. When at least one source event was frozen, it calls the **actual** `renderUsExportCore`, distinguishes validation findings from typed workbook failures, and checks its returned full-input digest/registry stamp. For an explicit empty selection it emits the validation/report/package path without invoking the one-event-minimum adapter or inventing an XLSX. It reads the exact pinned US-08 Plan PDF through a private verified internal adapter. A vanished, mismatched or unreadable pinned Plan is a failed execution; an absent Plan is permitted only in incomplete mode and is listed as absent.

Build a report from request/run facts and already-built payloads. Its time fields identify the measurement boundary: request receipt, operator preparation click, worker start when known and **Report data prepared at**, before PDF rendering. The owner approved this timing correction on 2026-10-04: actual PDF-render completion and database publication completion are recorded later in run detail/audit, not backfilled into the frozen PDF. The PDF labels `report data prepared − preparation started` as **Elapsed to report data preparation**; `publication completed − preparation started` later measures system/session elapsed time in run detail. Unknown worker timing remains unavailable. A separate observed drill is needed for the C-013 trained-operator target; do not label session age as active human effort. The report contains no self-hash or later artifact hashes. Synthetic packages carry a visible non-operational mark on the report and package metadata; the attached Plan preserves its own mark.

Hash order is acyclic: available XLSX and pinned Plan PDF plus validation JSON → request report PDF → manifest JSON → `SHA256SUMS` → stored ZIP. Manifest entries cover payload files including the report and list unavailable files/reasons for incomplete mode; they exclude the manifest, sums and ZIP. `SHA256SUMS` covers payloads and manifest. ZIP SHA-256 is external run/artifact metadata. Canonical JSON, fixed ZIP entry order/mtime, safe filenames, bounded bytes and a verifier make the result reproducible. Do not add P1 CSV/JSON exports merely because the old draft reserved enum values. The P0 package always has validation, report, manifest and sums; workbook and Plan presence depends on the explicit outcome.

Publish attempt-scoped private objects only after hash/ZIP verification. Commit artifact rows, final status and exact audit metadata atomically after verified upload; do not expose a ready run before all referenced bytes exist. A failed attempt cannot remove a referenced winning object, and an ambiguous commit requires a reference/fence check before cleanup. Retrying must not overwrite an immutable key or duplicate the run. The US package adapter may share a verified **U.S.-only** private storage service with Plan but never a RU bucket, key, worker or fallback. Its local synthetic configuration may exercise the flow; production publication remains unavailable until a separately reviewed non-RF storage and recovery configuration exists. Without configured US storage, request create/edit/validate and diagnostic preview remain available; preparation, publication and download return an explicit unavailable result. No public object URL or direct FDA network client is added.

## US HTTP, cabinet and audit

Use strict US-only contracts and canonical `/api/us/traceability/requests` and export-run routes, explicitly allowlisted in `UsDevelopmentModule` and OpenAPI. List/detail, create/edit/close, validate, acknowledge warning, prepare by mode, run history/detail, retry and tenant-authorized bounded download are P0; sign-off is P1. Every boundary uses `UsSessionGuard`, a server-resolved US tenant and fresh processor/capability membership checks. Reading requires `traceability.read`; preparation requires the existing QA/export authorization policy; downloads require `traceability.export.read`. A reader can download a permitted existing artifact without acquiring mutation permission. Wrong-tenant IDs are not found; RU and generic profiles have no usable request path. Do not port the old draft's RU guards or presigned download behavior without a separate US threat-model review. Download should follow the established private US Plan byte-response pattern, with size limits and audit.

Every mutation, rejection, mode decision, retry, publication and download records exact tenant, actor, request/run identity, action, outcome, mode, revision/digest and relevant finding/artifact hashes. The worker's recorded initiator is distinct from the system execution identity. Requester contact is personal data: restrict it to authorized response views, exclude it from routine logs/error payloads, and keep all persisted copies and backups in the US deployment boundary.

The existing US cabinet gains a Trace requests item, grouped with Search, Trace and Plan. EN/ES screens cover list with received/due countdown, request form, server scope/validation findings with source links, two clearly separate preparation actions, queued/processing/ready/failed and storage-unavailable states, immutable revision history and audited downloads. The incomplete action never says Export-ready. A valid empty result says no matching records; a technical failure has its own state. The countdown continues after an incomplete download. No CTA says submit/send/upload to FDA. All controls have keyboard/focus and non-color status; no new RU navigation or Russian copy.

## Independently reviewed stages and verification

1. Rules/contracts and additive tenant-scoped persistence: request/scope/deadline, revision, mode, digest, exact schema constraints and cross-tenant denial. A focused failing test precedes each change.
2. One consistent selection/validation/freeze: transaction-aware US-07 reader, complete bounded scope, full serialized snapshot, current-vs-historical handling, stale validation and idempotency/concurrency tests. Prove that later edits do not change revision 1.
3. Package core and private storage: actual US-07 call, pinned US-08 Plan read/hash, report, acyclic manifest/sums/ZIP verifier, durable fenced worker, crash/retry/publication/cleanup and storage-unavailable paths. Byte-determinism and tamper tests use an isolated synthetic store.
4. US-only HTTP and EN/ES cabinet: current membership and role denial, OpenAPI/isolation checks, draft/validation without storage, distinct outcomes, accessible states, exact audit assertions and complete synthetic browser drill. Each stage has a separate implementer and independent review before the next, per the owner's execution preference; a detailed plan follows approval of this spec.

Proportionate package test/typecheck/lint/build, migration upgrade/fresh tests, `git diff --check` and formatting checks are required at implementation. A clean synthetic ZIP and browser journey are not hosted non-RF storage, backup/restore, Excel interoperability, production throughput, fluent Spanish, accessibility-device or regulatory acceptance. US-11 separately measures trained human time and collects screenshots/evidence. No push, merge, release or deployment is included in this design.

## Explicitly deferred

RQ-008 QA sign-off, notifications, email/EDI delivery, arbitrary FDA requests beyond supported processor scope, generic-profile FDA-labelled exports, CSV ZIP/canonical JSON, a purge scheduler, external submission, hosted provisioning and Station behavior remain outside US-09 P0.
