# Печатные инструкции оператора — дизайн

Дата: 2026-08-21
Статус: утверждён (brainstorming)
Первый документ: **MKR-INS-01 «Станция сканирования: вход оператора и старт смены»**

## Цель

Собрать печатные инструкции к продукту на базе существующего конвейера
документов лендинга (`packages/legal-documents`): структурированный контент →
страница на лендинге → печатный PDF-артефакт с верификацией. Первой покрываем
самую критичную зону — операторские сценарии, начиная со входа и старта смены.

## Решения (принятые в brainstorming)

- Зона первой инструкции: вход оператора по бейджу и старт смены на станции.
- Архитектура: расширяем `packages/legal-documents` новым видом документа
  «инструкция», а не отдельный пакет и не разовая страница.
- Публикация: публичная страница на лендинге, только RU. EN — позже.
- Скриншоты: снимаются из dev-галереи станции с тестовыми (вымышленными)
  данными; Claude снимает их сам.
- Артефакт: DOCX с встроенными PNG → существующий конвейер
  LibreOffice → PDF/A → veraPDF → манифест.

## 1. Контент и типы (`packages/legal-documents`)

- В реестр вводится категория документа
  `kind: "legal" | "template" | "instruction"`. Существующие релизы получают
  свои kind (MKR-PD-01/02 — legal, MKR-DPA-01/MKR-BRD-01 — template);
  поведение существующих документов не меняется.
- Новый код `MKR-INS-01` в `LegalDocumentCode`, релиз в `LEGAL_RELEASES`
  со статусом `active`, ревизией `2026.08/01`, маршрутом `/d/mkr-ins-01/`.
- RU-only контент: для инструкций локаль `ru` обязательна, `en` опциональна —
  тип `content` и `routes` становятся `ru`-обязательными с опциональным `en`.
  Валидация реестра (`validateLegalRegistry`) проверяет: для `legal`/`template`
  обе локали обязательны (как сейчас), для `instruction` достаточно `ru`.
- Новые блоки в `LegalBlock`:
  - `step` — `{ kind: "step"; title: string; text: string; image?: { id: string; caption: string }; expected?: string }`.
    Нумерация шагов сквозная в пределах секции, задаётся рендером, не контентом.
  - `callout` — `{ kind: "callout"; tone: "info" | "warning"; text: string }`.
- Контент — новый файл `documents/station-operator-shift.ts`. Структура секций:
  1. Назначение и подготовка (что должно быть включено/подключено).
  2. Вход по бейджу (+ callout: fallback-поиск по имени, бейдж не читается).
  3. Выбор существующей смены.
  4. Создание новой смены.
  5. Начало работы (стартовый рабочий экран, что проверить).
  6. Частые проблемы и куда обращаться.

## 2. Скриншоты

- Источник: dev-галерея станции — `apps/station` в `vite dev` с
  `?gallery=1` (`src/dev/StationScreenGallery.tsx`, фикстуры без реальных
  данных).
- Экраны: логин оператора (сканирование бейджа), поиск оператора по имени,
  выбор смены, создание новой смены, стартовый рабочий экран.
- Формат: PNG, фиксированный вьюпорт (единый размер для всех скриншотов,
  ориентир 1280×800), без личных данных — только фикстуры.
- Хранение: `packages/legal-documents/assets/instructions/mkr-ins-01/<image-id>.png`
  — единый источник для DOCX-артефакта и страницы лендинга. Блок `step`
  ссылается на изображение по `id`; сборка падает, если файл по `id` не найден
  (и предупреждает об осиротевших файлах).

## 3. Лендинг (`apps/landing`)

- Новая страница `/d/mkr-ins-01/` через компонент `InstructionDocument.astro`
  на базе `LegalDocument.astro`: та же обвязка — код, ревизия, «действует с»,
  оглавление, контакты, print-стили.
- Рендер новых блоков: `step` — нумерованный шаг с заголовком, текстом,
  скриншотом с подписью (`<figure>/<figcaption>`) и блоком «Ожидаемый
  результат»; `callout` — выделенная плашка info/warning.
- Скриншоты копируются/импортируются из пакета в статику лендинга на сборке
  (через import из workspace-пакета или copy-шаг), чтобы не дублировать файлы
  руками.
- Реестр `/legal/` показывает инструкции отдельной группой «Инструкции»;
  EN-реестр (`/en/legal/`) инструкции без EN-локали не показывает.
- SEO/поиск: страница попадает в `LEGAL_SEARCH_PAGES`/sitemap как RU-only.

## 4. Печатный артефакт

- `docx.ts` расширяется:
  - встраивание PNG: media-часть, relationship, `<w:drawing>` c явными
    размерами (ширина по печатной полосе, высота по соотношению сторон);
  - рендер `step`: нумерованный заголовок, текст, изображение с подписью,
    «Ожидаемый результат»; рендер `callout` — абзац с выделением.
- Новый вид артефакта `instruction-pdf` в `LegalArtifactKind`; имя файла по
  существующей схеме: `markiro_mkr-ins-01_2026-08_ru.pdf`.
- Конвейер без изменений по сути: LibreOffice → PDF/A → veraPDF → манифест с
  хешами. Для инструкций свой лимит размера PDF (константа рядом с
  `MAX_LEGAL_PDF_BYTES`), так как встроенные скриншоты тяжелее текста.
- Проверка отсутствия font-substitution и валидация PDF/A сохраняются;
  скриншоты в PDF/A допустимы как растровые изображения.
- DOCX для скачивания не публикуем (в отличие от template-документов) —
  наружу идёт только PDF.

## 5. Тестирование

- `registry`: валидация нового kind, RU-only-локалей и маршрутов.
- `docx`: юнит-тесты встраивания изображений (наличие media-части,
  relationship, корректные размеры) и рендера `step`/`callout`.
- `generate/verify-artifacts`: инструкция проходит генерацию и верификацию,
  манифест учитывает новый kind и лимит размера.
- Лендинг: `pages.test.ts` и `legal-artifacts.test.ts` — новая страница в
  реестре и поиске, EN-реестр без инструкции; рендер шагов со скриншотами.
- Сборка контента: тест, что каждый `image.id` из контента имеет файл в
  assets и наоборот.
