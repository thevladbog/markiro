# Повторная обработка: приёмка на Station и ТСД

Правило: [согласованная спецификация](../superpowers/specs/2026-09-12-validation-reprocessing-design.md).
Этот документ задаёт сценарии проверки новой настройки. Он не подтверждает их
выполнение. Результаты прежнего режима печати в
[основном протоколе](validation-dm-duplicate.md) не доказывают повторную обработку.

## Подготовка

Использовать тестовую организацию, тестовый товар и синтетические полные КМ.
Подготовить исходную закрытую смену с принятым кодом A, активную исходную смену
с кодом B и ещё не принятый код C. Сохранить отчёт и готовую выгрузку закрытой
смены до испытания. Указать версию и SHA API, Station/Android, ОС, модель ТСД,
сканера и принтера, подключение, язык печати, DPI и носитель.

Для сценария освобождения и нового скана в той же смене использовать приёмку,
сделанную после обновления, либо код с текущим владельцем на момент миграции.
Уже освобождённые до обновления обычные приёмки без достоверного свидетельства
сервер не может восстановить из журнала всех сканов; этот исторический случай
не покрывается новой серверной гарантией. Локальные запреты устройств сохраняются.

Создать две смены проверки с печатью: с выключенной и включённой настройкой
«Разрешить повторную обработку кодов из предыдущих смен». Настройка должна быть
выключена по умолчанию и недоступна для изменения после открытия.

## Сценарии

Каждый сценарий выполнить на Station и ТСД отдельно. В колонке результата
записывать `passed`, `failed` или `not_run` и ссылку на свидетельство.

| Сценарий                                                                                               | Ожидаемый результат                                                                                                              | Station | ТСД     |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------- | ------- |
| Выключенная настройка, код A после загрузки истории                                                    | Ошибка дубля; счётчик и число заданий печати не растут                                                                           | not_run | not_run |
| Включённая настройка, код A                                                                            | Один принятый повтор и одно задание печати; исходная смена по-прежнему владеет кодом                                             | not_run | not_run |
| Карточка исходной смены отсутствует или устарела как активная, серверная история подтверждает закрытие | При включённой настройке разрешён один повтор; устаревший кэш не превращается в ошибку активной смены                            | not_run | not_run |
| Код A второй раз после завершения контроля                                                             | Ошибка дубля; ни новой единицы, ни нового задания                                                                                | not_run | not_run |
| Включённая настройка, код B                                                                            | Ошибка: исходная смена ещё не закрыта; печать не начинается                                                                      | not_run | not_run |
| Код C                                                                                                  | Одна обычная приёмка и одно задание печати                                                                                       | not_run | not_run |

| Явная перепечатка с причиной после смены календарной даты                                              | Используются сохранённые байты и дата; растёт число попыток, количество обработок прежнее                                        | not_run | not_run |

| Обрыв загрузки истории на промежуточной странице                                                       | Прежняя полная история сохранена, время её проверки не заменено временем неполной загрузки                                       | not_run | not_run |

В обеих реализациях дополнительно проверить: обычный код принят, владение
освобождено, затем тот же код сканируется другим устройством в той же смене
проверки с печатью. Ожидается отказ без нового приёма и печати; точная повторная
доставка исходного скана не создаёт нового факта. Статус: `not_run`.

Дополнительный сценарий поздней синхронизации: устройство B сохранило закрытую
исходную смену P, затем P освобождена; устройство A приняло код в S и освободило
владение; более ранний офлайн-скан B в S был локально предварительным повтором.
После серверной коррекции исторического победителя проверить, что освобождённая
обычная приёмка не создаёт действующее локальное владение или количество.
Повторить после перезапуска и доставки устаревшей обычной квитанции: количество
остаётся нулевым, исходные данные печати сохранены. Статус: `not_run`.

## Проверка отчёта

После серверного подтверждения A и C новая смена показывает две обработки:
одну впервые и одну повторно. Для A видна исходная смена. A и C встречаются
в новой плоской TXT/CSV-выгрузке ровно по одному разу. Сравнить полное значение КМ,
включая GS и криптохвост; GTIN и серийный номер сами по себе недостаточны.

Повторная обработка не создаёт короб или связь агрегации и не увеличивает
глобальный выпуск/остаток. Повторно скачать сохранённую до испытания выгрузку
исходной смены и сравнить её байты; проверить прежний отчёт и владение кодом A.

Окончательный результат приёмки указывать отдельно от локальных автоматических
тестов. Публикация, установка сборки и включение режима на производственной линии
выполняются только по отдельному поручению.

## Локальные свидетельства разработки

Автоматические проверки и стенд с фиктивным принтером не заменяют сценарии
физической приёмки выше. Для текущей реализации выполнены:

- API и PostgreSQL: изолированная локальная база, проверки гонок, границ
  организации, повторной доставки, точных результатов обработки и отчётов.
  Отдельный опыт с изменениями данных между страницами подтвердил неизменность
  уже опубликованной истории.
- Station: браузерный стенд с настоящей локальной SQLite и фиктивными API
  и принтером. Проверены отказ до печати, разрешённый повтор, контроль этикетки,
  ожидающее подтверждение, поздний конфликт, перезапуск, создание смены
  и совместимость формы со старым API. Проверены русский и английский интерфейсы,
  обе темы и ширина 1024 пикселя.
- ТСД: тесты Room, синхронизации и Compose, сборка отладочного APK. Проверены
  границы текста и доступность действий на экране 320 × 640. Устройства
  или эмулятора для установки сборки не было. PNG, полученные в тестах,
  не подтверждают работу сканера или физическую печать; русский экспорт
  изображения иногда пропускает заголовок и не принят как полное визуальное
  свидетельство.
- Админка: реальные React-компоненты с локальными тестовыми ответами API.
  Проверены выключенное начальное значение, редактирование запланированной смены,
  запрет изменения после открытия, итог «3 = 2 + 1», переход в исходную смену,
  полный КМ с GS и криптохвостом, ошибка загрузки и повтор запроса. При ширине
  390 пикселей полный код переносится без горизонтального переполнения документа.

Синтетический опыт на хосте с историей 100 000 кодов для Station потребовал
около 263 МиБ дополнительной памяти процесса и 62,4 МБ SQLite; публикация
заняла около 440 мс. Это не измерение полной цепочки HTTP/Tauri, обработки
сканером или закрытия смены на заводском оборудовании. Проверка фактического
объёма истории и скорости на целевых устройствах остаётся частью приёмки.

Windows/Tauri, Android на физическом ТСД, принтер, офлайн-сеть оборудования,
облачное развёртывание и прежние выгрузки из производственной организации
в этой разработке не проверялись. Существующие инфраструктурные тесты API
с внешними сервисами остаются отдельным этапом.
