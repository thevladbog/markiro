## Регрессии и итоговое ревью

Свежий reviewer выполнил read-only обзор всей реализации. Все пять важных замечаний воспроизведены failing tests и исправлены:

- Производственные факты теперь синхронизируются до зависимой истории перепечатки; один SQLite read не выбирает warehouse события при оставшихся production dependencies.
- Восстановленный ключ того же устройства видит прежние сеансы, задания, кэш и pending события; события сохраняют исходного владельца. Чужой ключ доступа не получает.
- Локально расформированный или аннулированный короб недоступен для нового задания; сохранённые поля источника не переписываются.
- Реальный экран работает в StrictMode; уход со страницы сохраняет barrier до завершения операций.
- Причина аудита соответствует конкретной попытке, включая её sending/sent/verified, с точными actor/tenant/device/sequence assertions.

Ручной ввод отдельно прошёл RED→GREEN: нет action до реализации; затем верный SSCC вызывает один lookup/send, неверная контрольная цифра не вызывает их, сканер остановлен на время формы, отмена ничего не печатает, повтор того же номера не отправляет второй экземпляр. Обратная проверка этикетки остаётся сканированием.

Ранее отложенное замечание preview исправлено после прямого запроса пользователя и RED→GREEN: центрирование SSCC, переносы/ellipsis и maxLines, точные bitmap pixels кириллицы, выравнивание при 203/300 DPI, отбрасывание позднего растра другого шаблона. SSCC preview использует GS1-128 с FNC1 и AI 00; default Code 128 сохранился. После последующего ревью новые задания и preview используют общий LabelRenderPlan: ASCII и кириллица растеризуются одинаково, полный KM и геометрия берутся из общей модели. Ранее сохранённые производственные байты не изменены. Кнопка ручного ввода постоянно показана в header, с проверкой disabled-состояний. Обнаруженное на скриншоте наложение footer/recovery воспроизведено RED на обоих размерах и устранено; GREEN проверяет геометрию и доступность действий.

## Принятые решения

1. До прямого разрешения сохранять новый режим без коммита/пуша. После указания «После правок — пуш и пр» это ограничение снято. В PR включается весь утверждённый режим; merge, выпуск и deployment не разрешены этим указанием.
2. Использовать слитый TSPL fix из `42d83f736`: база проверена до реализации. Цена ошибочной базы — иной состав будущего PR; до PR потребуется свежий three-dot diff.
3. Для локальных Turbo/browser subprocess использовать scratch Corepack wrapper: установленный глобальный pnpm отличается от закреплённой версии. Цена — локальное воспроизведение этих команд требует правильного PATH; манифесты и dependency policy не менялись.
4. В Zod использовать `eventUnion.options[0]` для строгого prepared-варианта вместо отсутствующего `.extract`. Цена — зависимость от порядка вариантов; типы и тесты проверяют этот контракт.
5. Добавить явный стандартный Data Matrix 30×30 без исторических дат, чтобы не выдумывать отсутствующий срок годности. Цена — дополнительный вариант выбора; автоматического назначения нет.
6. Добавить явный стандартный SSCC 58×40 без исторических дат. Цена — дополнительный вариант выбора и аддитивная seed migration; пользовательские шаблоны не заменяются.
7. Не реконструировать отсутствующие исторические поля; проверять серверный источник по tenant/identity/payload с mapping локального box ID. Цена — сервер проверяет источник, но сохраняет заявленные станцией дайджесты снимка печати, не сами отрендеренные байты.

Предыдущий remote CI выявил пропущенные warehouse маршруты в Windows CORS gate: дефект воспроизведён локально, verifier и обе fixtures дополнены; полный Station release contract — 480/480. Ошибка типа events в API fixture исправлена. Предыдущая сборка production images получила Docker Hub HTTP 429; этот внешний этап требует нового CI запуска.

## Внешние ограничения

Windows/Tauri, физический сканер, TSC 210, носители/DPI, силовое и сетевое прерывание реального транспорта не проверены: оборудование и Windows execution environment недоступны. Rust transport не менялся, поэтому Cargo checks не запускались. Физическая приёмка перечислена в инструкции выше.

Remote CI запускается GitHub после пуша; его результат нужно проверять отдельно. Publication, deployment, beta/stable installer и установка на фабричную станцию не запускались и не входят в текущую авторизацию. Локальные зелёные проверки не доказывают эти этапы. Local Graphify graph в этом checkout отсутствует, поэтому incremental graph update неприменим.
