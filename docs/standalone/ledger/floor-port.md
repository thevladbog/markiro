# Floor UI port: take the approved designs from the cloud station (read together with /tmp/claude/fb/rules.md)

Owner decision (2026-10-13): the standalone STATION floor UI (apps/standalone/src/floor) looks and lays out badly (see screenshots in the task). The cloud station (apps/station) already has the APPROVED, production-tested designs and screens. Do NOT redesign from scratch: PORT the cloud station's presentation to the standalone floor, so the two look the same. The cloud web contour is being wound down, so forking the presentation code into apps/standalone is acceptable (no shared package needed now).

Where the cloud code lives: apps/station/src/pages (OperatorLogin.tsx, ShiftSelection.tsx, TaskSelection.tsx, NewShift.tsx, WorkScreen.tsx, WorkstationSetup.tsx, Enrollment.tsx, WarehouseReprint.tsx, ExceptionFlow.tsx, ...), apps/station/src/components (PalletStrip, PalletClose, PalletExceptions, ConflictList, ...), apps/station/src/App.tsx (shell/header/status bar, 2.5k lines monolith tied to the cloud API), apps/station/src/station.css (127 KB), apps/station/src/ui, assets, i18n/ru.json, plus docs/design-briefs/ and docs/superpowers/specs for the station redesigns (shift card redesign 2026-09-20, one-line header). Read the git log of apps/station for the latest visual changes (shift card redesign #615/#619, header) so you port the CURRENT look, not an old one.

Method (per screen you own):

1. Open the cloud screen's JSX + the CSS rules it uses; run the cloud station in dev (its fixtures/gallery under apps/station/src/dev) and screenshot it as the reference; screenshot the standalone screen as «before» (browser tools, 1280×800 and 1920×1080).
2. Port the markup structure, class names and CSS rules into apps/standalone (CSS goes into NEW files next to your screen, e.g. src/floor/<area>/<name>.css, imported by your component; do NOT edit a shared floor stylesheet that another agent also edits; take design tokens from @markiro/ui as the cloud does). Keep identical spacing, sizes, hierarchy, copy where the product text is the same.
3. KEEP the standalone behavior and data layer untouched: host protocol, offline outbox, scan handling, lockouts, A4/pallet logic, hooks and types in src/floor/*.ts. Only the presentation layer changes. If the cloud screen has a feature the standalone lacks (e.g. shift modes, inventory tasks), do NOT implement it: list it in the report as a gap with the cloud file reference.
4. Contracts that must stay green: every interactive station element ≥ 64 px high (tools/production-browser specs), keyboard/focus/labels, i18n through apps/standalone/src/i18n/ru.json (reuse the cloud's Russian copy where it is the same product text), existing Vitest tests (change a test only if the markup/copy changed by design and say so).
5. After: «after» screenshots of the same states next to the cloud reference in /tmp/claude/fb/<area>-shots/ and a table in the report: screen, cloud file, what was ported, what differs on purpose, gaps.
   Coordination (four porters at once, each owns different files): fb-login owns src/floor/OperatorSignIn.tsx, FloorStatusBar.tsx, the floor shell header and sign-in states; fb-hub owns the shift hub («Смены линии») and the new-shift dialog (src/floor/shifts); fb-work owns the work screen (src/floor/work, pallets, close, exceptions); fb-misc owns reprint (src/floor/warehouse, print), the send queue (src/floor/queue), the workplace/setup screens (src/floor/setup). Do not edit another porter's files; if you need a shared helper, add a new file of your own. Do not touch office pages (src/office) or the shell.
