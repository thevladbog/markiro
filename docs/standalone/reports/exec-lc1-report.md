## Решения владельца, пришедшие во время исполнения

- **`tenantId` и `siteId` — не UUID, а непрозрачные строки**, которые выбирает контрагент: 1–64 знака
  `[A-Za-z0-9._:-]`, регистр значим, без обрезки. В домене это `STANDALONE_OPAQUE_ID_PATTERN` и
  `standaloneOpaqueIdSchema` (переэкспорт есть и в контрактах), в Rust — `trust::is_opaque_id`. Имена
  согласованы с исполнителем ЛЦ-0. `licenseId`, `planVersionId`, `replaces` и `hostId` остаются UUID:
  привязка к хосту не ослаблена.
- В подписанных фикстурах `tenantId` = `Zq4bL0x9cabinetTenant01`. Добавлено 27 враждебных и
  пограничных случаев: пустой, 65 знаков, пробелы, NUL, табуляция, перевод строки, `/` и `\`,
  кириллический двойник, полноширинная буква, ZWSP, NBSP, число, `null`. Обратная проверка: UUID,
  nil-UUID, 64 знака и верхний регистр принимаются.
- Случай плана «a nil tenant id» был отказом. Теперь такой `tenantId` допустим, поэтому случай
  заменён на эти 27 и на «a nil host id». **Ожидание случая изменено по решению владельца.**
- §4.2 спецификации исправлен.
- **ЛО8** (подписка без даты окончания: срок файла не больше года, новый файл по запросу бесплатно)
  — это поведение облака, план ЛЦ-0. Строку ЛО8 в спецификации я не трогал, чтобы не конфликтовать с
  ЛЦ-0.

  - Добавлен `parseJsonStrict`, им теперь читаются заголовок и нагрузка.
  - `signCompactJws` подписывает только то, что потом пройдёт проверку.
- Добавлены 12 общих враждебных подписанных фикстур, `expectations.json` получил необязательное поле
  `retiredKids`:

  - суррогаты в `kid` и в нагрузке;
  - лишнее поле в нагрузке и чужой издатель;
  - неканонический base64url;
  - подпись с высоким S — её принимают обе стороны, это закреплено;
  - файлы больше предела.
- Пределы 16 и 64 КиБ теперь закреплены тестом: убирание проверки размера роняет его.
- «Простой текст» дополнительно отвергает C1, U+2028/2029 и двунаправленные управляющие знаки.
- Origin набора ключей обязан иметь вид `https://хост[:порт]`.
- Модульный тест ловит тестовый ключ в производственном наборе по самой точке, а не только по
  префиксу `test-`.

### Итоговое ревью всего плана (opus), исправлено в `28fb5f109`

- Rust читал `plan`/`channel` и из объекта (`{"demo":null}`). Теперь только из строки, добавлены
  новые случаи.
- Проверка закрытых ключей ловит больше форм:
  - PEM с экранированными `\n` и PEM в блоке YAML;
  - Proc-Type PEM;
  - `d:` в JS-литерале, в одинарных кавычках и в экранированном JSON;
  - голый DER: PKCS#8 P-256, RSA, SEC1;
  - файлы UTF-16.
- Литерал DER в тексте задачи 9 плана разбит на части, иначе проверка ловила сам план.
- Шаг CI проверяет kid через here-string вместо канала: под `pipefail` канал мог скрыть совпадение
  (SIGPIPE).
- Origin проверяется по меткам DNS.

- `usable()` не закреплён отдельным тестом: подменные JWK отвергает и `importKey`, исход тот же.
- Остаточные расхождения чисел (`1.0`, `-0`, `1e0`, сверхточные) задокументированы.

Мутационная проверка: для каждого стража мутант убит названным тестом. Выживает по замыслу только
снятие повторной сверки base64 в Rust: крейт `base64` 0.22 сам отвергает такие строки.
