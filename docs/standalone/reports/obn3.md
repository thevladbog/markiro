## Волны ревью (что исправлено)

Rust: плохое состояние текущего пакета не повторно проверялось (теперь ежечасная перепроверка со счётчиком поколений, паника проверки -> `Invalid`); два одновременных PUT одного uploadId разрушали загрузку; у тела загрузки не было простоя-таймаута (60 с); `HEAD` на установщик вёл себя как скачивание; промоушен и завершение загрузки не исключали друг друга; `update_stage` читал манифест без предела.
Вебвью: потеря предложения и закрытие диалога при мигании связи; диалог застревал в `starting`; цели ниже 64 px на станции; аудио-прогресс; тексты причин на станции; ключи списка истории; сырой код вида устройства; документация.

## Отклонения при исполнении

- Коды ошибок добавлены в конец списка (после `export_file_corrupted`), не после `restore_pending`.
- Тестовый приватный ключ: `update.privateJwk`, не `update.jwk`.
- Чужой продукт в манифесте ЛЦ-1 разбирает как `Malformed`: добавлен `signed_for_another_product` (подпись проверяется, потом читается `product`) -> `wrong_product`.
- Тесты «испорченная подпись» плана были нестабильны (последний символ base64url — биты выравнивания) — портится символ в середине подписи (в хосте, оболочке и `update_logs`).
- `GET /v1/device/update` и `.../installer` зарегистрированы прямо в `router()`, а не через `server::update_routes`: `license_routes.rs` требует ровно один `.merge(` и два `Router::new(`.
- Хэш оболочки: `ManifestView.channel` — ручное отображение enum; `mock_app_with` в `ipc.rs` теперь держит `UpdateState`.
- Вебвью: `App` разделён на `App` + `AppScreens` (провайдер обновлений), чтобы не переотступать ~370 строк; `SupportContext.read` из ЛЦ-3 вместо поля `office`; `SUPPORT_CONTRIBUTORS` теперь 3 (проверка длины в `support-report.test.ts` изменена по решению продукта); блоки раздела — соседние карточки; токены `--sp-2`/`--sp-3` вместо `--space-*`; `FloorUpdateLine`/`UpdateBanner` — `Alert role="presentation"`.
- Диалог на станции (`size="floor"`) не даёт ✕/Esc/клик по фону (в `@markiro/ui` Modal нет размера ✕) — закрывается «Отмена».
- Запуск установки с экрана несовместимости и панели входа — `updateShell.install` без отчёта `app.update.start` (маршрут офисный).
- Перепроверка плохого текущего пакета каждый час не пишет строк аудита (строка только при продвижении и на старте).
- `releases.json`: первая запись `0.1.0`, протокол **5**, мин. 1 (в плане 3; в коде `PROTOCOL_VERSION = 5`); тега `standalone-v*` в репозитории нет — сверить с выпуском беты владельцу.
- Уникальных per-task «Отклонений» в §23 спецификации нет — они только здесь.
- Часть задач выполнена без «красного» прогона (отмечено мутантами): 3, 6, 8, 12 (тест источника `host`), 5-й пункт волны вебвью. Остальные — красный подтверждён.

## Не сделано / открыто

- Пункт ревью 5: на старте `open_blocking` хеширует `staged` и `current` (до 512 МиБ) до начала обслуживания — на медленном HDD под таймаутом запуска службы Windows это может задержать хост. Предложенное решение: продвижение синхронно (rename), полная проверка в фоне при состоянии `Verifying`.
- Новый `POST /manifest` во время идущего PUT удаляет папку первого PUT (Windows: файл открыт — папка остаётся до следующего старта).
- Состояние `Mismatch` перехеширует установщик каждый час.
- Пункт ревью 10: пакет, загруженный после `missing/invalid`, не обновляет предложение без смены связи (по спецификации «не по таймеру»).

## Что не проверено

- Реальный Windows: обновление службы, UAC, запуск установщика, потоковая загрузка в WebView2, `FileStamp` по времени создания NTFS (проверен только Unix inode), реальный обрыв сети/Wi-Fi, 60-секундные лимиты (проверены на 50 мс), файл 256 МиБ на самом деле.
- Раздача по реальным устройствам: станции/ТСД не участвовали.
- Визуал: ни одного экрана нового UI в браузере не видели (полоса, строка станции, панель входа, таблица, экран несовместимости); `FloorUpdatePanel` над `OperatorSignIn` — компоновка не видна.
- `pnpm test:production-bundle:contract` и `tools/production-browser` (правило 64 px) не запускались; правило проверено лишь классом `mk-btn--floor`.
- Тег беты и `releases.json`.
