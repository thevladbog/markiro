### Additions beyond the brief (trust-domain attention)

1. **Host address validation in the shell (`host_origin`).** The brief leaves the typed address to `PinnedClient` (`https_only`) and then stores it with `trim_end_matches('/')`, so `https://user:pw@host:port`, a path, a query, a fragment or white space would pass, be sent to (key attached) and be written to `device.json` and into the status the webview reads. `change_address` now first runs `host_origin`: no white space or control character anywhere, `reqwest::Url` parses it, scheme `https`, no user name, no password, path exactly `/`, no query, no fragment; the kept form is `url.origin().ascii_serialization()` (lower-case host, no trailing slash). Anything else is `invalid_request` before any I/O, so the key never goes to a spelling the shell would not keep and `device.json` is untouched. No LAN-only (private range) restriction: a host may be addressed by name and the brief's tests use 127.0.0.1; the pinned certificate (and the key check) is the guard, as the existing probe does.
2. **`host_local_pair` is refused on an office PC** (`DeviceError::Request(InvalidRequest)` before any I/O). The brief says only that `claim` pairs as `office` and `local_pair` "always as a station"; without the refusal an office-role PC could still obtain a station device key through the loopback pairing when a host answers on 127.0.0.1. Roles stay exclusive (changed only by uninstall). Station/host/no-role PCs are unchanged; pairing flows for stations are byte-for-byte as before (only `kind` is threaded through `remember`).
3. **`manage_state` takes the role** (`manage_state(app, dir, role)`), `run` passes `installation::read_beside_executable()`. The brief's fragment 5 (`DeviceState::load(dir.clone())` in `run`) does not exist in this tree; the device is built in `manage_state`. Making the role a parameter lets `tests/ipc.rs` kill the "state ignores the role" mutant.
4. Tests beyond the brief: `a_host_address_is_a_https_origin_and_nothing_else` (unit, 5 accepted spellings with their kept form, 15 refused), `an_address_with_credentials_a_path_or_a_query_is_refused_before_any_request` (against a real host that would answer at those spellings, `device.json` and status unchanged, plus `HTTPS://host/` accepted and kept plain), `an_office_pc_never_pairs_as_a_station_on_this_computer`, and an `install_role == "station"` assertion in `the_app_manages_every_state_its_commands_read`.

Not changed: pairing flows for stations, `claim` order of checks (fingerprint shape, code shape, lock, hello, fingerprint equality, pinned client), secrets handling (the key stays in `PairedDevice`/`HostLink`, nothing new logged: `installation.rs` logs only fixed strings, never file contents), offline-first behaviour (an unreachable new address changes nothing: `unreachable`, old address and link kept).

Role location is shell-side: `installation.json` is read from the executable's directory (admin-writable only when installed under `Program Files`); the webview has no command that writes it, only `install_role` (read). An unreadable/unknown/extra-key file means no role = station (kiosk stays on). Kiosk-per-role itself is the webview's decision (Task 4) from `install_role`; nothing in the shell enters lockdown on its own.

## Self-review

- Three identities: station and host-role PCs can never pair as office (the kind comes only from the installer file, not from the webview); an office-role PC cannot get a station key via `local_pair` (P1) and its `claim` kind is `office`; `change_address` keeps `kind` from the stored config. No command returns the device key; `install_role` returns only the role string.
- A person at a station cannot change the role through the shell; if the file is missing or unreadable the PC is a station (safe side for the floor).
- `change_address` is serialised with pairing/forget/line changes through `self.pairing`; the file is written before the in-memory replace, and the link is replaced last (so a failed save leaves the old address in both places).
- No secrets logged; `installation.rs` prints fixed text only.
