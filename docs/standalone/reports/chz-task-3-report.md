## Self-review and concerns

1. **`maxLines` and `palletId` may be missing on the wire.** serde reads a missing `Option` as `None`, so a body without them is accepted as `null` (the row then writes `null`). The Zod schema requires them; the builder always sends them. My body test records this in a comment and does not pin the leniency. If strictness is wanted, a `deserialize_with` is a one-line proto change (not made: outside the brief).
2. **Counts are not cross-checked by the host.** The host validates formats, pallet, `maxLines`, `documentId` and `partCount`, but accepts any non-negative `codeCount`/`boxCount`/`palletCount`/`openPalletSuppressedBoxCount` (u64/u32 by type, negatives refused by type). It cannot verify them against the files without re-deriving the export; the brief makes the same choice. A client with a session can therefore write a false count into the journal.
3. **Pallet export state is not rechecked** (by design in the brief): a pallet export is recorded even if the pallet was disassembled after the files were saved; a pallet export of an active shift is allowed, a shift export of a planned or active shift is a 409 `conflict` with the shift's status.
4. **Repeated posts are not deduplicated**: the same `documentId` can be recorded twice (pinned by a test); each is a row.
5. **Load.** The machine ran at load 50-90; the full Vitest package failed 6 tests by the 5 s limit in `shifts-page` / `template-editor` (not touched by this task); they pass with `--testTimeout=30000`. Counts as the brief states them are base dependent: proto 48 (measured 50), `office_exports` 8 (measured 20: base 11 + 4 + 5 mine), Vitest 278 (measured 373 for the two files).
6. `git add -N` was not used; the commit added explicit paths. No scratch file remains in the tree.
