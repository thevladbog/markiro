### Additions beyond the brief

1. **Absolute program paths** (`install.rs`): `system_program(program, system_root)` maps `icacls` to `%SystemRoot%\System32\icacls.exe` and `powershell.exe` to `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`; any other name is run as given. `trusted_system_root(env)` accepts `SystemRoot` only when it is a plain absolute drive path (letter, `:`, `\`; no `..`, no `" < > | ? * ; /`, no control characters, no UNC/relative form), strips a trailing `\`, otherwise `C:\Windows`. `SystemCommands::run` applies both on Windows only (`cfg(windows)`); the program names the seam and the tests use are unchanged. An elevated installer therefore never finds `icacls`/`powershell` through a changed `PATH`.
2. **Stop while the service is `StartPending` (addendum item 3 decision).** `service.rs` reports `controls_accepted = empty()` while starting, so Windows always refuses a stop then (error 1061). Decision: `WindowsServices::stop` treats 1062 (not active) and 1061 (cannot accept the control) as no error, and `install::stop` now asks again at every poll while the state is anything but `StopPending` (Stopped/missing ends it). So `uninstall`/`stop-service`/reinstall over a starting host waits it out and stops it as soon as it runs, bounded by the existing 30 s limit (`Timeout` otherwise). Tests of Task 1 are unchanged and green.
3. **Numbers, not text, plus a hint a person can act on.** Constants `ERROR_*` and pure predicates `stop_refusal_is_harmless` (1062, 1061), `start_refusal_is_harmless` (1056), `delete_refusal_is_harmless` (1072: already marked for deletion) and `service_error_text` (access denied 5: "run from an administrator session"; 1072: close Services/Event Viewer or restart) live in `install.rs` so they are tested on any OS; the adapter only calls them.
4. **`install_host` (addendum item 1).** `install::install_host(paths, executable, services, commands, sleep)` does `HostPaths::ensure()` (data directory, `tls`, `logs`, `backups`) BEFORE `icacls`, then `install` with `configured_port` (`host.json`'s port, else 45710). `main.rs`'s Windows `install_service` is just: paths, `current_exe`, `WindowsServices::connect`, `install_host`. Tested on any OS with fakes: the directory exists at the moment `icacls` runs, the configured port reaches the firewall script.
5. **Exit codes (addendum item 2).** `install`: 0 running, 1 failed, **4 = installed but did not stay up** (`InstallError::StoppedAfterStart`, usually an unfinished restore: the service stays installed with its restart policy, and `host.restore-intent` makes `start` refuse). This is an addition to the brief's "0 or 1": the NSIS hook (Task 5) needs it to treat the case as a WARNING with the restore hint; a hook that only tests `!= 0` still fails closed. `network-check`: 0 / 3 (`PUBLIC_REMAINS`) / 1; usage error 2. Pure functions `failure_code` and `network_check_code` carry the mapping and are unit-tested; the module doc of `main.rs` lists the codes for Task 5.
6. `stop-service` prints "MarkiroHost is stopped" / "is not installed"; `uninstall` prints where the data stays (it never takes a "delete data" option; there is none).
7. **CLI test through the real binary** (`host/tests/installer_cli.rs`): usage errors (exit 2); non-Windows refusals (exit 1, plain message); `network-check` against a fake `powershell.exe` on `PATH` (Unix only): public network -> exit 3 and listing, none public -> 0, `--make-private` that cannot help -> 3, failing PowerShell -> 1 naming the program, missing PowerShell -> 1.
8. Extra `network_profile` tests: nothing public + `--make-private` does not touch anything; every public network (not only the first) is changed; a failed change is an error and the list is not read again.

### Restore marker / service restarts (rk-task-5-report, rk-minors, ust-minors 2)

- `install` over an unfinished restore: configure + firewall + start succeed, the host refuses to start (marker), the wait ends in `StoppedAfterStart`, exit 4, service stays registered. Windows then retries every 60 s indefinitely (non-crash failure actions); each try takes the data-dir lock briefly, so an administrator's `restore` may meet "locked" once and must repeat. Runbook (Task 7): `sc stop MarkiroHost` first, wait for `STATE: STOPPED`, repeat on "locked".
- `stop-service` between two failure restarts sees `Stopped` and returns at once; Windows will start the host again within the 60 s delay. This cannot be closed in the seam without disabling the service; documented here for the runbook (restore needs the lock: repeat until it is free).
- `shutdown_runtime` (5 s) is unchanged and sits inside the 30 s the installer waits; an administrator `sc stop` / `stop-service` is a clean stop (exit 0) and does not trigger failure actions.
