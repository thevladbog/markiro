## Hardening beyond the brief (no change to the brief's interfaces except the optional `clock` prop)

1. **Press guard on every button** (2a7 lesson): a press is ignored for 400 ms after the view changed; the view key is phase + panel + job (id, state, attempts) + verifying, so the button that a job's new state puts under the finger (`Отправить` → `Повторить отправку` → `Напечатать ещё раз`) is held. Also on the picker (view = kind of label), the typed-code submit (preventDefault of the submit click), the leave button and `Повторить`. New optional prop `clock` (default `performance.now`), like `LabelPanel`/`ShiftClosePanel`. Focus goes to the view container (`tabIndex=-1`), never to a button.
2. **Work in hand holds buttons with `aria-disabled` + waiting style**, not `disabled` (keyboard focus is kept, as the other floor panels do); `disabled` stays only for "no reason chosen" / empty typed code (the brief's test needs it). The leave («К сменам») is never held by work (N9).
3. **No reload by parent re-render**: the session load effect depends on `attempt`, pairing and the queue only; `track`, `onRecorded`, `onHostError`, operator, context and `jobSaid` are read through a `live` ref. The brief's effect depended on `context`/`onRecorded`/`track`, so an inline callback from the parent would have re-run `load` and reset a half-made setup.
4. **`onRecorded` and `onHostError` are told even if the screen is gone** (job/record already written; a refused key is the shell's), only UI updates are gated by `alive`.
5. **Settle after an unexpected failure** (`settleAfterFailure`, inside the queue): `recoverWarehouseJob` re-reads the open job (a send cut by a failed final write becomes `unknown`/`interrupted`, never resent), the delivery is told, and when the job is `unknown` the screen says that instead of «Ничего не напечатано» (which would be false after the bytes went).
6. **Honest offline**: a persistent warning `floor.warehouse.offlineNotice` while `online` is false (in addition to the brief's per-scan `errors.offline`); new keys `offlineNotice`, `jobLine`, `jobState.*`. `jobLine` ("Задание: …") gives the job state in words next to the label (non-colour status, also after a restart); the chosen reason is said in words ("Причина: …") in every reasons view; on resume the "resumed" alert also carries the recovered job's state.
7. Templates button is held (aria-disabled, no action) while a job waits (brief only disabled it via `disabled`); typed-code submit with an empty value is ignored (Enter on empty field).
8. `show()` is exhaustive with no `default` branch.
