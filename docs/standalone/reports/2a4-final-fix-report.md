## Decided differently / deviations (for «Отклонения»)

1. **Mocks keep their own `.manage` calls.** The review said the mock apps drop the "duplicate" `.manage` calls. They do not duplicate anything: `manage_state` is called only by `run()` and by the one new test (on a mock app built without those states). The other mocks need custom `DeviceState`/`LocalDbState` (pre-paired, unavailable), so they were left as they were. `Manager::manage` on a handle returns `false` on a duplicate, it does not panic.
2. **Two `reach_with` tests ship in W2, not W1.** The seam (the connect gets what the lookup left) appeared while writing W2; its two tests are in the W2 commit with the code. RED is shown by mutant W2h.
3. **W1 alone does not compile `--lib` and `--test ipc`** (they call `send_all`, `resolve_with`, `manage_state`, which W2 adds), as the review's note "RED: it does not compile until W2" anticipates. Every other target compiles and passes at W1.
4. **Webview range check beyond "integer".** On the controller's instruction W3 also refuses out-of-range numbers in the webview (100..10 000), mirroring the shell's bounds (duplicated constants, the shell still enforces).
5. Chunk size 64 KiB is also applied to COM. For COM it changes nothing important (serialport's per-write timeout already reports partial progress); it is the review's choice (one `send_all`).
6. `print_to` TCP: with the budget spent by the lookup, the first attempt still happens with a zero timeout (`connect_with`'s existing rule), which std reports as `InvalidInput` -> `not_sent`. Safe direction.
