## Defects of the brief's code found and fixed (same classes as Task 7 / the dispatch)

1. **A set the shell would refuse could be stored** (control char in the port, name over 256, 33rd scanner): the shell refuses the WHOLE set (`invalid_scanners`), so at the next start every scanner stays closed because of one bad one. Now refused in the form with words, dropped on read, refused on save (validate first; the shell already validates before it mutates, `ScannerManager::configure`, and re-acknowledges an unchanged set).
2. **Scanner and serial printer on one COM port** (the dispatch's question): the scanner holds its port open, so print would fail `not_sent` and the scanner never connect. Refused both ways in the UI (scanner form names the printer; printer form names the scanner) and in `saveWorkstationSettings`.
3. **After the shell refused the set the operator could not give it again** (brief: dirty false after the DB write, Save disabled). Now Save stays active while `unapplied` (shell refused) or `unopened` (saved scanner the shell does not list and nothing was given since, e.g. refused at app start); the second press asks the shell only (no DB rewrite, tested: one transaction in total). `applied` stops the flicker between the shell's answer and its snapshot.
4. **Connection text was a lie for saved scanners** (brief: not in snapshot = «Подключится после сохранения»). Now: not equal to a saved scanner (port AND speed) = «after save»; saved + no first answer = «Проверяем связь…»; watch failed = «Состояние связи не прочиталось»; saved + not listed = «Оболочка ещё не открыла этот порт» (+ «Нажмите «Сохранить»» when retryable). The snapshot has only connected/disconnected and no error kind (checked `scanner/runtime.rs`); configure refusals are shown by words only, never `HardwareError.message`.
5. **Typed but never added port** was lost silently on Save/Back: Save is active, says «Нажмите «Добавить сканер» или очистите поле порта…», writes and asks nothing.
6. **Stale answers** (Task 7 class): the COM list uses an ask counter for success and failure; a late `watchScanners` answer after leaving is stopped (cleanup + `cancelled`).
7. **Double save / stale draft**: the Task 7 ref guard is kept through the shell call; the shell gets the SET THAT WAS SAVED (closure of the press), not a scanner added meanwhile (tested). «Назад» is never held by the shell's answer (tested).
8. **Focus**: «Тише»/«Громче» used `disabled` in the brief (focus lost at a limit) -> `aria-disabled` + no-op (tested; this changes the brief's `hasAttribute("disabled")` assertion to `aria-disabled`); removing a scanner moves the focus to the scanners heading; errors, the port list and the connection text are in persistent polite regions with `role="presentation"` Alerts.
9. «Громкость 0» was shown as «Громкость 0 %» although it plays nothing: now «Сигналы без звука» whenever `soundLevel === 0`. «Проверить звук» uses `soundLevel(draft.sound)`, the same `playSignalTone("ok", undefined, level)` the floor plays (module-mocked test checks the arguments).
10. Added a sentence to the check section: it applies to labels printed after saving (a job keeps its `verify`, Task 4/5): `floor.setup.check.later`.

## Concerns / for the reviewer

1. One boolean `verifyPrintedLabel` for all label purposes (see checklist); decide in ПЛ-Ц whether pallets need their own.
2. `FloorApp` reads the saved level once at open; a read that is slower than a whole setup visit would overwrite a newer `onSaved` level (theoretical).
3. A serial printer and a scanner on one port are refused only when both are in the SETTINGS; a USB-spooler queue whose port is a COM port is not known to the app.
4. Not exercised: real COM scanners, `list_serial_ports` on Windows, WebView2 audio, a browser, screen readers, touch.
