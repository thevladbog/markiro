## Design findings in the brief's own code (fixed; deviations)

Trap analysis found three real defects in the plan's `FloorApp`, each pinned by a test and a mutant:

1. **Dead idle lock.** The idle lock fires once and then waits for nothing (`active = false`). The brief's `leave` dropped any second reason while one waited (`leavingRef`), so an idle (or «removed») sign-out that fired while the operator was already leaving to the list was DROPPED and the lock never fired again: a station left open with a signed-in operator forever. Now `standing: Leave | null`; a sign-out upgrades a waiting non-sign-out leave, the first sign-out stands (L1, L1b–d, L2, L4).
2. **Stuck on a work screen the shell no longer holds.** `finish` did nothing for `line_changed` ("work_left already moved the station"). If the office moved the station back to its line while the leave waited (`device_refreshed` with the same line clears `pendingDevice`), `work_left` was dispatched, the shell had no work and nothing to change, and the screen stayed on the work view with `leaving: true` and a disabled button forever. Now `finish` returns to the list in that case too (when the line really changed, the reducer takes the floor away in the same batch) (L5, L6).
3. **Stale list after a turned-back entry** (my own gate, item 10 below): the list stayed mounted with the card it started from; now `ShiftList` is keyed by a counter, so it reads the copies again (G3, G3b).

Also deviations: the work screen's wait text sits in an always-mounted `aria-live="polite"` container (a live region created together with its text is not reliably announced; the brief's `{leaving && <p aria-live>}`) (WS1); `standing` ref replaces `leavingRef` and is reset when the drain ends (L3: a stale value would make every later leave a no-op — pinned by a test that enters and leaves three times).
