## Label correctness rules (AGENTS.md) - how each is held

- Expiry: no re-derivation; `boxLabelFields` of the domain uses `shelfLifeExpiryDate` (production day + N - 1). Tests: one-day shelf life (10.09 -> 10.09), leap day + 366 (29.02.2028 -> 28.02.2029), year boundary (31.12.2026 + 30 -> 29.01.2027), no shelf life -> empty expiry (values mirror the domain/handheld `box-label-fixtures.json`).
- Civil dates, not the PC's zone: production date is the shift's `YYYY-MM-DD`; a test sets `process.env.TZ` to UTC / Asia/Tokyo / Pacific/Honolulu with a box closed at 20:00Z (already the 9th in Tokyo) and gets the same 08.10.2026 / 17.10.2026 each time.
- Snapshot, not today's catalog: product, print name, GTIN, shelf life, counterparty come from `shift.snapshot`; test renames product/GTIN/counterparty in the copy and still gets the frozen values.
- DPI-neutral / printer's dpi and language: `withPrinterDpi(spec, printer.dpi)`; ZPL 203 -> `^PW464`, ZPL 300 -> `^PW685`, TSPL 300; compared with `generateZpl`/`generateTspl` of the domain (the same code the office preview uses) and with exact literals.
- GS1 exactness: SSCC stays the bare 18 digits in the fields; exact-byte test pins the stock label's `^BCN ... ^FD>;>800046006820000035007` (GS1-128 with FNC1), `(00)046006820000035007` HRI, TSPL `BARCODE ... "!100046006820000035007"`. No `\u001d` appears in a box label (no KM). Raw scanner values do not enter this task.
- Bytes: 1 code unit = 1 byte; test asserts TSPL has six 0xFF bytes and no 0xC3 (no UTF-8).
- Fonts: nothing added; the rasterizer is the existing bundled-IBM-Plex one. No CDN.
- "Same model/code path as preview": `renderLabel` calls the domain emitters and the app's `rasterizeText` (the preview's rasterizer); no second renderer.
