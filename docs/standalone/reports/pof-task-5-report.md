## What was done

1. Tests first (RED recorded), then the implementation. TS: `print-form.ts`, `OfficeFilesApi.openFile`, test support `fakeOfficeFiles`.
2. Security model of `open_office_file` (the ЧЗ Task 7 precedent, applied in one pass before any action):
   - `existing_form(root, segments, name)`: the first segment must be `Формы` (`FORMS_ROOT`; the brief allowed any root of `ROOTS`, this is stricter: the parts of an export are data, never started); the name must pass `is_plain_file_name` (letters/digits of any script, space, `-_.()`, no device names, ends in a listed extension) AND its extension must be `html` (any case); only then `existing_folder` (the segments through `check_segments`: root in `ROOTS`, 2..8 segments, every one a plain name, so no `..`, `/`, `\`, `:`, drive, UNC; every folder on the way is walked with `symlink_metadata`, a link/junction/file refuses); the file itself is checked with `symlink_metadata`: only a regular file (not a link, not a folder, not missing) is returned. Everything refuses with the bare `invalid_request`; an I/O error other than NotFound is `storage` (logged by kind, never a path).
   - Launcher: ONE Windows code path, `launch_explorer(target, what)`, now shared by `show_in_explorer` (folder) and `open_in_default_program` (file). It uses the already reviewed testable builder `explorer_launch(target, system_root) -> Option<ExplorerLaunch{program, argument, current_dir}>` (compiled on every OS under `cfg(any(windows, test))`): absolute `%SystemRoot%\explorer.exe` (fallback `C:\Windows`), the path in double quotes handed over with `raw_arg`, starts in the system folder, no shell string, a path containing `"` is no launch. Off Windows both are `unsupported`.
   - Files the office writes are now created with `OpenOptions::create_new` + mode `0o600` on Unix (`create_new_file`), because the HTML holds the organization's products and codes (applies to exports too; Windows keeps its own ACLs).
3. Webview (`src/office/forms/print-form.ts`):
   - `printInFrame(html, doc, print)`: one hidden `iframe` (`PRINT_FRAME_ID`, `aria-hidden`, `tabIndex -1`, 0x0) with `sandbox="allow-same-origin allow-modals"` (NO `allow-scripts`: a script that got in through the data does not run; `allow-modals` because a sandboxed document's `print()` is refused without it). The `about:blank` frame inherits the window's CSP (`default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'`): inline styles/SVG, no network. HTML written with `document.open/write/close`, then the `afterprint` listener (registered AFTER `open`, which erases a window's listeners), `view.focus()`, `print(view)`. The frame is removed on its own `afterprint` (closure over its own frame, so a late event of an older print cannot remove a newer frame), on a failing print (rethrown), and replaced by the next print if `afterprint` never comes. No blob / object URL is made, so there is nothing to revoke. Works offline (system Arial and inline SVG barcodes of the domain forms; nothing is fetched).
   - `formFolder`, `openInBrowser` as in the brief, plus `formFileName(name)`: the minors note says form file names carry the host's SSCC text, so the file is saved and opened under the SANITISED name (everything outside `\p{L}\p{N} _().-` becomes `_`, trailing dots/spaces trimmed, `.html` forced, stem capped at 100 UTF-16 units, empty stem becomes «Форма», a device name (`CON`, `COM1`, `LPT¹`…) gets the prefix «Форма »). The JS class is a subset of the shell's `is_name_char`, so anything it produces passes the shell. Every name `render-form.ts` makes is returned unchanged (tested), so the brief's `openInBrowser` test holds as written. `OfficeFilesApi.openFile(segments, name)` invokes `open_office_file`.
4. Names the forms make were verified against the shell's allowlist: Rust test `the_names_of_the_forms_are_taken` saves and re-finds all ten file names `render-form.ts` can produce (incl. «без SSCC» and the empty-SSCC placard `Ярлык паллеты  A5.html`) under a sanitised shift number.

## Self-review / concerns

1. `FORMS_ROOT`-only opening is stricter than the brief ("a folder of ROOTS"); nothing else in the plan opens a file.
2. `Печать` relies on a synchronous `print()` right after `document.close()` (Blink defers printing until load completes). In a browser where `print()` returns immediately and `afterprint` fires early the frame could go before the spooler has the page; not observable here.
3. Opening an `.html` in the default browser executes its inline `<style>`; the form's HTML contains no script (domain forms are static; the data is escaped by the domain). The saved bytes are the domain's (no CSP meta is injected, to keep byte parity); the browser path therefore has no CSP, only the escaping.
4. Unix owner-only mode is a small hardening of every office file (exports too), beyond the brief; Windows is unaffected.
5. The 240-unit path bound from ЧЗ applies to form paths too; a very long shift number is already sanitised by `exportFolder`; a refusal surfaces as `OfficeFilesError("invalid_request")` for the dialog (task 7) to show.
6. `rtk` was not an obstacle; scratch files live only in `/tmp/claude/impl-pof-t5/` (harness, backups, probe, logs); the tree is clean after the commit.
