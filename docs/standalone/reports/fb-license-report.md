## Что пришло от владельца

В автономе нет ни лицензии, ни штатного обновления. Решения владельца: лицензия на площадку, подписка, обновления только вручную из файла, обращений в интернет нет. Позже добавлено: один пункт «Информация» в разделе «Сервис». Его каркас делает `claude/fb-about`, а разделы «Лицензия» и «Обновление из файла» встраиваются в него.

## Что в спецификации

- Отдельный файл, а не §32 пилотной спецификации: её §18–31 — уточнения уже написанных планов пилота.
- §2: исходное состояние по коду — `hostId` (config.rs), идентичность I1, `hello`/протокол, `db::open` → `MIGRATOR.run` (копии перед миграциями нет), путь обновления в хуках NSIS, release-evidence, прецеденты: `latest.json`/minisign облачной станции и JWS офлайн-грантов. Ed25519 есть в `aws-lc-rs` и `node:crypto`, новых зависимостей не нужно.
- §3: состояния trial / active / expiring / grace / restricted / wrong_host, таблица маршрутов «закрываемые / никогда». Закрываются только открытие запланированной смены и создание смены станцией. Повторный вход владельца, факты, блоки, выгрузки и копии не закрываются никогда. Тест классификации маршрутов.
- §4–5: конверт `markiro-signed-v1`. Подписываются точные байты полезной нагрузки, поэтому канонизация JSON не нужна; есть разделение контекстов license/update. Описаны поля, порядок проверки, хранение в базе (переживает копии; `restore` переносит лицензии, как переносит отзывы), продление, сценарии I1, восстановления без идентичности и клона ВМ, ключи и их ротация, тестовые ключи за фичей с проверкой бинарника.
- §6: офлайн-инструмент `tools/standalone-license` (keygen, inspect-request, issue, verify, sign-update) и обмен «запрос активации ↔ файл лицензии» без сети.
- §7: время — отметка `max_seen` с монотонным пределом и `issuedAt` как нижней границей.
- §8: миграция, маршруты, аудит, логи.
- §9: страница «Информация» с пятью разделами и точками расширения Т1–Т5, баннеры, станция, тексты.
- §10: пакет обновления — тот же установщик и подписанный `.update.json`. Пакет подписывает владелец из черновика, который делает CI. Приложение само запускает проверенный файл через `runas`; установщик открыт без совместной записи, поэтому подмены не будет. Каждая база копируется перед миграциями (хост и оболочка). Описаны откат хоста, порядок «сначала хост», правила версий, запрет понижения версии, Authenticode, обещание «без интернета».
- §11–17: безопасность, тесты (автоматические и только для Windows), 6 планов, решения ЛО1–ЛО14, SaaS-админка, риски, что не проверено.

## Редакция 2 — раздача обновления через хост (решение владельца 2026-10-13)

Коммит `e857843c5` на `claude/fb-license`; prettier чист.

- Новый §10.11.
- Хранение на хосте (`updates\staged|current|previous`):
  - пакет загружает администратор через офис;
  - проверяется при загрузке, при продвижении, при каждом старте и перед раздачей;
  - в резервные копии не входит (размер, воспроизводимость, подлинность держится на подписи);
  - восстановленный хост пакет с `mismatch` или `invalid` не раздаёт.
- API устройства, только по ключу устройства:
  - `GET /v1/device/update`;
  - `GET /v1/device/update/installer` с `Range` и `If-Range`;
  - оба маршрута вне `protocol_guard`, чтобы устройство с `app_too_old` могло обновиться;
  - ограничители и строка `update.download` на скачивание с нуля;
  - `hello` не меняется.
- Устройство само проверяет подпись и хеш, сверяет версию пакета с `hello` и запускает установщик с UAC без `/ROLE`.
- Станция предлагает обновление только на хабе, ставит только администратор, автоустановки нет.
- Окно совместимости N−1 и экран жёсткого отказа с кнопкой «Обновить с хоста».
- Порядок раскатки и таблица «Устройства и версии» (Т5); учёт версий устройств (ЛО11) теперь обязателен.
- Планы: ОБН-3 в основной линии (12–14 задач), всего 54–65 задач.
- ЛО14 решён; добавлены ЛО15 (предзагрузка), ЛО16 (кнопка с UAC на экране несовместимости), ЛО17 (окно N−1).
