## What was done

Brief steps 1-3 in order (tests first, RED recorded, then implementation), with the EXTRAS requirements built in:

- `PrintFormDialog.tsx`, `form-printer-context.tsx`, `Office.tsx` (`printForm` prop, `FormPrinterProvider`), `office-query.ts` (`boxReport`, `shiftPalletReport`), `ShiftCardPage.tsx` (buttons «Бланк смены», «Ярлыки паллет смены», column «Формы»: «Состав» per box and pallet, «Ярлык» per closed pallet with an SSCC; paper A4/A5 choice kept by the card), `ru.json` (`office.shiftCard.*`, `office.forms.*`).
- Beyond the brief (all required by the dispatch's EXTRAS):
  1. **Fresh rows at the press.** The dialog reads the host's rows when it opens (a cached answer of an earlier opening is never drawn from: `reading = isPending || (isFetching && !busy)`), AND each press reads them AGAIN (`box.refetch()` / `pallets.refetch()`), and draws from what that read returned. For «Бланк смены» the press refetches the shift, products, lines, counterparties and organization (`queryClient.refetchQueries(..., {throwOnError: true})`) and rebuilds the inputs, so a renamed product or a shift closed since the card opened is printed/refused as it is now. «Сформировано» is the moment of the press (drawn after the paint wait).
  2. **Heavy work.** New `prepareForm` in `render-form.ts` splits data+file name (cheap, decides refusal) from `draw()` (the domain's HTML, heavy); `renderForm` = prepare + draw, output byte-identical (forms-parity untouched and green). The press shows a stage text in a polite region («Читаем актуальные данные…» / «Рисуем форму…» / «Сохраняем форму и открываем браузер…»), then `paint()` (a frame and a turn, at most 100 ms for a window that draws no frames) lets the window paint it BEFORE the synchronous draw.
  3. **Cancel on dialog close.** An `alive` ref is checked after the paint waits (and before anything is printed or saved); a closed dialog prints nothing and saves nothing. (A press already inside `openInBrowser`'s save+open cannot be cancelled between the two shell calls; the check precedes it.)
  4. **Refusals mirror the cloud**: the placard of a pallet not closed / without SSCC → «Ярлык печатается только у закрытой паллеты с SSCC.» (cloud 409 `PALLET_NOT_CLOSED`), no pallets to placard → «В смене нет закрытых паллет с SSCC: печатать нечего.», blank of a closed shift → «Бланк печатается только у запланированной или активной смены.», unknown pallet → «Паллета не найдена.»; both buttons `disabled`. Pallet taken apart → placard offered, watermark «РАСФОРМИРОВАНА» by the domain; the shift's placards leave it out.
  5. **Failures in plain Russian with a retry**: a failed read (open or press) → the `LoadError` with «Повторить» (host texts via `errorMessageKey`); a failed blank refresh → host text, buttons stay, next press retries; shell failures → `office.forms.files.*` (any non-shell error → `storage`); print failure → «Окно печати не открылось…»; «Показать папку» failure → text.
  6. **a11y**: buttons stay on the keyboard while busy (`aria-disabled`, not `disabled`; presses ignored while busy); one polite live region, on the screen before it is said into, holds progress, refusal, `taskUnavailable`, «Форма открыта…» and failures, whose Alerts are `role="presentation"` (no double announce); paper radios disabled while busy.
  7. **No leak into logs**: the dialog never writes to the console (a test spies on all five console methods across print failure, host failure, shell failure).
- `task-inputs.ts` (new): `taskFormInputs(...)`, shared by the card and the dialog's refresh.

## Self-review / concerns

1. **Not exercised by anything automated**: WebView2's print dialog for the sandboxed frame, A4/A5 by `@page`, `afterprint`, Explorer opening the `.html` (Task 5's concerns stand); a real host answer; the real look of the dialog in a browser (no browser check was made in this task).
2. **The draw is synchronous.** The progress text is painted before it, but a form with thousands of codes (box ~8 ms/code under load; pallet report 2000 boxes ~5 s) still freezes the window for that long: it is the domain's synchronous renderer. The dialog cannot cancel a draw already running; close-to-cancel works before the draw and before the save.
3. A press already inside `openInBrowser` (save then open) is not cancellable between the two shell calls; a closed dialog then still opens the browser for a file it saved. Smaller than the draw; not changed (Task 5's function).
4. The card's «Ярлыки паллет смены» button is decided from the card's own cached pallet list; if the station closes the first pallet while the card is open the button appears only after the card is read again (the dialog itself is always fresh). The card does not auto-refresh (Task 6 note).
5. «Бланк смены» «Сформирован» is Moscow time by parity (minors note); box/pallet forms use the organization's zone.
6. `refused.box` («Короб не найден.») is a dead key (a box always draws).
7. Full-package run could not be obtained green at default limits under load 100+ (10 timeouts in three load-sensitive files, all green when re-run alone); `Not implemented: navigation to another Document` appeared only in those loaded runs.
8. `graphify update .` was not run (`timeout` absent on this machine; the graph is git-ignored).
