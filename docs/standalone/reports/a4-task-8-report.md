## Print/label correctness (how the sheet is a document that accompanies a pallet)

- Order: a box that fills a pallet writes the box job and the pallet job in one transaction; the box label goes first (existing `readOpenJob` order), then the pallet's A4 sheet REPLACES the pallet's thermal label (one job per pallet close, one format per job, no double print). Pinned: `floor-work-pallet-sheet` (1 RAW send for the box, 1 driver send with `paper: "a4"`).
- Source: only the frozen snapshot (`palletSheet`, `organization`, `product`, the shift copy's production date). The station has no live sheet table (sheets are not in the feed), so nothing can read one.
- Once: one job per pallet close; a failed/unknown job is never sent by itself (`driver_unknown` → `unknown`, recovery moves nothing, `printAgain` without a reason refused; a job found `sending` after a restart → `unknown/interrupted`, no send). Tested through the real runtime with a fake shell.
- Reprint of a closed pallet (`reprintPallet`) = new job, same SSCC, same fields, same sheet bytes, one `pallet_exception` reprint record, no second `pallet_closed`.
- «Напечатать снова» / «Другой принтер»: new send only after reading the newest job in the transaction (existing 2a7/ПЛ-Ц rules, untouched); bytes reused only if mode, paper, language and dpi are the job's; A4 → thermal renders the snapshot's pallet template; thermal → A4 renders the sheet; box + A4 → `NoPrinterError`.
- Missing sheet / missing organization in the snapshot (disabled sheet is frozen as it is — Task 4; a sheet missing from the host table is frozen as none): the pallet closes, the job is `failed` `render_failed` with no bytes and the A4 printer kept, the panel shows «Этикетка паллеты не напечатана» with the new text, nothing is sent, «Другой принтер» prints the thermal label. Nothing is silently substituted.
- Required area: `renderSheetBytes` always carries real `requiredBounds` (asserted > 0 and inside the page), as Task 7's `sheet_draw_plan` requires.
