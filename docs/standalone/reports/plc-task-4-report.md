## Discipline carried over from 2a7/2a8 (beyond the brief's literal code)

- Reprint is not just "new job + exception": its transaction carries two comparisons (pallet still closed and whole; the job read is still the pallet's newest, by rowid like `LAST_BOX_JOB_SQL`) so a disassembly or a racing reprint landing between read and write makes it stale (`PalletUnavailableError` / `StaleJobError`) with nothing written and nothing sent. Without it the host would get a `pallet_exception` for a taken-apart pallet and answer `pallet_state` for good.
- The same guard sits in front of `printAgain`'s pallet exception (a pallet disassembled while its label waits: `StaleJobError`, job unchanged, no record).
- Disassembly: reason required (`reasonFields`), `disassembled_at` only while closed and not taken apart, boxes untouched; irreversibility/confirmation is the screen's (task 7) — noted in the doc comment.
- Template of another revision: `PalletTemplateChangedError` (instance of `PalletUnavailableError`, so the brief's contract holds) instead of an anonymous "unavailable".
- Pallet reprint pre-check (closed, whole) runs before the job is rendered: nothing renders for a pallet taken apart (tested with a render spy).
- Pallet label is never re-sent automatically (only `sendLabelJob` once, as a first send).
