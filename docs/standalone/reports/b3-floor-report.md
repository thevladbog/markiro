## Решения владельца, пришедшие по ходу (учтены)

- (A) «Отвязать станцию» — в «Рабочем месте», отдельным компонентом `UnpairStation`, монтируется одной строкой
  в подвале `WorkstationSetup` (правка `src/floor/setup/WorkstationSetup.tsx`: 1 импорт и 1 строка).
  Полномочие — то же подтверждение личности, что для выхода из полного экрана.
- (B) Выход из полного экрана разрешён и оператору, но после свежего подтверждения личности: бейдж либо табельный
  номер + PIN, через путь входа (`signInWithBadge` / `signInWithPin`, те же счётчики блокировок). Вход администратора
  офиса на этом ПК работает как раньше. Это меняет решение плана 1f2 «оператор не выходит из киоска» — обновлён
  `apps/standalone/AGENTS.md` (раздел о киоске); ни одно прежнее утверждение теста не ослаблено: прежних тестов
  «оператор не может выйти» в репозитории не было (киоск проверялся только офисным `WindowModeButton`).
- (C) Панель «Синхронизация» — да.

## По пунктам владельца

### 1. Кнопка выхода из полноэкранного режима в шапке

Было: на настроенной станции выйти из киоска мог только администратор через «Оконный режим» в офисе; в цеховой шапке
кнопки не было (облачная станция её имеет).
Стало: в правой колонке шапки (рядом с «Сменить оператора») иконка 64×64 `FloorWindowControl` — «Выйти из
полноэкранного режима» (в киоске) / «Вернуться в полноэкранный режим» (в оконном). Показывается только там, где
таблица окна запирает ПК (`due`): не на хосте/офисе, не в разработке, не на ненастроенной станции. Выход — через
`Reconfirm` (бейдж либо номер+PIN; при вошедшем операторе — только его собственное подтверждение, на экране входа —
любого оператора; подтверждение никого не «входит»). Путь назад — без подтверждения. Пока диалог открыт, экраны цеха
не слышат сканы (`createGatedScanSource`), чтобы бейдж не приняли за код продукта.
Файлы: `src/floor/FloorWindowControl.tsx`, `Reconfirm.tsx`, `reconfirm.css`, `gated-scan-source.ts`,
`FloorStatusBar.tsx` (проп `tools`), `operator-switch.css`, `src/app/App.tsx` (`floorWindowMode`, `floorGate`, `floorTools`).
Тесты: `test/floor-reconfirm.test.tsx` (подтверждение бейджем, номером+PIN, неверный PIN, блокировка после 5 попыток
тем же счётчиком, чужой оператор, отмена, mute источника, выход/возврат, ошибка окна), `test/app.test.tsx`
(«the floor's own controls…»: полный цикл выхода/возврата с командами `exit_lockdown`/`enter_lockdown`, экран входа,
не показывается в разработке).

### 3. «Отвязать станцию»

Кнопка в подвале «Рабочего места»; диалог с последствиями (справочники с PIN/хэшами бейджей, смены и счётчики
попыток уходят; неотправленные записи остаются на диске и на хост не уйдут — с числом; хост, восстановленный из
копии, ждёт блоки SSCC — предупреждение), нельзя при открытой смене, затем `Reconfirm`, затем тот же `device_forget`
(`clear_copies`) с `keepUnsent`, если есть/не посчитаны неотправленные. Контекст `UnpairContext` отдаёт `App`.
Rust: `device_forget` теперь удаляет и копию БД до обновления (`standalone-station.pre-*.db`/`.partial` с `-wal`,
`-shm`, `-journal`) — `LocalDbState::remove_pre_upgrade_copies`; сбой удаления -> `storage`, `device.json` остаётся
(принято владельцем в ОБН-1, вопрос Д9 закрыт в AGENTS.md).
Файлы: `setup/UnpairStation.tsx`, `unpair-context.ts`, `unpair-station.css`, `WorkstationSetup.tsx` (1 импорт +
1 строка), `src-tauri/src/local_db.rs`, `src-tauri/src/lib.rs`.
Тесты: `floor-reconfirm.test.tsx` (6 тестов на «Отвязать»), `app.test.tsx` (через «Рабочее место» -> `device.forget`),
Rust: `tests/local_db.rs` (удаляет все pre-файлы и только их), `tests/ipc.rs` (копия остаётся при откате очистки и
уходит с подключением).

### 4. «Синхронизация»

### 5. Горизонтальный скролл при выборе продукции

Причина: строки результатов поиска были `nowrap`-кнопками внутри `.new-shift__search { overflow: auto }`, длинное
имя раздвигало панель. Сейчас имя — отдельный элемент с многоточием, GTIN целиком, полный текст в `title` и
`aria-label`; `overflow-x: hidden` у панели; кнопки шаблонов — то же; заголовок карточки товара — 2 строки с
многоточием и `title`. Проверено в браузере 1280×1024 и 1024×600 (длинное имя ~130 символов): `scrollWidth ==
clientWidth`. Файлы: `NewShift.tsx`, `shift-hub.css`. Тест: `floor-new-shift.test.tsx`.
Карточка смены на хабе уже обрезала названия (`-webkit-line-clamp`), её не трогал.

### 6. Нет фото продукции

Причина: станция фото не получала вовсе («standalone keeps no product photos»): оно не было ни в ленте, ни в
снимке смены, а байты отдавались только офисным маршрутом. Добавлено «установленным способом»:

- Хост: миграция **0027** (`products.photo_rev`; не `products.rev`, потому что `rev` — `expectedRev` офиса, а диалог
  товара грузит фото и сохраняет товар после — иначе «stale_revision»); смена/снятие фото берёт ревизию и будит
  станции; лента переотправляет товар на `photo_rev` с `photoChecksum` (`FEED_KEYS`); новый маршрут
  `GET /v1/device/products/{id}/photo` (ключ устройства; в `license/gate.rs` `NEVER`).
- Протокол: `ProductRecord.photo_checksum` (`serde(default)`) + Zod `photoChecksum` (`default(null)`), фикстура
  `changes-catalog.json`; `SYNC_SCHEMA_VERSION` 5 (`ENTITY_SET` …`;v5`).
- Станция: shell-миграция **0017** (`ref_products.photo_checksum`, таблица `ref_product_photos`, base64 до 400 000
  символов = JPEG до 300 000 байт, `Disposable`: «Забыть» очищает), `syncProductPhotos` после каждой успешной
  синхронизации справочников (до 25 за проход, сбой не валит синхронизацию, повтор с тем же backoff), `ProductPhoto`
  показывает фото на карточке смены и на карточке товара новой смены; без фото, при сбое чтения и при
  недекодируемой картинке — монограмма на цветной панели (как раньше).
  Прежнее решение изменено: тест хоста «фото не берёт ревизию» (`product_photos.rs`) теперь «берёт одну ревизию, но не
  `rev` товара»; ожидаемые ленты в `host/tests/{changes,products,templates}.rs` получили `photoChecksum`.
  Тесты: Rust `host/tests/product_photos.rs` (+3: лента с контрольной суммой, сохранение товара после загрузки фото,
  маршрут устройства), Vitest `test/product-photos.test.tsx` (12), `app.test.tsx` (фото докачивается после синхронизации),
  `reference-sync.test.ts`, `local-executor.test.ts`, `src-tauri/tests/local_db.rs` (набор таблиц, 0017 в сравнении
  схемы).

## Вопросы владельцу

1. Подтверждение личности при вошедшем операторе принимает только его собственный бейдж/PIN (чужой — «подтвердите
   своим»). Если нужно, чтобы выход/отвязку подтверждал любой оператор (например, мастер смены), это одна проверка
   в `Reconfirm`.
2. Номера миграций: хост 0027, станция **0017** — если параллельный поток (b3-setup) тоже берёт 0017, при слиянии
   нужно перенумеровать одну из них.
3. «Последнее обновление справочников» считается с запуска приложения (у `SyncState` времени нет); после
   перезапуска до первой синхронизации написано «ещё не обновлялись».
