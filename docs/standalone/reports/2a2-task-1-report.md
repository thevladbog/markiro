## Findings and concerns (for the controller / later tasks)

1. `box_membership_digest` does not validate; the domain throws on a malformed hash or a duplicate. Parity holds only for input the host has already checked (`is_code_hash` and distinctness). Tasks 4/5 (`box_closed`) MUST check the incoming hashes (`is_code_hash`, no duplicates) before digesting, and answer `invalid_record` rather than comparing the digest of garbage. Pinned: duplicates are kept (E4), and the Vitest test shows the domain refuses them.
2. The `time` crate parses a real leap second (`23:59:60`) and `written == text` is the only thing that rejects it. Do not loosen that comparison. M2 and E10* pin it.
3. `fact-receipt-codes.json` and `exception-reasons.json` are read only by Rust in this task (the comment in `fixtures.rs` says «as the webview reads them»; that is true only after plans 2a6/2a8). A code added in the domain/webview alone is unpinned until then. The reason codes have no domain constant to compare with (grep of `packages/domain` finds none).
4. `record_digest` relies on serde_json being built WITHOUT `preserve_order` for every feature set the host is built with. `cargo tree -e features -i serde_json --workspace` shows only `default, std, alloc, raw_value, unbounded_depth`; the key-order test (plan) and the nested/non-ASCII tests (mine) fail loudly if a dependency ever turns it on. Numbers: `1` and `1.0` are different digests by design (a sender that re-serializes integers as floats gets `payload_mismatch`); the TS station must send integers as integers.
5. Plan counts: host `fact_rules` 12 and Vitest +50 instead of the plan's 5 and +35; later tasks' «Expected» totals for the host and Vitest are shifted by +7 and +50 respectively (proto unchanged). The three rules fixtures were NOT changed for this reason.
6. Environment: the whole-package Vitest run is timing-sensitive while a cargo run is in progress (19 5-second timeouts in unrelated files); run them one after the other.
7. Not run: the delayed-`setImmediate` stand (not applicable, no effects); no browser, no hardware; CI not exercised (no push).
