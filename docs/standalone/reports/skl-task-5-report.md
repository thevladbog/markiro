## Deviations and hardening beyond the brief (no semantic change to the brief's interfaces)

1. **A reprint never makes a new identity.** `sourceFields` now also refuses (as `incomplete_km`) a record whose stored code does not hash to the identity it was found by (`kmHash(km) !== source.identity`) and a box or pallet whose `sscc !== identity`. The host could in theory answer a different code under the right hash; the printed bytes are now provably the looked-up unit's. The tests also assert that the renderer receives exactly the looked-up code or SSCC, that a record to the host carries only the hash (no `Tail` or full code), and that a unit, a box and a pallet reprint change no table outside `wh_*`.
2. **Category list that does not parse fails closed.** The brief's `readJson(...)` returned `null` for a corrupt `category_codes`, i.e. «every category» (fail open). Now the template is unreadable (`spec: null`, so `template_unavailable`).
3. **`wh_jobs_open` race.** If the insert fails because another job took the one place meanwhile, `prepareWarehouseJob` answers `refused: busy` (only for a `LocalDbError` with an open job present; anything else is rethrown).
4. **Attempt bound.** `MAX_WAREHOUSE_ATTEMPTS = 10000` (the host's limit) and `WarehouseAttemptsError`: a send beyond it is refused before anything is written or sent, because the host would refuse the record forever and the session could never be accepted/purged.
5. The records are checked against the host's strict rules in tests (`warehouseRecordSchema` plus: attempt at most 10000, subject/identity/template text 1-64 trimmed with no control chars, `errorCode` null exactly for sent/verified/cancelled and `^[a-z_]{1,64}$` otherwise, `occurredAt` exactly `toISOString`, keys `repair/errorCode/operatorId` present). Every failed/unknown code (`FAILED_CODES`, `UNKNOWN_CODES`, `interrupted`, `printer_unconfigured`, `render_failed`) is checked to be a lower-case word.
