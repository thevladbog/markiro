### Responsiveness, focus, keyboard (UI attention list)

- Plan in turns with words «Проверяем, какие форматы доступны: N из 12…» in a polite `role="status"` region; formats, counts and pallets appear when the plan is ready; a failure of the check is said with its kind and the submit stays off.
- Export: reading -> (turn) forming -> (turn) saving -> recording, each phase in the same status region («Читаем данные смены…», «Формируем файлы…», «Сохраняем файлы…», «Записываем выгрузку в журнал действий…»). The turn before forming lets the words paint before the synchronous render; the turn before saving lets a click made during forming be handled before anything is saved.
- Cancel: «Отменить формирование» during reading and forming (Escape and the overlay do the same there); it wakes a pending read at once (`Promise.race`), so a host that never answers cannot hold the dialog; nothing is saved or recorded; after the files start to be saved there is no cancel, Escape/×/overlay/«Закрыть» do nothing, and a second export cannot start (ref guard plus disabled controls). «Записать снова» has its own guard.
- Focus: moved to the status region when an export starts (the loading submit becomes disabled), then to the result alert (`tabIndex=-1`, as the other pages' notices); Modal still traps Tab and restores focus on close.
- Warnings sit in one `aria-live="polite"` region and their Alerts are `role="presentation"` (2a5 lesson); results are their own alerts, not nested in a live region.
- Memory: the rows are read for the re-read through `session.call` (not a mutation, which would keep tens of MB in the mutation cache) and the cached export source is removed from the query cache when the dialog goes.
- Roles: every role; planned shifts have no button. The old 2a3 "closed shift has no/only figures" assertions: see below.
