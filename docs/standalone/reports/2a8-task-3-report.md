- `readCloseSummary(local, pairing, shiftId)`: plan of this pairing's copy now, codes held, closed (not taken apart) boxes, `reasonRequired` (`shiftCloseReasonRequired`), `blocker` in the order closed > `open_box` (with `items`) > `label` (count of `OPEN_JOB_SQL` jobs, counted not read so an unreadable job still blocks). No copy of the shift for this pairing -> zeros and `closed`.
- `closeShift(context, reason, guards?)`: summary -> blocker/reason checks (reason not one of the six domain codes -> `reason_required`; plan unmet and no reason -> `reason_required`; a reason given when not needed is kept) -> ONE `local.transaction`: `guards`, `DELETE` of this shift's empty open box, `outboxStatement(shift_closed)`, then the `UPDATE … SET local_state = 'closing'` that re-checks the summary with `expectedChanges: 1`; `changes_mismatch` -> `stale`, any other failure rethrown. `closedAt` and the record id come from the injected `context.now()` / `context.newId()` (ISO form with ms, which the host's `device_instant` accepts; the same instant is the outbox `created_at`).
- `outboxStatement`: now `INSERT … SELECT … WHERE NOT EXISTS (shift of this pairing with local_state)`, `expectedChanges: 1`, values extended by host, device, shift. After the mark, any writer's record of the shift (scan, box close, exception, reprint, label decision) fails its transaction with `changes_mismatch`; `shift_closed` is written before the mark in the same transaction, so it is always the last record.

## 2. Integrity points (dispatch list) and how each is held

1. Refusals with precise `CloseBlocker`s: open box with codes (`open_box`, `items`), waiting label (`label`), already closed/closing/closed or no copy (`closed`). Unsent records do NOT block (offline-first, plan §5.7.7 / decision 17): test "is not held up by the records of the shift that are not sent yet, and follows them" (earlier records stay `acked_at IS NULL`, `shift_closed` follows them).
2. Re-check inside the transaction (beyond the brief, see 4): plan (`planned_qty IS ?`), no waiting label (`OPEN_JOB_SQL`), no open box left after the DELETE, counts of codes and of closed boxes, each scoped to host AND device.
3. `outboxStatement` guard: killed by M1/M2/F1-F5.
4. Crash safety: one write (DELETE + record + mark); a close that committed but whose answer was lost, or a restart in `closing`: a second `closeShift` (even with the SAME record id) answers `blocked/closed`, writes nothing, outbox byte-identical (tests "closes once", "finds a second close with the same record id closed", "lets the close of a closing shift go on without a second record after a restart"). Delivery of the record is the existing sender's (Task 5 adds the `closing` -> `closed` receipt).
5. Record id idempotency + reasons list = the domain's six codes (every one closes, a stray string is `reason_required` whatever the plan).
6. Time from `context.now()` (mutant R5 `new Date()` killed); pairing scope: foreign pairings that differ in host only and in device only (seeded copies, boxes, codes, open box, waiting job of the SAME shift id) change nothing read or written.

`shiftLabelsSettled` (2a7 minors / final review (e)): the rule lives here as `waiting` in the summary and the `NOT EXISTS (… OPEN_JOB_SQL)` in the write; table-driven tests pin all seven job states x check flag (waiting: prepared, sending, failed, unknown, sent+check; settled: sent without check, verified, skipped), also as a job appearing between summary and write. 2a6 (e) / N9, N12, N13: the summary is read separately from the write, which is safe only because the write re-checks it; the caller (Task 4) must still run `closeShift` as a queued, tracked job (concern 3). ## 4. Beyond the brief (each with a failing-first test and a mutant)

- **Plan pin** (`s.planned_qty IS ?`): the host sync (`replaceShiftCopies`/`UPSERT`) rewrites `planned_qty` of an active shift outside the work queue, so the plan can change between summary and write; without the pin the record would carry the plan it saw and a `reasonCode: null` for a plan that is no longer met. Now `stale`, the summary is read again (-> `reason_required`). `IS` (not `=`) so a null plan works. Mutants N1, N2.
- **No open box left** after the DELETE (`NOT EXISTS … closed_at IS NULL`): the counts of codes/closed boxes alone do not see a box whose counter moved from outside the queue; without it a box that held no code at the summary and holds one at the write (a writer outside the queue) leaves the counts of the shift equal, and the shift would be marked closing with an open box in it. Mutants U7/U7b/D5 (D5: dropping `item_count = 0` from the DELETE would delete a box that holds a code; the guard test kills it).
- Disassembled boxes excluded from the closed count in the write too (U6c; test uses a closed box with a zero counter, because a box with codes is already caught by the codes count).
