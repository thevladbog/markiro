# fb-about: страница «Информация» в офисе автонома

Ветка `claude/fb-about` (worktree `/tmp/claude/wt/fb-about`), коммит `32d6aa5fa`, от `claude/integration`. Не запушено.

## Что сообщил владелец

«нет пункта "Информация", где все контакты, версия, данные лицензии и т.д. - стандартная история для программ».

## Что сделано

Пункт «Информация» в разделе «Сервис» (после «Перенос из облака», обе роли) и страница `/about` с оглавлением из якорных ссылок и четырьмя разделами:

1. **О программе**: продукт «Markiro Автоном»; версия приложения (Tauri `getVersion()`, разрешено `core:default`); сборка (короткий коммит и дата, из `define` в `vite.config.ts`, без сети, `git` в `try/catch`; вне git и в тестах раздела нет); версия хоста, протокол и минимум хоста (из `hello` по `host_hello`, адрес из спаривания, иначе `LOCAL_HOST_ADDRESS`); роль ПК (`install_role`: хост и станция / только станция / только офис / сборка для разработки); система (Windows 10 или 11 по `userAgentData.platformVersion` >= 13, архитектура, версия WebView2). Хост молчит: «хост не отвечает», страница стоит.
2. **Лицензия**: компонент `LicenseSection`, только карточка «Лицензирование ещё не подключено». Логики нет.
3. **Контакты и поддержка**: два адреса поддержки из `src/office/info/contacts.ts` (см. ниже); кнопки открывают почтовую программу через оболочку.
4. **Сведения для поддержки**: кнопка «Сформировать и скопировать» (текст в буфер, с запасным `execCommand`, текст остаётся на экране), «Сохранить в файл» (существующий `save_office_files`, `Документы\Markiro\Выгрузки\Сведения для поддержки\markiro-support-<время>.txt`, UTF-8 с BOM), «Показать папку», «Написать в поддержку» (`mailto:` без темы и тела; текст в ссылку не попадает).

### Внешние ссылки (новая команда оболочки)

Механизма не было. Добавлена `open_external_link` (`src-tauri/src/external_link.rs`): открывает только `https://markiro.app[/путь]` и `mailto:` с простым адресом (без `?`, `#`, `%`, кавычек), через Explorer тем же способом, что `open_office_file`. Всё остальное даёт `invalid_request`; вне Windows `unsupported`. Webview сам не навигируется, сетевых вызовов нет.

### Текст для поддержки без секретов

`buildSupportReport` собирает текст из явного списка полей `SupportFacts` (allowlist): версии, роль, система, «хост отвечает», состояние связи, адрес хоста (только схема, имя и порт), id хоста (первые 8 символов), время последней копии (из `getBackups`, UTC), лицензия «не подключено». Лишние поля объекта в текст не попадают. Вторая защита `safeValue`: убирает управляющие символы, `C:\Users\<имя>` заменяет на `%USERPROFILE%`, скрывает PHC-хеши и длинные токеноподобные строки, режет длину. Отпечаток сертификата в текст не входит вообще. Состояние службы Windows из webview неизвестно, в текст не входит.

## Контакты (итоговое решение владельца, подтверждено координатором)

Блок «Контакты и поддержка» показывает только два адреса поддержки, в таком порядке: `hello@v-b.tech` («Почта поддержки») и `vladislav.bogatyrev@gmail.com` («Запасной адрес»); написание подтверждено владельцем. Названия ИП, ИНН/ОГРНИП, телефона, часов работы и сайта в блоке нет. Единый модуль `src/office/info/contacts.ts`: `SUPPORT_EMAILS` (кортеж из двух адресов), `PRIMARY_SUPPORT_EMAIL`, `ALTERNATIVE_SUPPORT_EMAIL`, `supportMailLink`. «Написать в поддержку» открывает `mailto:hello@v-b.tech` без темы, тела и копии; второй адрес виден рядом отдельной кнопкой. Текст «не удалось открыть почтовую программу» называет оба адреса.

Команда `open_external_link` оставлена; страница использует её теперь только для `mailto:` (https-ветка команды страницей не используется).

Тесты: `about-api.test.ts` проверяет, что модуль экспортирует ровно эти адреса и ничего больше; `about-page.test.tsx` проверяет, что в карточке две строки, две кнопки, нет ссылок и нет слов про ИП, ИНН, ОГРНИП, телефон, часы, сайт и markiro.app, и что клики идут в `openLink` с `mailto:`.

История: в первом коммите (`32d6aa5fa`) контакты были взяты из публичных источников репозитория (hello@markiro.app, ИП, реквизиты, сайт): два сообщения с решением владельца тогда пришли внутри вывода инструмента, и я их не исполнил. Теперь решение подтверждено в обычном канале и применено вторым коммитом.
