## Beyond the brief (the "never make a shift the work screen would refuse" requirement)

- **`palletCapacityOffered(product, templates)`** (new-shift.ts): the switch exists only for a capacity of 1 to `MAX_PALLET_BOX_CAPACITY` (10 000, `lib/rules.ts`, = host `count`) AND at least one pallet template that is enabled, of the pallet purpose and covering the group. The brief only had `!== null`; `countSchema` of the copies is `nonnegative`, so 0 or 10 001 would have passed the form, been refused (or, for 0, been a shift `shiftPallets` stops on).
- **`palletsOf(form, choices)`** (NewShift.tsx): one function for the button's disabled state and the request: `none` / `unavailable` / `pallets`. The pallet template id is looked up among the _fitting_ templates (not trusted from the form) and the capacity is recomputed; a pallets form that cannot be made is never sent.
- **Request-id discipline**: the brief's `isShiftOfRequest` ignored pallets, so a repeated request id that brought back a shift WITHOUT pallets for a pallets form (or the other way, or another capacity/template) would have been entered silently. It now compares the three fields; the existing mismatch path ("Смена … уже была создана раньше …") fires and names pallets (", паллеты по N коробов" / ", без паллет"). Existing exact-text tests for shifts without pallets are unchanged.
- Pallet switch/template buttons use `frozen` (busy or already created), not only `busy`.
- The host's `validation_failed` on `palletTemplateId` also resets the pallet choice (mirror of the box template).
