### Deviations from the brief's code (all in `OperatorSignIn.tsx`, each covered by a test and a mutant)

1. Late answers are dropped (review note a). The screen keeps `alive` (mounted) and `current` ({hostId, deviceId, lineId}) refs, both written in layout effects so they are right the moment a commit lands. After a check, if the screen is gone, nothing is dispatched or set; if the pairing or the line it started with changed, `onSignedIn`/`onSync`/the message are skipped, and only `busy` and the PIN are reset.
2. NEW OPTIONAL PROP `lineId?: string | null` (not in the brief's interface). The brief's `pairing` has no line, so «compare the pairing and the line you started with» was impossible without it. It is optional, so the plan's Task 6 code compiles unchanged, BUT the line check is inert until Task 6 passes `lineId={status.lineId}` (same for `key`ing/resetting). **Controller: please add `lineId` to the Task 6 wiring.**
3. The PIN is cleared after EVERY completed check (success, refusal, lockout, database failure), not only after a refusal: after a success the parent may not unmount (a reducer that refused the stale sign-in), and dots must not linger.
4. `scan.current = attempt` is synced in `useLayoutEffect` (was a passive effect) so a scan right after a re-render uses the new pairing, never a stale closure.
