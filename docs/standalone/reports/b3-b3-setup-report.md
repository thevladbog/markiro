# b3-setup: «Рабочее место» станции (бета 3)

Ветка `claude/b3-setup` (worktree /tmp/claude/wt/b3-setup, от claude/integration).

## По пунктам владельца

1. **Сканер: нет выбора COM-порта.** Команда перечисления портов уже была (`list_serial_ports` в `src-tauri/src/scanner.rs`, `hardware.listSerialPorts`), но экран только печатал список текстом по кнопке. Теперь вкладка «Сканер» (и COM-принтер в форме принтера) сама спрашивает порты при открытии и показывает их в своём searchable-списке `ComPortField` (новый `src/floor/setup/ComPortField.tsx`): «Выберите порт» / порты / «Ввести вручную…». Ручной ввод — текстовое поле «Название порта»; если портов нет или список не прочитался, поле остаётся обычным текстовым «COM-порт сканера» (запасной вариант). Кнопка обновления — «Обновить список портов» (и в форме COM-принтера). Rust не менялся (cfg/Windows-кода не добавлялось), скорость и прочее как раньше.
2. **«Снова не наши селекты».** Корень: `Select` из `@markiro/ui` при `size="floor"` ВСЕГДА рендерил нативный `<select>` (плюс экран ставил `native`). В `packages/ui/src/components/Select.tsx` добавлен флаг `custom`: при floor-размере рисует собственный (Radix) список в касательных размерах (триггер и пункты >= `--control-floor` 64px, шрифты floor; поиск тоже). Без `custom` поведение прежнее, облачная станция (`apps/station`) не затронута. Все 7 списков экрана переведены на `custom` (разрешение, подключение, принтер Windows (теперь с поиском), способ печати, бумага, язык, три назначения). Аудит всех экранов `src/floor` и `src/hardware`: других `<select>/<input>/<button>/native` нет (остальные экраны используют только Button/Input/Alert/DataTabs/PinPad и т.п.). Страж: `test/floor-controls.test.ts` (как office-controls, плюс проверка что у каждого floor-`Select` есть `custom`).
3. **Название принтера по умолчанию.** Новый принтер открывается с «Принтер N» (наименьший свободный N среди имён списка). При выборе принтера из списка Windows название становится его именем, пока оператор не ввёл своё (флаг `nameAuto` в `PrinterDraft`); поле редактируется. Код: `printer-draft.ts` (`nextPrinterName`, `newPrinterDraft`, `settleDraft`).
4. **Текст не влез в «Обновить список принтеров».** Кнопка занимала узкую колонку сетки (185px). Теперь она и список принтеров занимают всю строку формы (`setup-printer-connection__wide`), `white-space: nowrap`; на 1024 проверены все кнопки экрана (нижний ряд: подпись «Проверять этикетку короба» остаётся в одну строку, пояснение-статус визуально скрыто на <=1100px, остаётся для скринридера).
5. **Проверка печати этикеток и А4.** «Пробная печать» была, но на экране ломалась вёрсткой (п.6) и результат был виден только внизу. Для каждого принтера (в т.ч. А4 через драйвер: тестовый лист с SSCC и предпросмотром; термо: тестовая этикетка Code 128) кнопка есть; добавлен чип результата прямо в строке принтера (Отправляем… / Отправлено / Печать подтверждена / Код не тот / Не напечатано / Не подготовлено), подробный текст остаётся в нижней строке. Отдельных тестовых этикеток «короб/паллета/дубль» нет: пробная этикетка одна на принтер и не зависит от роли (решение: роль меняет только маршрут, формат один; для А4 печатается лист паллеты) — сообщите, если нужна отдельная по ролям.
6. **Принтер «в один символ в строку».** Строка принтера была flex: слова + три кнопки рядом с `overflow-wrap: anywhere` — на узкой колонке слова схлопывались до буквы. Теперь строка — сетка: слова сверху, три кнопки (Изменить / Пробная печать / Удалить) одной строкой на всю ширину; `overflow-wrap: break-word`. Аналогично поправлена строка сканера. Просмотрено на 1280×1024 и 1024×600: колонки не схлопываются, карточки прокручиваются.
