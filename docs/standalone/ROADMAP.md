## 2. Решения владельца (кратко; полный текст в ledger/OWNER-DECISIONS.md)

- Стратегия: после MVP — ТСД на хосте и одновременно сворачивание веб-контура; подписант ЧЗ встраивается в офис автонома;
  Postgres в автоном не тащим; on-prem из облачного кода только по приходу крупного клиента; облачную станцию не замораживаем,
  нужное форкаем в автоном. Один завод, несколько кабинетов; сеть площадок не нужна. Роли офиса пока admin/technologist.
- Лицензия: на площадку, подписка; ВСЕ рекомендации спецификации приняты (ЛО1–ЛО27): мягкое применение (открытую смену не
  останавливать; после льготного срока запрет только новых смен), пробный период 14 дней, подписанный файл (JWS ES256) = выгрузка
  снимка прав SaaS-админки, привязка к hostId и сверка по ИНН, места по видам устройств при сопряжении, апгрейд файлом с большим
  sequence, обновления ТОЛЬКО вручную из файла + раздача через хост (окно совместимости N−1). Офлайн-лицензия для контрагента без
  кабинета (флаг «Офлайн», без доступа в облако); tenantId — произвольная строка 1–64 `[A-Za-z0-9._:-]`; подписка без даты
  окончания = файл на год, новый бесплатно по запросу. Логотип компании = функция лицензии `customLogo` (часть тарифа И доп).
- Режимы смены: два режима «Агрегация»/«Проверка», при «Проверке» флаг «Печатать дубликат Data Matrix» (+шаблон, обязательная
  проверка этикетки); режим на смену, после открытия не меняется; по умолчанию «Агрегация».
- Окна: офис и хост — всегда обычное окно; станция — обычное окно до настройки, киоск после; выход из киоска и отвязка станции
  доступны оператору после повторного подтверждения (бейдж или табельный номер+PIN); `--windowed` и `"kiosk": false` — запасной выход.
- Интерфейс: формы создания/правки и длинные данные — в боковые шторы (`src/office/EntityDrawer.tsx`), модалки только для
  подтверждений и «сабмитов»; кастомные селекты с поиском везде; «Сотрудники» убраны из меню (данные/API остаются);
  «Синхронизация» в шапке станции — да; нумерация смены как в облаке (`OCT26-001`, `/S` со станции, латиница).
- Вход в офис: утверждён макет B2 (pen.dev, `docs/design-briefs/check_with_reprint.pen`, кадры «Офис / Вход — B2 …»):
  логотип слева сверху, обе темы + переключатель Светлая/Система/Тёмная, плоская карточка, справа «Недавние на этом ПК»,
  подвал `● · Markiro Автоном <версия> · Офис` (без связи — «Связи нет» справа от красной точки, остальное сдвигается).
- Запуск по роли: host → сразу Офис; station → станция; office → Офис.
- Данные: файлы выгрузок хранятся на хосте и скачиваются повторно (в копиях базы — принято); «Печать» HTML не сохраняет;
  статистика поддержки шифруется (ECDH P-256 + AES-GCM, токен `MKS1.<kid>.…`), открытый ключ `sup-d11c3182` встроен.
- Модели: агенты — Sonnet (экономия лимитов); ревьюеры Sonnet.

## 3. Состояние работ

### В работе (ветки `claude/b32-*`, worktree в /tmp/claude/wt — могут пропасть; ветки сохранены в репозитории)

- `b32-shell`: ГОТОВ и влит (окно входа B2 + выбор «Недавних», сайдбар (настройки вниз), точка статуса вместо чипа, «Обзор», выбор папок
  через проводник (копии, выгрузки), заглавные буквы в восстановлении, «Данные для анализа», автозакрытие диалога печати,
  кнопка «Выйти» в шапке офиса.
- `b32-shifts`: «Открыть» вместо «Изменить», штора смены с режимом правки, вкладка «Сканирования», пояснение метки паллеты.
- `b32-station`: режим в новой смене, фото продукции на станции (+фон из фото), история сканирований вместо нижнего «Плана»,
  точка статуса в стиле чипов, вкладка проверки сканера, исправление печати А4 (HP Smart Tank 790), выбор А4 в перепечатке.
- `b32-media`: прозрачные PNG/WebP фото, логотип компании в формах/этикетках + функция `customLogo`, «Поиск кодов» по умолчанию за 7 дней.
- `b32-boot`: ГОТОВ (`b217173d0`, запуск по роли) — слить в integration вместе с остальными.
  Порядок слияния: влить ветку → `tsc`, `pnpm --filter @markiro/ui build` (устаревший dist давал ложные ошибки), тесты; после всех — общий контроль
  (шарды Vitest, `cargo test --workspace`, контракты, миграции) → пуш → CI → установщик.

### Не начато (в порядке приоритета)

## 5. SaaS: диагностика по тенанту (новая доработка, спецификации ещё нет)

Требование владельца (2026-10-15): присланную диагностическую информацию (текст «Сведения для поддержки» с зашифрованным
токеном `MKS1.…`) можно вставить в SaaS-админку в карточке тенанта; админка расшифровывает токен (закрытый ключ поддержки
хранится ТОЛЬКО в окружении API/секретах, как ключ лицензий; в репозиторий не попадает), сохраняет её как ИСТОРИЮ (по тенанту, с
датой получения, версией приложения/хоста, ролью ПК) и как СТАТИСТИКУ, которую можно просматривать открыто (по месяцам: смены
по режимам, сканирования, короба, паллеты, ошибки, устройства по видам и т.д.); на карточке тенанта видны: текущая версия
(по последней диагностике), использование лицензии (занято из доступного: места по видам устройств, срок, возможности) и др.
Нужно: спека (разбор формата токена из `docs/superpowers/specs/2026-10-13-standalone-license-and-updates-design.md` и
`tools/standalone-support/decrypt.mjs`; публичный формат payload — `apps/standalone/src/host/usage-stats.ts`), таблицы в Postgres
(история + агрегаты, идемпотентность по хешу токена), маршрут в `apps/api` (платформенная политика, аудит с точными полями,
лимит размера), страница в `apps/saas-admin` (вставка, история, графики/таблицы), тесты на отказ (подмена, чужой ключ, повтор).
Расхождения для проверки: фактический набор полей usage-stats хоста и поле «использование лицензии» (оно сейчас не входит в
статистику: добавить в «Сведения для поддержки» версии/лицензию в незашифрованную или зашифрованную часть — решить в спеке).

## 7. Ловушки процесса (чтобы не наступить снова)

- Чистить worktree после слияния (диск упирался в 3 ГБ). Перед `git worktree remove` проверять, что у рабочей копии integration
  на месте `.git` (один раз указатель и ~4,6 тыс. файлов пропали; восстановлено `git restore --source=HEAD --worktree --staged .`
  и `CI=true pnpm install --frozen-lockfile --offline --config.confirmModulesPurge=false`).
- После слияния ветки с правкой `packages/ui`/`domain` пересобирать dist, иначе ложные ошибки типов.
- Слияния проверять `tsc` сразу (слияние тихо теряло импорт `useRef`).
- Реестр маршрутов лицензионных ворот (`host/src/license/gate.rs`) обязан содержать каждый новый маршрут; тест читает исходник с CRLF.
- Тяжёлые Vitest-файлы (`template-editor`, `print-form-dialog`, `shift-*`) падают по таймауту под нагрузкой — перезапускать по одному.
- Не использовать неограниченный `pkill`; `gh` запускать через терминал приложения; терминальные вкладки не копить.
- Модель агентов — Sonnet; исполнители планов описаны в `docs/standalone/ledger/exec-rules.md`.
