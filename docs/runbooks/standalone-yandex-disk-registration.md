# Яндекс Диск для Автонома: регистрация приложения клиента

Редакция 4 от 2026-10-23. Код подключения, ротации и восстановления реализован;
Windows и живой backup/restore пока не проверены, выпуск не выполнен.
Тестовое приложение зарегистрировано: PKCE без секрета и refresh с секретом клиента
проверены успешно напрямую в Яндексе. Секрет хранит служба хоста под DPAPI;
исполнение Windows-службы требует отдельной приёмки. Серверы Markiro в схеме не участвуют.

Приложение создаётся в вашем аккаунте Яндекса и принадлежит вам. Общего приложения Markiro и
передачи копий через серверы Markiro в этой схеме нет.

## Что понадобится

- Аккаунт Яндекса, к которому предприятие сохранит доступ. Для простоты создайте приложение
  в том же аккаунте, чей Диск будете использовать для копий. Включите двухфакторную защиту.
- Контактная почта и иконка предприятия или сервиса размером не более 1 МБ.
- Для первой проверки — отдельное тестовое приложение и синтетические данные, без базы предприятия.

## Регистрация: шесть шагов

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/), войдите в выбранный аккаунт и нажмите
   «Создать приложение». Выберите **«Для авторизации пользователей»**.
   [Прямая ссылка из документации Яндекса](https://oauth.yandex.ru/client/new/id/).

   Это ваше собственное приложение для подключения Автонома к вашему Диску. Тип
   **«Для доступа к API или отладки» не выбирайте**: в нём нельзя задать нужный адрес возврата.

2. Укажите название, например **«Автоном — резервные копии — тест»**, прикрепите иконку и
   укажите вашу контактную почту. Нажмите «Продолжить».

3. На шаге платформ выберите **«Веб-сервисы»**. В поле **Redirect URI** вставьте адрес целиком:

   ```text
   http://127.0.0.1:45711/oauth/yandex/callback
   ```

   Этот адрес означает возврат в Автоном на том же компьютере. Сайт, домен, открытие порта
   роутера или доступ из интернета не нужны. Не заменяйте его на адрес хоста в локальной сети,
   `localhost`, сайт Markiro или `verification_code`: схема, адрес, порт и путь должны совпасть.
   Если форма Яндекса не принимает этот адрес, остановитесь и сообщите текст ошибки без секретов.
   Другая настройка пока не проверена.

4. На шаге доступа к данным оставьте только два разрешения. Если есть поиск по доступам,
   ищите по идентификаторам из правого столбца:

   | Разрешение                                                                | Идентификатор               |
   | ------------------------------------------------------------------------- | --------------------------- |
   | Доступ к папке приложения на Диске                                        | `cloud_api:disk.app_folder` |
   | Базовая информация об аккаунте для определения подключённого пользователя | `login:info`                |

   Чтение/запись всего Диска, почта, телефон, фото и остальные разрешения не нужны. Если эти
   два доступа отсутствуют или Яндекс требует дополнительные настройки/проверку приложения,
   не добавляйте более широкие права ради продолжения — сохраните безопасный текст сообщения.

5. Проверьте название, адрес возврата и два разрешения. Подтвердите сохранение приложения
   кнопкой, которую показывает Яндекс (в документации — «Всё верно»).

6. На странице созданного приложения найдите и сохраните **ClientID** (может называться
   `Client ID`). Это публичный идентификатор приложения. Для следующей проверки достаточно
   прислать только его.

   **ClientSecret / секретный ключ, пароль Яндекса, коды входа и OAuth-токены не присылайте.**
   Для автоматического обновления нужен именно ClientSecret этого приложения, но вводится он
   **только в нативном защищённом окне Автонома**. Не отправляйте
   его в чат/почту/поддержку, не вставляйте в JSON-профиль и не публикуйте скриншот с ним.

## Что произойдёт дальше

В тестах 2026-10-22 PKCE дал пару токенов без секрета; refresh без секрета отклонён,
а refresh с ClientSecret прошёл с HTTP 200. После ClientID Автоном открывает
нативное окно ClientSecret, затем вход в Яндекс. Секрет и токены хранит служба хоста под Windows
DPAPI вне базы/бэкапов, и она же напрямую обновляет токен, когда офис закрыт. Работа реальной
Windows-службы ещё требует проверки. Значения секретов в интерфейс обратно не возвращаются.
Получать «отладочный токен» или отправлять секреты в поддержку не нужно.

Подключение: **ClientID → вход в Яндекс → разрешение
доступа → проверенная копия**; для автоматического refresh между ClientID и входом — нативный
ввод ClientSecret. Сам клиентский секрет не является дополнительным паролем расшифровки бэкапа. На странице разрешения сверяйте название вашего приложения,
аккаунт и запрошенные права. Не разрешайте доступ неизвестному приложению.

Работу обновления токена при закрытом офисе и после перезапуска службы отдельно проверим на
Windows под LocalService. Проверка в браузере или на macOS этого не подтверждает.

## Что сохранить для нового компьютера

- Доступ к аккаунту-владельцу приложения и аккаунту Диска. Если это один аккаунт — доступ к нему.
- **Прежний ClientID.** Его можно записать в инструкции предприятия или экспортировать
  из Автонома в файл `yandex-connection.json`, в котором не будет токенов и секретов.

На новом ПК потребуется указать прежний ClientID, войти в тот же аккаунт и выбрать копию.
Если запись с ClientID потеряна, откройте [кабинет OAuth](https://oauth.yandex.ru/) под владельцем
и найдите прежнее приложение. **Не создавайте новое приложение вместо прежнего при переустановке:**
новое приложение может не получить доступ к старой папке копий. Один вход в Яндекс без ClientID
не позволяет Автоному определить, какое приложение использовать.

Для самого восстановления копии ClientSecret не обязателен: достаточно прежнего ClientID и
входа в Яндекс по PKCE. После восстановления для возобновления автоматических копий возьмите
ClientSecret у того же приложения в кабинете Яндекса и введите в нативное окно Автонома.
Можно отложить этот шаг: данные восстановятся, облачное расписание останется выключенным.
DPAPI-файл старого ПК переносить не нужно. Если секрет изменили в Яндексе, повторите подключение
на хосте с новым секретом; новое приложение создавать не требуется.

Отдельного пароля восстановления нет: ключ расшифровки находится вместе с копией в закрытой
папке Диска. Поэтому доступ к этой папке позволяет восстановить данные предприятия и ключ хоста.
Не публикуйте папку и не делитесь ей с посторонними.

## Если что-то не получилось

| Ситуация                                                         | Что делать                                                                                                                                                |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Создали тип «Для доступа к API или отладки»                      | Не используйте его для этого сценария; тип после создания не меняется. Зарегистрируйте отдельное приложение для авторизации, прежнее удалять не требуется |
| Потерян или отозван токен                                        | Повторите вход с прежним ClientID; новое приложение создавать не нужно                                                                                    |
| Потерян ClientID                                                 | Возьмите его у прежнего приложения в кабинете владельца                                                                                                   |
| Яндекс пишет о верификации, модерации или недоступном разрешении | Зафиксируйте сообщение без секретов; готовность приложения проверяется отдельно, мгновенная доступность не гарантируется                                  |
| Хотите использовать другой Диск или другое приложение            | Это новое назначение копий; старые архивы автоматически не переезжают                                                                                     |

## Подключение в Офисе

1. Администратор открывает «Резервные копии» → «Яндекс Диск». Офис может работать на другом ПК.
2. Вводит ClientID или импортирует публичный JSON-профиль и подтверждает выбранное назначение.
3. Нажимает «Подключить / заменить ClientSecret». В системном окне вводит ClientSecret;
   затем в браузере входит в нужный аккаунт и разрешает доступ. Не вставляет секрет в ClientID.
4. Дожидается именно подтверждённой облачной копии. «Подключён» означает готовую связь,
   а не наличие резервной копии. Дата данных в копии показана отдельно от даты загрузки.
5. Экспортирует публичный профиль для нового ПК. Отключение сохраняет архивы на Диске;
   для отзыва доступа дополнительно использует кабинет Яндекса.

## Восстановление на новом ПК

1. Выключите прежний Host и не запускайте его параллельно с восстановленным.
2. Установите Автоном с ролью «Хост». До создания предприятия выберите восстановление
   из Яндекс Диска. Укажите прежний ClientID или импортируйте профиль и войдите в Яндекс.
3. Явно выберите предприятие/ИНН, hostId и дату копии. Нажмите «Скачать и проверить».
   Отдельный пароль и DPAPI-файл прежнего ПК не нужны.
4. Подтвердите выключение старого Host и восстановление на этом ПК; разрешите Windows UAC.
   Служба остановится для штатного restore и запустится снова. Рабочую целевую БД мастер
   не заменяет. Непереданные локальные факты блокируют операцию и сохраняются.
5. После сбоя используйте «Продолжить прерванное восстановление», включая экран недоступного
   Host. Не создавайте новое предприятие поверх начатого восстановления.
6. Войдите в Офис прежним паролем. Проведите сверку станций и снимите hold штатным действием
   администратора. Вход в Яндекс не сбрасывает пароль Офиса.
7. Для новых автоматических копий отдельно подключите ClientSecret того же приложения
   в Офисе. До этого облачные копии выключены; само восстановление уже завершено.

Если целевой Host уже содержит предприятие, требуется инженер и существующая процедура
восстановления. Автоматического обхода проверки или удаления локальных данных нет.
