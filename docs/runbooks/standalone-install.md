# Установка «Markiro Автоном»: роли ПК, служба, сеть — памятка для ИТ

Памятка к установщику пилота (план УСТ, спецификация пилота §9.4 и §10, «Уточнения плана УСТ»,
родительская спецификация §9.1–9.2). Площадка пилота — два ПК в одной сети Wi-Fi: хост работает на
ПК станции, ПК администратора — офис. Установку на площадке делает наш инженер вместе с ИТ клиента.

**Что проверено и что нет.** Ничего из этой памятки ни разу не выполнялось на Windows. Установщик, хуки
NSIS, `smoke.ps1` и подкоманды хоста написаны и проверены тестами на подделках и чтением кода на macOS;
задание CI `standalone-windows-build` с этим кодом ещё не запускалось (ветка не отправлялась). Каждое
утверждение ниже о поведении Windows — то, чего код ждёт от неё, а не то, что видели на машине.
Пункты, которые обязательно пройти руками, собраны в разделе «Ручная проверка на Windows».

Связанные памятки:

- резервные копии и восстановление хоста — `docs/runbooks/standalone-backup-restore.md` (план РК);
  разделы 2, 5 и 6 нужны установке, ссылки на них ниже;
- перенос данных из облака (план ИМП) — **отложен**, памятки перехода нет. Готова только арифметика
  стартовых номеров SSCC (`tools/standalone-export/sscc.mjs`, `pnpm test:standalone-export`); импорта
  данных, который читал бы базу облака и заполнял хост, нет. Не обещайте клиенту перенос данных как
  готовую функцию.

## Что ставится

Один установщик `markiro-standalone-<версия>-windows-x86_64-setup.exe` для Windows 10/11 x64. Его
собирает задание CI `standalone-windows-build`. Артефакт `standalone-installer-<полный коммит>`
хранится 30 дней и содержит:

- установщик;
- `release-evidence.json`: версия, репозиторий и коммит, роли, SHA-256 и размер установщика, состояние
  подписи Authenticode (`NotSigned` или `Valid`);
- `SHA256SUMS`: хеши установщика и `release-evidence.json`.

Перед установкой сверьте хеш: `Get-FileHash <файл> -Algorithm SHA256` должен совпасть со строкой в
`SHA256SUMS`. Задание запускается только при изменениях, которые касаются автонома (это решает `classify-changes`).

Роль ПК выбирается при установке:

| Роль           | Ключ            | Что на ПК                                                                                                      |
| -------------- | --------------- | -------------------------------------------------------------------------------------------------------------- |
| Хост и станция | `/ROLE=host`    | Служба `MarkiroHost` с главной базой, правило брандмауэра, приложение в киоск-режиме, автозапуск приложения    |
| Только станция | `/ROLE=station` | Приложение в киоск-режиме, автозапуск; подключается к хосту на другом ПК, `markiro-host.exe` на ПК не остаётся |
| Только офис    | `/ROLE=office`  | Приложение без киоск-режима и без автозапуска; подключается к хосту как устройство офиса                       |

Правила ролей:

- **Откуда берётся роль.** Сначала из `/ROLE=`, иначе из предыдущей установки (реестр), иначе
  установщик задаёт два вопроса. Тихая установка (`/S`) без `/ROLE=` и без прежней роли отказывает с
  сообщением и кодом возврата 2: ничего не ставится.
- **Допустимые значения** `/ROLE=` — `host`, `station`, `office`; любое другое отказывает. NSIS
  сравнивает строки без учёта регистра, поэтому `/ROLE=HOST` принимается как `host`, а в файл роли
  всегда пишется строчными буквами.
- **Роль не меняется поверх.** `/ROLE=` не той роли, что уже стоит на ПК, отказывает. Чтобы сменить роль,
  удалите программу и установите заново: данные при удалении сохраняются.
- **Что записывается.** `HKLM\Software\Markiro\Standalone`, значение `Role` (для следующего установщика)
  и `installation.json` рядом с `markiro-standalone.exe` (для приложения). Содержимое файла — ровно
  `{"role":"host"}`, `{"role":"station"}` или `{"role":"office"}`: приложение отказывается читать файл с
  другим ключом, другим написанием роли и любым другим содержимым и тогда работает **станцией**, то есть
  запирается в киоск-режим. Если окно ПК офиса запирается, откройте `installation.json` (он в каталоге
  установки, писать в него могут только администраторы) и проверьте текст; приложение не сообщает об
  ошибке чтения на экране.

## Памятка для ИТ

**Служба**

- Имя `MarkiroHost`, отображаемое имя «Markiro Хост». Только роль «хост и станция».
- Файл: `<каталог установки>\markiro-host.exe service`. Ожидаемый каталог установки —
  `C:\Program Files\Markiro Standalone` (на Windows не подтверждён; `smoke.ps1` ищет установку именно
  там).
- Учётная запись `NT AUTHORITY\LocalService`: без пароля и без прав администратора.
- Запуск автоматический, вход в Windows не нужен. Автовход в Windows установщик не настраивает: нужен ли
  он на станции, решает ИТ клиента.
- При сбое служба перезапускается через 5, 30 и 60 секунд, дальше каждые 60 секунд. Счётчик сбоев
  сбрасывается через сутки без сбоев. Сбоем считается и выход с кодом ошибки: команда
  `sc qfailureflag MarkiroHost` отвечает `TRUE`. Остановка администратором (`sc stop`,
  `markiro-host stop-service`) сбоем не считается, и Windows её не перезапускает.
- Ставит, перерегистрирует и снимает службу установщик. Вручную, из консоли администратора на ПК
  хоста (команды только для Windows):
  - `markiro-host install` — зарегистрировать (или переписать) и запустить службу, ждать до 30 секунд;
  - `markiro-host uninstall` — остановить и удалить службу и правило брандмауэра, данные не трогать;
  - `markiro-host stop-service` — остановить и дождаться остановки; службы нет — не ошибка.
- **Установка поверх переписывает настройку службы, кроме учётной записи.** Файл, автозапуск и
  действия при сбое становятся прежними, а учётная запись существующей службы остаётся той, что
  выставил ИТ клиента (так советует `standalone-backup-restore.md`, раздел 2, для записи второй папки
  копий по сети). `LocalService` получает только служба, которую установка создаёт (по коду; на
  Windows не проверялось).
- Порядок `install`: владелец и права каталога данных, остановка прежней службы, запись настройки, правило
  брандмауэра, запуск и ожидание. Повтор сходится к тому же состоянию. Установка на чистом ПК, которая
  не удалась на любом шаге до запуска, откатывается (служба и правило снимаются); неудавшееся
  обновление существующую службу не удаляет.

**Коды возврата `markiro-host`** (их читает установщик, `src-tauri/windows/installer-hooks.nsh`)

| Команда         | Код | Значение                                                                                                              |
| --------------- | --- | --------------------------------------------------------------------------------------------------------------------- |
| `install`       | 0   | служба работает                                                                                                       |
| `install`       | 4   | служба зарегистрирована, но не осталась запущенной или ещё запускается через 30 с (см. «Установка с предупреждением») |
| `install`       | 1   | отказ (нет прав администратора, отказ службы или `icacls`, прежняя служба не остановилась за 30 с)                    |
| `network-check` | 0   | общедоступных сетей нет                                                                                               |
| `network-check` | 3   | осталась общедоступная сеть                                                                                           |
| любая           | 2   | неверная командная строка                                                                                             |

**Сеть**

- Входящий TCP 45710 (порт из `host.json`), только на ПК с ролью «хост и станция».
- Правило брандмауэра `MarkiroHost` («Markiro Хост (TCP 45710)»): входящее, разрешающее, TCP, профили
  «частная» и «доменная», удалённые адреса — только локальная подсеть (`LocalSubnet`). Правило не
  привязано к программе. Установщик создаёт его заново при каждой установке и удаляет при удалении.
- Номер порта в правило берётся из `host.json` в момент `install`. Если порт хоста потом меняли
  (`markiro-host run --port …` записывает его в `host.json`), правило нужно перерегистрировать командой
  `markiro-host install` (или переустановкой).
- Исходящих соединений в интернет нет: хост и приложение не обращаются в интернет, автообновления и
  телеметрии в коде нет (проверено чтением кода, а не мониторингом сети). Исключение — сам установщик:
  если на ПК нет WebView2, установщик Tauri скачивает его у Microsoft (режим по умолчанию; на Windows не
  проверялось). На ПК, где стояла облачная станция, WebView2, скорее всего, уже есть.

**Каталоги**

- `%ProgramData%\Markiro\Host` — данные хоста (только роль «хост и станция»):
  - `host.db` с `-wal` и `-shm` — главная база;
  - `host.json` — идентификатор хоста и порт;
  - `tls\cert.der` и `tls\key.der` — сертификат хоста и его закрытый ключ;
  - `logs\host.<дата>.log` — журнал службы; хранятся 14 последних файлов (по одному на день работы);
  - `backups\` — локальные копии базы (план РК);
  - `host.lock` — блокировка: второй хост на том же каталоге не запустится;
  - `host.restore-intent` — есть только при незаконченном `markiro-host restore`.
- **Права каталога данных** установщик выставляет командой `icacls` по идентификаторам SID (имена групп
  на русской Windows переведены): наследование от `ProgramData` снято; SYSTEM и «Администраторы» — полный
  доступ; `LocalService` — изменение; обычным пользователям доступа нет. Права наследуют файлы внутри.
  Перед этим владельцем каталога, всего в нём и папки `%ProgramData%\Markiro` становится группа
  «Администраторы» (`icacls … /setowner *S-1-5-32-544`): пользователь, создавший каталог раньше
  установщика, иначе остался бы владельцем и мог бы вернуть себе доступ к базе. Права, которые
  `ProgramData` дала такому пользователю на саму папку `Markiro`, установщик не снимает.
  - **Зачем.** В `host.db` и в копиях лежат хеши паролей, PIN и бейджей, соль бейджей и хеши ключей
    устройств; в `tls\key.der` — закрытый ключ, по сертификату которого устройства узнают хост. Если их
    прочитает обычный пользователь ПК станции, он получит материал для подбора PIN и бейджей и сможет
    выдать себя за хост.
  - Поэтому `markiro-host print-fingerprint` (без параметров он берёт этот каталог) и `restore`
    запускаются от администратора.
  - Команда применяется к самому каталогу без рекурсивного обхода: расчёт на то, что файлы внутри
    наследуют права. Файл, созданный раньше с собственными правами, ими и остаётся (см. ручную проверку).
- `%LOCALAPPDATA%\app.markiro.standalone` у каждого пользователя Windows — данные приложения:
  - `device.json` — подключение к хосту; ключ устройства защищён DPAPI **этого пользователя Windows**;
  - `standalone-station.db` — локальная база станции, в том числе ещё не отправленные на хост факты.

  Подключение хранится для каждого пользователя отдельно: на станции работайте под одной учётной
  записью Windows, другой пользователь увидит приложение неподключённым. Копирование файлов профиля на другой
  ПК подключение не переносит: ключ защищён DPAPI пользователя и обычно не расшифруется.

**Реестр**

- `HKLM\Software\Markiro\Standalone`, значение `Role` — роль для следующего установщика.
- `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`, значение `MarkiroStandalone`: автозапуск
  приложения при входе любого пользователя на станциях (роли `host` и `station`); на ПК офиса значения нет.

**Антивирус и SmartScreen**

Добавьте исключения:

- каталоги `%ProgramData%\Markiro\Host` и `%LOCALAPPDATA%\app.markiro.standalone` (базы SQLite в режиме
  WAL);
- процессы `markiro-host.exe` и `markiro-standalone.exe`.

Установщик пилота не подписан Authenticode (вопрос П12; `release-evidence.json` говорит `NotSigned`).
Следствия, оба ожидаемые и оба не проверялись на Windows:

- SmartScreen покажет «Неизвестный издатель». Запуск: «Подробнее» → «Выполнить в любом случае».
  Файл, скачанный из интернета, может нести метку загрузки (в «Свойствах» — «Разблокировать»).
- Служба и правило брандмауэра создаются PowerShell-скриптом, переданным как `-EncodedCommand` (так
  кавычки в путях ничего не искажают). Часть антивирусов подозрительно относится к такой строке. Если
  установка блокируется, внесите установщик и `powershell.exe` в исключения на время установки и
  сообщите нам.

## Сеть площадки (вопрос П9)

1. **Постоянный адрес ПК хоста.** Это обязательно. Лучше всего — резервирование DHCP на роутере по
   MAC-адресу адаптера. Иначе — статический адрес вне пула DHCP. Станция на самом ПК хоста ходит к
   хосту по `127.0.0.1` и от адреса не зависит. Остальные ПК хранят адрес хоста.
2. **Ethernet к ПК станции**, если можно протянуть кабель. Обрыв Wi-Fi тогда не трогает и офис.
3. **Профиль сети «Частная».** Windows часто относит новую сеть Wi-Fi к общедоступным, а правило
   открывает порт только в частной и доменной сетях.
   - Установщик в конце установки хоста проверяет профили (`markiro-host network-check`) и, если есть
     общедоступная сеть, при установке с окнами предлагает перевести её в частную. В тихой установке
     предложения нет: код 3 только записывается в журнал установки.
   - Вручную: «Параметры» → «Сеть и Интернет» → свойства сети → «Частная».
   - Из консоли администратора: `markiro-host network-check --make-private` переводит в частные все
     общедоступные сети. Без ключа команда только печатает сети (`<имя>: <категория>`); код 3 значит,
     что осталась общедоступная.
   - Если ИТ клиента против частного профиля, правило «для всех профилей с ограничением локальной
     подсетью» добавляется вручную; установщик его не делает. Это решение владельца вместе с ИТ клиента.
4. **Проверка с другого ПК:** `Test-NetConnection <адрес ПК хоста> -Port 45710` должен вернуть
   `TcpTestSucceeded : True`.
5. **Адрес хоста всё же сменился.** На ПК, подключённом к хосту по сети, на экране «Вход в офис»
   (на станции — «Офис») нажмите «Сменить адрес хоста» и введите новый адрес: IP-адрес или имя ПК, при
   необходимости с портом (`192.168.1.20` или `192.168.1.20:45710`); оболочка хранит его в виде
   `https://адрес[:порт]` и ничего другого (ни имени пользователя, ни пути, ни пробелов не принимает).
   - Приложение примет адрес, только если по нему отвечает **тот же хост**: сертификат совпадает с
     закреплённым при подключении, и хост по-прежнему принимает ключ этого устройства. Ключ уходит
     только хосту с закреплённым сертификатом. Подключение, ключ и копии остаются.
   - «По этому адресу отвечает другой хост…» — по адресу отвечает хост с другим сертификатом. Проверьте
     адрес. Если сертификат хоста действительно сменился (ПК хоста переустановлен с новыми данными или
     хост восстановлен на новом ПК, `standalone-backup-restore.md`, раздел 6), то отпечаток на ПК хоста
     (`markiro-host print-fingerprint`) уже не тот, что подключение помнит, и каждое устройство
     подключается заново по коду.
   - «Хост больше не принимает это устройство» — устройство отозвано или база хоста восстановлена из
     копии: подключите его заново.
   - «По этому адресу хост не отвечает» — адрес не изменился; старое подключение остаётся.
   - Кнопки нет на ПК хоста: его станция ходит к хосту по `127.0.0.1`.

## Порядок установки

Офис открывается, только пока включён ПК хоста (вариант Б спецификации пилота, §3): на ПК хоста стоит
главная база. Линия от сети не зависит: станция ПК хоста ходит к хосту по `127.0.0.1`.

Все ПК площадки ставятся одним установщиком одной версии: станция протокола 2 могла бы войти в смену с
паллетами и выпускать короба без них (спецификация пилота, «Уточнения плана ПЛ-Х»). Версию на каждой
станции сверяйте при установке.

### 1. ПК хоста (он же станция)

1. Запустите установщик от имени администратора: на первый вопрос ответьте «Да» (или
   `<установщик> /S /ROLE=host`).
2. Установщик копирует файлы, записывает роль, регистрирует и запускает службу (ожидание до 30 секунд),
   открывает порт и проверяет профили сети. Если вышло предупреждение с кодом 4 — см. «Установка с
   предупреждением».
3. Проверьте: `sc query MarkiroHost` — `RUNNING`; в `logs\` появился `host.<дата>.log`;
   `Get-NetFirewallRule -Name MarkiroHost` существует; с ПК офиса проходит `Test-NetConnection` (порядок
   ниже).
4. Откройте приложение ярлыком (`markiro-standalone.exe` в каталоге установки). Окно запирается
   (киоск-режим): на ПК хоста оно запирается всегда, в том числе на мастере первого запуска. Выйти из
   него можно, только пройдя мастер и войдя в офис администратором («Оконный режим»). Если окно не
   закрыть: Ctrl+Alt+Del → «Выйти из системы» (Диспетчер задач может открыться под окном).
5. Пройдите мастер первого запуска. Станция этого ПК подключается к хосту сама (по `127.0.0.1`).
   Затем в офисе назначьте линию.
6. Хост начинает с пустой базы: переноса данных из облака в пилоте пока нет (см. начало памятки).
7. Выпишите отпечаток сертификата (`markiro-host print-fingerprint` от администратора или экран
   «Подключение устройства» в офисе): он нужен при подключении других ПК.

### 2. ПК офиса (администратор)

1. Запустите установщик: на первый вопрос «Нет», на второй «Да» (или `/S /ROLE=office`). Служба,
   правило брандмауэра и автозапуск не создаются.
2. Откройте приложение. Хоста на этом ПК нет, поэтому приложение покажет «Служба хоста не отвечает».
   Нажмите «Подключиться к хосту в сети».
3. На ПК станции администратор входит в офис («Офис» → вход) и открывает «Устройства» → «Подключить
   устройство». Экран показывает код (10 символов, он действует ограниченное время; «Новый код» создаёт
   другой), отпечаток хоста и адреса хоста.
4. На ПК офиса введите имя устройства и либо отсканируйте код сканером, либо нажмите «Ввести адрес и
   код вручную» (адрес — `192.168.1.10` или `192.168.1.10:45710`; код — 10 символов, набирайте его
   английской раскладкой), затем «Далее».
5. **Сверьте отпечаток** на экране ПК офиса с отпечатком хоста на экране «Подключение устройства».
   Код уходит на хост, только если отпечатки совпали.
6. ПК подключается как устройство вида `office` и открывает «Вход в офис». Здесь нет «В цех», в шапке
   вместо «Выйти в цех» кнопка «Выйти» (она возвращает на «Вход в офис»), окно никогда не запирается.
   На цехе этого ПК никто не входит: оператор, линия и смены доступны только станции.
7. Если на ПК офиса уже стоит служба или он когда-либо ставился с ролью `host`/`station`, смотрите «Если
   что-то не так».

### 3. Ещё одна станция (роль «только станция»)

1. Установщик: «Нет», затем «Нет» (или `/S /ROLE=station`). Автозапуск создаётся, хост нет.
2. Приложение покажет «Служба хоста не отвечает» (на этом ПК хоста нет): «Подключиться к хосту в сети»,
   код из «Устройства» → «Подключить устройство» на офисе, сверка отпечатка — как на ПК офиса.
3. Затем назначьте линию и войдите оператором; окно запирается.
4. Не ставьте на этот ПК роль `host`, если на площадке уже есть хост: два хоста — два набора данных, и
   станции одной площадки не сойдутся.

### 4. Проверка после установки

1. Перезагрузите ПК хоста, не входя в Windows. С ПК офиса `Test-NetConnection` проходит и вход в
   офис работает: служба поднялась без входа пользователя.
2. Войдите в Windows на ПК хоста: приложение открывается само и запирается.
3. Выключите питание ПК хоста (не выключением в меню) и включите: служба поднимается сама;
   перезапуск после сбоя виден в журнале событий «Система».

## Установка с предупреждением (код 4) и восстановление

`markiro-host install` возвращает 4, если служба зарегистрирована, но сразу остановилась или через
30 секунд ещё запускается (например, большая база мигрирует при первом запуске). Установщик
считает это **предупреждением**, а не отказом: показывает окно (в тихой установке — запись в журнале
установки, окон нет) и продолжает; служба, правило и данные остаются, код возврата установщика 0. Самая
частая причина — незаконченное восстановление из копии: пока в каталоге данных лежит
`host.restore-intent`, хост отказывается запускаться, а в `logs\host.<дата>.log` написано «a restore of …
was interrupted … run the same markiro-host restore command again».

После тихой установки хоста всегда проверяйте `sc query MarkiroHost`: `RUNNING`.

Что делать (подробности — `standalone-backup-restore.md`, раздел 5, шаг 6):

1. Остановить службу: `sc stop MarkiroHost` и **дождаться `STATE: STOPPED`** в ответе команды
   `sc query MarkiroHost`. Служба отпускает блокировку каталога данных раньше, чем процесс завершился.
2. Повторить ту же команду `markiro-host restore …`, которой восстановление начиналось; маркер вручную не
   удалять.
3. Запустить службу: `sc start MarkiroHost`.

Две особенности, оба следствия политики восстановления (на Windows не проверялись):

- Пока маркер лежит, служба сама пытается запуститься (повторы Windows после ошибки: через 5 и 30
  секунд, затем каждые 60).
  Каждая попытка ненадолго берёт блокировку каталога, поэтому `restore` может **один раз** ответить, что
  хост запущен или каталог заблокирован («the host is running … Stop the service»). Это не отказ:
  повторите команду.
- `markiro-host stop-service` между двумя попытками видит остановленную службу и возвращается сразу;
  Windows запустит службу снова в течение 60 секунд. Поэтому для `restore` важнее дождаться
  `STATE: STOPPED` и повторить команду, чем нажимать `stop-service` один раз.

Если после предупреждения `sc query MarkiroHost` через минуту показывает `RUNNING`, служба просто
запускалась дольше 30 секунд, и делать ничего не нужно.

Если установка завершилась **ошибкой**: при отказе `install` установщик показывает «Служба MarkiroHost не
установлена (код N)» (в тихой установке — код возврата 2), а файлы и роль остаются. Повторный запуск
установщика с той же ролью сходится к рабочему состоянию.

## Обновление (вопрос П13: переустановкой)

1. Закройте приложение на каждой станции. На станции: администратор входит в офис, нажимает «Оконный
   режим» и закрывает окно. Иначе установщик Tauri сам предложит закрыть приложение (не проверялось).
   Повторный запуск приложения, пока оно уже работает, ничего не делает: второй экземпляр не
   находит спрятанное окно.
2. Запустите новый установщик.
   - Тихо: `<установщик> /S` — роль прежняя (из реестра).
   - С окнами: на вопрос «уже установлено» можно оставить «удалить перед установкой». Тогда прежний
     деинсталлятор снимает и роль, и установщик спросит роль снова — ответьте как в прошлый раз
     (поведение страницы Tauri не проверялось).
3. Перед заменой файлов существующий `markiro-host.exe` останавливает службу (данные остаются), после
   копирования `install` регистрирует службу заново и запускает её. Данные хоста и приложения остаются.
   Служба и станция на ПК хоста простаивают в это время; станции на других ПК копят записи в очереди.
4. Не ставьте более старую версию поверх новой: миграции базы идут только вперёд, и старая служба не
   сможет открыть базу, в которой применены более новые миграции (поведение библиотеки миграций,
   не проверялось).
5. Учётная запись службы обновлением не меняется (`sc qc MarkiroHost` показывает прежнюю); вторая
   папка копий по сети продолжает работать под той учётной записью, которую выставил ИТ клиента.
6. Версия хоста и версия приложения должны совпадать по протоколу: приложение старее службы или служба
   старее приложения покажет экран «Версии не совпадают».

## Удаление

«Приложения» → «Markiro Standalone» → «Удалить» (или `uninstall.exe /S`).

- Служба и правило брандмауэра удаляются (`markiro-host uninstall`), удаляются автозапуск, роль в
  реестре и `installation.json`.
- Данные остаются: `%ProgramData%\Markiro\Host` и `%LOCALAPPDATA%\app.markiro.standalone`. Флажок
  «удалить данные приложения» в окне удаления не действует: локальная база станции может хранить
  ещё не отправленные на хост факты.
- Повторная установка с ролью `host` поднимает тот же хост: тот же `host.json`, тот же сертификат,
  станции остаются подключёнными.
- **Проверьте после удаления.** Если `markiro-host uninstall` в деинсталляторе не удался, это только
  записывается в журнал удаления, а файлы всё равно удаляются: служба может остаться зарегистрированной
  без файла. Проверьте `sc query MarkiroHost` (должно быть «служба не установлена», код 1060) и
  `Get-NetFirewallRule -Name MarkiroHost` (не должно быть правила). Если осталось: `sc delete MarkiroHost` и
  `Remove-NetFirewallRule -Name MarkiroHost` из консоли администратора (команды Windows, не
  проверялись).
- Стереть данные можно только вручную, при выводе ПК из работы и после резервной копии.

## Если что-то не так

- `sc query MarkiroHost` — состояние службы; `sc qc MarkiroHost` — файл и учётная запись;
  `sc qfailure MarkiroHost` — действия при сбое. Тексты этих команд зависят от языка Windows.
- Журналы: `%ProgramData%\Markiro\Host\logs\host.<дата>.log`.
- Журнал установки: окно установщика, «Подробнее».
- Повторная регистрация службы: из консоли администратора
  `"C:\Program Files\Markiro Standalone\markiro-host.exe" install`.
- Окно ПК офиса запирается: проверьте `installation.json` (текст выше) и что установка шла с ролью
  `office`. Если файл отсутствует или нечитаем, ПК считается станцией.
- **Станция с устаревшим подключением офиса.** ПК с ролью `host` или `station`, на диске которого осталось
  подключение вида `office` (например, роль меняли удалением и установкой заново), остаётся запертым и
  открывается на «Входе в офис», пока его не подключат заново. Выйти из запертого окна может только
  администратор («Оконный режим»). Затем отзовите это устройство в «Устройствах» («Отозвать этот ПК?») и
  подключите заново, как на шаге «Ещё одна станция». Порядок не проверялся.
- **Устаревшее подключение станции на ПК офиса.** ПК с ролью `office` никогда не показывает цех, линию и
  вход оператора, даже если на диске осталось подключение станции. Отзовите это устройство в
  «Устройствах» и подключите ПК заново.
- ПК офиса никогда не подключается как станция: подключение «на этом компьютере» (по `127.0.0.1`) для
  него отказано. Если на ПК с ролью `office` что-то отвечает на `127.0.0.1:45710` (служба от прежней
  установки, хост, запущенный вручную), приложение пробует подключиться автоматически, получает отказ, и
  экран «Не удалось подключиться к хосту» предлагает только «Повторить»: способа подключиться по сети
  с этого экрана нет. Остановите и уберите хост на этом ПК (`markiro-host uninstall`, если служба
  осталась); тогда приложение покажет «Служба хоста не отвечает» с кнопкой подключения по сети.
- Приложение не закрыть, окно висит поверх всего: Ctrl+Alt+Del → «Выйти из системы». Свёрнутое окно
  (Win+D) запертой станции может не вернуться: повторный запуск приложения ничего не делает.

## Подпись Authenticode (вопрос П12)

Сейчас установщик не подписан — ни локальная сборка, ни сборка в CI. `Valid` в `release-evidence.json`
появится, только когда установщик подпишут. Подписывать будет владелец, когда у него появится
сертификат подписи кода.

1. Установите сертификат подписи кода в хранилище Windows на машине сборки (закрытый ключ остаётся
   вне репозитория).
2. Соберите хост и положите его рядом с приложением, как делает CI:
   `cargo build --release --locked --manifest-path apps/standalone/Cargo.toml -p markiro-host`, затем
   скопируйте `apps/standalone/target/release/markiro-host.exe` в
   `apps/standalone/src-tauri/binaries/markiro-host-x86_64-pc-windows-msvc.exe`.
3. Соберите оверлей подписи:

   ```text
   node tools/standalone-release/sign-overlay.mjs --thumbprint <SHA-1 сертификата> --timestamp-url <RFC 3161 URL удостоверяющего центра> > sign.json
   ```

   Инструмент не читает пароль, окружение и файлы; адрес сервера времени с именем пользователя или
   паролем он отвергает.

4. Соберите установщик с оверлеем:

   ```text
   pnpm --filter @markiro/standalone tauri build --config src-tauri/tauri.installer.conf.json --config <путь>/sign.json --bundles nsis
   ```

5. Проверьте подпись: `Get-AuthenticodeSignature` для установщика, `markiro-standalone.exe`,
   `markiro-host.exe` и `uninstall.exe`. Какие из этих файлов Tauri подписывает сам, не проверено.

В CI подписи нет, и задание пулл-реквеста её получить не должно: секрет в задании пулл-реквеста виден
коду этого пулл-реквеста. Подписанная сборка должна появиться отдельным защищённым процессом выпуска
(окружение с ревьюерами, запуск только с защищённой ветки), которого сейчас нет; до него подписанные
установщики собирает только владелец у себя.

## Что проверяет CI и чего он не проверяет

Задание `standalone-windows-build` (раннер `windows-latest`, Windows Server) собирает хост и установщик и
запускает `tools/standalone-release/smoke.ps1`. Скрипт проверяет:

- тихую установку трёх ролей и отказ без роли, точный текст `installation.json`, `/ROLE=HOST`;
- службу: учётную запись, автозапуск, действия при сбое и их сброс через сутки, перезапуск в новом
  процессе после убитого;
- правило брандмауэра (входящее, частная и доменная сети, порт, локальная подсеть) и права каталога данных
  и `tls\key.der` (SYSTEM, LocalService, Администраторы), владельца каталога данных и папки `Markiro`
  («Администраторы»), проверенную копию базы в `backups` с теми же правами;
- переустановку с тем же хостом и сертификатом, переустановку при незаконченном восстановлении (код 4:
  установщик не падает, служба остаётся), отказ при смене роли;
- удаление при работающем хосте, после которого данные остаются, а служба, правило, автозапуск и
  `installation.json` исчезли.

Скрипт и задание на момент написания не запускались. Что скрипт принимает на веру: английский текст
`sc.exe` на раннере, пути установки, форма свойств `Get-NetFirewall*`.

### Печать через драйвер Windows (план ДРВ)

Код вызовов спулера и GDI ни разу не запускался (только проверен на типы), поэтому этот пункт
обязателен до первой печати через драйвер на площадке клиента. Сообщить владельцу: модель
принтера и драйвера, разрешение в драйвере, что вышло на бумаге по каждому шагу, текст
сообщений на экране.

1. Установить драйвер термопринтера (Godex, TSC, Zebra или Xprinter), в настройках драйвера —
   бумага размера этикетки, разрешение принтера (203 или 300 dpi).
2. «Настройка рабочего места» → «Добавить принтер» → «Принтер Windows (USB)» → очередь →
   «Способ печати: Через драйвер Windows», разрешение как у драйвера → «Готово» → «Сохранить».
   Выбор «Способ печати» виден только для очереди Windows; поля и кнопки настройки
   достаточно крупные для пальца (не меньше 64 px — `tools/production-browser` это для новых
   элементов не проверял, измерить вручную или снять экран).
3. «Пробная печать»: этикетка выходит без масштабирования, штрихкод читается сканером, код
   совпадает.
4. Неверное разрешение в профиле (300 при драйвере 203) — пробная печать отвечает «Размер
   бумаги или разрешение в драйвере Windows не совпадают…», ничего не печатается.
5. Смена с принтером в режиме драйвера: короб закрывается, этикетка печатается; кириллица —
   шрифтом IBM Plex (не запасным: если шрифт в WebView2 не загрузился, печать отказывает с
   «Этикетку не удалось подготовить для этого принтера», а не печатает чужим шрифтом).
6. Очередь приостановлена или принтер выключен, но очередь принимает задания (обычная печать с
   буферизацией): этикетка — `sent`, то есть Windows приняла задание в очередь; экран не говорит,
   что она напечатана. Если включена проверка сканом, панель ждёт скан, и «Проверить очередь
   Windows» читает «Задание находится в очереди Windows…» (`present`). Если проверка скана
   выключена, задание завершено и кнопки очереди нет. После возобновления очереди выходит ровно
   одна этикетка. «Принтер не ответил вовремя» и «Windows не подтвердил задание…» появляются
   только когда вызов драйвера действительно не возвращается (очередь настроена «печатать
   напрямую на принтер», сетевой принтер недоступен): через 20 секунд; «Напечатать снова»
   спрашивает причину; само ничего не перепечатывается. Не ждите этих сообщений от
   приостановленной очереди — это ожидаемое поведение, а не ошибка.
7. Перезапуск программы во время вызова драйвера, который ещё не ответил (очередь из шага 6,
   блокирующая): задание читается «Печать прервалась», «Проверить очередь Windows» — «Номер
   задания Windows неизвестен». Этикетка, уже принятая в приостановленную очередь (`sent`), после
   перезапуска остаётся в состоянии `sent`: «Печать прервалась» она не показывает.

Что учесть при проверке:

- **Пробная этикетка 58×40 мм.** Пробная печать ставит бумагу драйвера на 58×40 мм на время
  задания. У драйверов в стиле TSC/Godex это уходит принтеру командой размера; на более крупном
  рулоне этикетка ложится в левый верхний угол, следующее задание возвращает размер. Для
  пробной печати берите носитель не меньше 58×40 мм.
- **Не откатывать сборку при незавершённых заданиях драйвера.** Сборка без драйверного режима не
  знает поля `mode` и читает такой профиль как RAW: незавершённые задания (`prepared`,
  `failed`, `unknown`) повторили бы замороженный растр `MKRMNO1…` как RAW, и принтер напечатал
  бы мусор. Сначала дайте оператору разобрать все такие задания, потом откатывайтесь.
- **Журнал шелла.** Запустите приложение из `cmd` с перенаправлением ошибок:
  `"C:\Program Files\Markiro Standalone\<имя exe приложения>" 2> drv-log.txt` (путь и имя файла
  — по вашей установке). Окно с windows-подсистемой при таком запуске пишет stderr в файл.
  Каждый сбой вызова драйвера даёт одну строку `standalone: driver print step=…` с названием шага,
  кодом ошибки Windows и числами (для `geometry` — размеры и разрешение страницы против того, что
  назвал драйвер, и режим бумаги), и ещё одну строку `… refused code=…` с кодом отказа; содержимого
  этикетки, кодов в ней, имён очереди и документа там нет.

Порядок первой проверки у владельца (по важности):

1. Запустить сборку из `cmd` с `2> drv-log.txt`. Записать модель принтера, имя и версию драйвера,
   разрешение драйвера.
2. Настройка → очередь Windows → «Через драйвер Windows», разрешение как у драйвера → «Пробная
   печать» на носителе не меньше 58×40 мм. Измерить этикетку: 58×40 мм, без масштабирования, без
   зеркала, без инверсии. Code 128 читается сканером и совпадает.
3. Если пробная печать пишет «Размер бумаги или разрешение … не совпадают»: прислать
   `drv-log.txt` (строка с шагом `geometry`: размеры страницы против того, что назвал драйвер) и
   попробовать другое разрешение.
4. Если каждая печать пишет «Windows не подтвердил задание до конца» и ничего не выходит —
   сообщить сразу (в `drv-log.txt` строка с шагом `StretchDIBits`/`EndDoc` и кодом).
5. Разрешение профиля 300 при драйвере 203: отказ, ничего не напечатано, в очереди Windows пусто.
6. Настоящая смена на настоящем носителе: закрыть короб и паллету. Проверить размер, кириллицу
   шрифтом IBM Plex, SSCC (GS1-128) и DataMatrix сканером с точным содержимым.
7. Приостановить очередь: этикетка `sent`, проверка скана ждёт, «Проверить очередь Windows»
   читает «Задание находится в очереди». Возобновить: выходит ровно одна этикетка.
8. Очередь, которая блокирует (сетевой принтер отключён, «печатать напрямую»): через 20 секунд
   «Принтер не ответил вовремя». Само ничего не перепечатывается. «Напечатать снова» спрашивает
   причину. Записать, выйдет ли оригинал позже.
9. Перезапустить программу во время ожидания шага 8: «Печать прервалась», «Проверить очередь»
   читает «Номер задания Windows неизвестен».
10. Вернуть ту же очередь на «На языке принтера»: ZPL/TSPL печатается как прежде. Измерить
    новые элементы настройки (не меньше 64 px).

### Листы паллет А4 через драйвер Windows (план А4)

Режим страницы А4 в оболочке (`DMPAPER_A4`, ориентация, масштаб, проверка печатной области) ни
разу не запускался на Windows (проверен только на типы и арифметикой на хосте), поэтому этот
пункт обязателен до первой печати листа на площадке. Предпосылка — пройденный пункт «Печать
через драйвер Windows». Сообщить владельцу: модель принтера и драйвера, размер бумаги и поля в
драйвере, что вышло на бумаге по каждому шагу, строки `drv-log.txt` и текст на экране.

1. Установить драйвер лазерного или струйного принтера, бумага в драйвере — А4, односторонняя
   печать, одна копия. Запустить приложение из `cmd` с `2> drv-log.txt`.
2. «Настройка рабочего места» → «Добавить принтер» → «Принтер Windows (USB)» → очередь →
   «Способ печати: Через драйвер Windows» → «Бумага: Лист А4». Разрешение переключается на 300 dpi
   и недоступно для правки. «Готово». «Этикетка паллеты» → этот принтер; в списках «Этикетка короба»
   и «Дубль кода» его быть не должно. «Сохранить».
3. «Пробная печать» на этом принтере: на экране появляется предпросмотр листа, на бумаге выходит
   одна страница. Измерить линейкой: страница А4 (210 × 297 мм), масштаб 1:1 (логотип, рамки и
   штрихкод не растянуты и не уменьшены), поля — не меньше 10 мм у нарисованного содержимого,
   ничего не обрезано ни с одного края. Отсканировать SSCC внизу листа: «Код совпал».
4. Горизонтальный лист (готовый «Палета А4 · горизонтальная» в смене с паллетами): ориентация
   страницы совпадает с макетом, поворота и обрезки нет; то же для «две А5» — после разреза по
   линии SSCC читается сканером на обеих половинах.
5. Принтер с большими непечатаемыми полями (старый лазерный, 6,35 мм и больше): экран отвечает
   «Размер бумаги или разрешение … не совпадают» (`geometry_mismatch`), ничего не печатается и в
   очереди Windows пусто. В `drv-log.txt` строка `step=geometry` с размерами страницы и областью
   печати.
6. Бумага в драйвере не А4 (Letter): отказ до отправки, ничего не напечатано.
7. Смена с паллетами и принтером паллет «Лист А4»: закрыть короб и паллету — сначала этикетка
   короба на термопринтере, потом ровно один лист А4. SSCC на листе совпадает с SSCC паллеты на
   экране, даты производства и срока годности — смены и правила «день производства — первый».
8. Спул около 1 МБ: лист уходит в очередь за секунды или за десятки секунд. Если окно ждёт дольше
   20 секунд, экран говорит «Принтер не ответил вовремя»; записать, вышел ли лист и когда.
   Само ничего не перепечатывается.
9. Очередь приостановлена: лист `sent` (Windows приняла задание), после возобновления выходит
   ровно один лист. Принтер выключен или бумага кончилась: записать, что говорит экран и что вышло.
10. Перезапуск программы во время печати листа: «Печать прервалась», лист сам не уходит
    повторно; «Напечатать снова» спрашивает причину.
11. «Другой принтер» для паллеты: термопринтер печатает этикетку паллеты, А4-принтер — лист;
    для короба А4-принтера в списке нет.
12. Если каждый лист оканчивается «Windows не подтвердил задание до конца», хотя бумага вышла, —
    сообщить сразу: возможно, драйвер отвечает нулём на масштабированную печать (в
    `drv-log.txt` строка `step=StretchDIBits returned=… expected>0`).
13. Измерить новые элементы настройки (поле «Бумага», предпросмотр): не меньше 64 px.
14. Смена с паллетами без листа (основного листа нет и лист не выбран) на станции с принтером
    паллет «Лист А4»: каждое закрытие паллеты оставляет задание `failed` («Этикетку не удалось
    подготовить для этого принтера…»), паллета закрывается; этикетку печатают через «Другой принтер». Предупреждения
    при входе в смену нет — перед такой сменой выбрать в офисе основной лист или лист смены.
15. «Основной лист организации» берётся в момент сохранения смены в офисе. В правке
    запланированной смены с выбранным листом выбрать «Основной лист организации» и сохранить:
    смена получает текущий основной; потом сменить основной лист — запланированная смена
    остаётся на прежнем, лист в снимке открытой смены — тот, что был при сохранении.
16. Логотип входит в снимок каждой смены и в его предел: после загрузки большого логотипа
    смена, которая прежде открывалась, может не открыться (хост отвечает `conflict`
    `snapshot_too_large`). Записать размер логотипа (точки) и текст на экране.

### Логотип организации на этикетках (план А4)

Термоэтикетки со стандартной разметкой (поле `organization_logo`) печатают логотип
организации или, без него, встроенный логотип Маркиро; байты каждой такой этикетки изменились
по сравнению с версией до плана А4. Картинки логотипа декодирует WebView2, на Windows это не
проверялось. Сообщить владельцу: модель принтера, язык (ZPL или TSPL), dpi, файл логотипа,
что вышло на бумаге и что сказал экран.

1. Офис в окне приложения (WebView2): «Профиль → Логотип для печати» → загрузить PNG, затем
   JPEG, затем SVG. Каждый раз появляется чёрно-белый предпросмотр; «Сохранить логотип».
2. SVG со ссылкой на внешнюю картинку (`<image href="https://…">`): внешняя часть в
   предпросмотре не появляется, сетевого запроса нет (журнал брандмауэра или прокси).
3. Файл, который не является картинкой (переименованный `.txt` в `.png`): отказ с текстом.
   PNG в несколько килобайт, заявляющий 20 000 × 20 000 точек (сплошной белый): отказ
   «Картинка слишком большая в точках…», окно офиса продолжает работать.
4. Без своего логотипа: смена со стандартной разметкой печатает логотип Маркиро на Zebra (ZPL)
   и TSC (TSPL), каждый при 203 и 300 dpi. Логотип внутри своего поля, ничего не налезает,
   SSCC и коды читаются сканером.
5. Со своим логотипом: новая смена печатает его так же (пункт 4); смена, открытая до загрузки,
   печатает прежний. «Убрать логотип» — новые смены снова печатают логотип Маркиро.
6. Этикетка через драйвер Windows с логотипом: текст по-прежнему шрифтом IBM Plex; без
   загруженного шрифта — отказ «Этикетку не удалось подготовить для этого принтера», а не
   запасной шрифт.
