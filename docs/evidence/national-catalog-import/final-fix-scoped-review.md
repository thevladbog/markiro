## New fix-introduced breakage

### R1 — Important / P2: expiry cleanup can be overwritten by a late core failure recorder

**Current code:** `apps/api/src/modules/national-catalog/national-catalog-import-retention.ts:139`–`:173`, integrated with `national-catalog-import-apply.service.ts:215`–`:255`, `:272`–`:293`, and `:303`–`:320`.

**Minimal interleaving:** an accepted core receipt is pending when its session expires. A worker holds the session lock in its product transaction; the collector has selected that same receipt and its receipt transaction waits for the session lock. The worker fails `assertSessionAccess` with `import_session_closed` and its transaction rolls back, releasing its locks. Before the worker's separate catch transaction acquires the session, the collector acquires it, reads the pending receipt, writes `failed/import_session_closed`, clears retry intent, inserts `national_catalog.import.item_failed`, and commits. The worker catch subsequently acquires the same session, reads the already terminal failed receipt, but its guard excludes only cancelled operations and applied/conflict/cancelled products. `failed/import_session_closed` passes that guard. It writes the failure again, increments attempts and inserts a second audit for the same tenant, actor, operation/preview and target.

The serialization within each transaction does not close the gap between rollback and failure recording. The actual `operation()` helper at `national-catalog-import-apply.service.ts:420` is a scoped read; even if the collector marked the operation finished, the catch only excludes cancelled. Both failure paths use action `national_catalog.import.item_failed`, outcome `failure`, targetType product if productId exists else national_catalog_import_preview, the same targetId, and matching operationId/previewId/result/reason. This is a duplicated terminal transition, not two provider attempts. A delayed infrastructure-failure catch can additionally replace the collector's terminal reason with `infrastructure_failure`, set a new `nextAttemptAt`, and cause finalization to restore running/enqueuePending until another expiry check closes it. The TTL check still prevents a new product write; the defect is durable outcome/retry/audit accuracy.

**Why introduced here:** the new collector is now an additional terminal receipt writer competing with the existing split worker failure path. The I2 fix fences cancellation but does not fence this new expiry transition. `national-catalog-import-preview.test.ts:690` executes cleanup → worker replay → cleanup sequentially, so its once-only assertion cannot exclude this race. No existing output demonstrates the disputed interleaving. This conclusion is a source-traced concurrency finding, not a claimed runtime reproduction. A later scoped correction should preserve an already terminal failure or compare the admitted receipt generation/attempt before recording a stale failure; an interleaving regression should cover cleanup between rollback and catch. No correction or extra suite was run in this review.
